# AI 投彈的設計

日期：2026-09-06
分支：`feat/ai-bombing`

## 〇、起因

`japan-m4` 倫內爾島難度太高。專案負責人量到的原因不是「敵機太強」，而是
**只有玩家一個人在炸船**：

```
$ grep -rn "dropBomb" src/
src/main.ts:1330      world.dropBomb(          ← 玩家的幀迴圈
src/world/World.ts:617  dropBomb(              ← 定義
$ grep -rn "bomb" src/ai/*.ts
（沒有輸出）
```

另外五架一式陸攻是純誘餌。而 G4M 的彈艙是 500 kg × 2、單枚爆心 11,700，
要擊沉三艘最便宜的組合是三艘弗萊徹（20,000 × 3 = 60,000）—— 玩家一趟只
帶 23,400，回補 20 秒。這一關現在是「一個人來回投六次以上，全程被六架
F6F 咬」。

護航機解決的是「被咬」那一半，**投彈量那一半沒有動**。這一份 spec 做的是
後者。

## 一、範圍

做：

- `Command` 加 `bombing`
- `Combatant` 帶自己的彈艙
- AI 在物理步裡投彈，投彈點是機體質心
- 瞄準走 `solveImpact` 正解 + 船位外推
- `ai/shipAttack.ts` 加一個轟炸航路

不做：

- **對地轟炸。** B-17 炸機場那種要目標清單與另一套航路，另開一支。
- **投雷。** 另一支分支。
- 編隊轟炸。僚機各自投各自的。
- AI 迴避彈幕。威脅評估仍然只認得飛機。

## 二、為什麼投彈要在物理步裡，不能照玩家那條路

玩家投彈在 `main.ts` 的**幀迴圈**（1330 行），用內插後的算繪位置加
`model.bombPoint`。對人類沒問題，對 AI 不行 —— 這個專案有逐位元重播的
護欄（`replay-determinism`、`order-of-battle-replay`、`turret-replay`），
而幀迴圈的節拍隨畫面更新率變動。

所以 AI 投彈掛在 240 Hz 的物理步上，與開火（`World.step` 673 行的
`c.command.firing`）同一個位置、同一個節奏。

`World.dropBomb` 本身已經是決定性的：散佈走 `spreadPair(bombs.dropped)`，
是累計序號的雜湊而不是 `Math.random()`。

### 2.1 既有的四份重播基準為什麼結構上不受影響

**AI 投彈閘在「有活的敵艦目標」上。** 而基準場景沒有船：

```ts
// test/tools/spawn-snapshot.ts:209
ESCORT_B17: (): BattleConfig => ({
  ...DEFAULT_BATTLE, units: lineAbreast(HEAD_ON, B17G, 4, BF109K4, 8),
}),
```

四份場景都沒有 `fleet`，所以 `bombs.dropped` 恆為 0。**不是「測了沒變」，
是不可能變。**

這也順手畫出了範圍：這一輪不做對地轟炸。

## 三、投彈點用質心，不用 `bombPoint`

`bombPoint` 住在 `AircraftModel`（算繪層），`World` 讀不到也不該讀。

而它與質心差兩三公尺 —— **那一格是給玩家對準星用的，不是精度來源**。
殺傷半徑是 30 m 的量級，兩公尺的釋放點偏移落在雜訊裡。

## 四、瞄準

### 4.1 用 `solveImpact`，不另外推公式

不要寫第三份彈道。`world/bomb.ts` 已經有兩份必須逐位元一致的實作
（`Bombs.step` 與 `solveImpact`），它們的註解反覆寫著「差一個字就是準星與
水柱分家」。AI 再推一份「該在幾公尺前放」的閉式解，就是第三份會漂開的東西。

改成問同一支函數：

```
每個決策拍（10 Hz）：
  solveImpact(自己現在的狀態, k, 甲板高度, dt) → 落點 + 飛行時間 t
  船在 t 秒後的位置 = position + forward × speed × t
  |落點 − 預測船位| < 釋放半徑 → bombing = true
```

`dt` 取 `1/240`，與玩家的準星（`main.ts:1372` 傳 `loop.stepSeconds`）以及
空中的炸彈完全相同。

### 4.2 為什麼船位要外推

船以 8 m/s 固定艏向前進，而炸彈從 1,000 m 落下約 14 秒 —— **112 m**。
弗萊徹全長 114.75 m。不外推的話每一顆都會落在船尾之後接近一整個船身。

外推是解析的：固定艏向、等速、不閃避（`world/ships.ts` 的 `stepShips`）。

### 4.3 解算平面取甲板高度，不是海面

`solveImpact` 的 `groundAt` 決定「落在哪裡算落地」。取海面的話落點會比
甲板遠 —— 甲板高 4.5～7 m，末速下多掉那幾公尺約多飛 7 m。

在釋放半徑的量級之內，但沒有理由留著這個偏差：甲板高度就是
`max(hull.center.y + hull.half.y)`，讀得到。

### 4.4 釋放半徑 = 該艘船的**船寬**

專案負責人裁定：照船體寬度處理。

```
                     船寬 = 2 × hull.half.x
  Fletcher DD-445      12.08 m
  Wichita CA-45        18.82 m
  Essex CV-9           28.40 m
```

它是這一關難度的主旋鈕，**起始值，由試飛裁定**。

【為什麼是逐艦而不是一個常數】大船本來就比較好打。一個常數會讓航母與
驅逐艦一樣難命中，而那與直覺相反。

【240 Hz 的取樣夠不夠細】巡航 90 m/s 下每個物理步走 0.375 m，落點大約同步
移動 —— 遠小於 12 m 的最小釋放半徑，所以不會「跨過去而沒有一步落在窗內」。

## 五、攻擊航路

依 `bombBayOf(spec.id) > 0` 與掃射分流：

| | 掃射（戰鬥機） | 攻擊航路（有彈艙） |
|---|---|---|
| 瞄點 | 最近的活砲位 | 船的**預測位置**（水平） |
| 脫離 | 400 m | 見 §5.2 的狀態機 |
| `firing` | 進錐開火 | 恆 false（自衛交給砲塔） |

【為什麼不開固定槍】一式陸攻沒有固定槍（`battery.mounts` 是空陣列，
`World.fire` 零次迭代），但 B-17 與 He 111 有。讓它們在航路上掃射會把機首
拉離航路。自衛是砲塔的事（`world/turrets.ts`）。

### 5.1 第一版錯在哪（2026-09-06 實測）

第一版是「平飛、定高、朝船的預測位置」—— **每一步都重新瞄準**。實測：

```
架   陣亡於  投彈趟數     補滿彈之後離「該投」最近差多少（窗 18.82 m）
# 0     57s     1            # 2   58 m
# 2     存活    1            # 3   37 m
# 3    140s     1            # 7  411 m
# 8     35s     0
（十架，八架陣亡，每架只投得成一趟）
```

**管線是乾淨的**：AI 說「投」的 696 個物理步，696 個都送到 `command`，
`CommandDelay` 與 `applySafety` 都沒吃掉，彈艙回補也一次都沒擋到。

問題在航路本身。每一步重新瞄準 = 追尾曲線，而炸彈脫手時繼承的是速度向量，
也就是轉彎圓的**切線**。在弧線上，預測落點橫掃海面的速度遠快於飛機接近船
的速度 —— 落點「刷」地掃過那個 18.82 m 的窗。

第一趟之所以成功，是因為開場那 5 km 是又長又直、已經穩定的航線。
**那是碰巧，不是設計。**

另外「投完繼續往船飛」讓它們鑽進 20 mm 火網 —— 那是十架死八架的直接原因。

### 5.2 三個狀態

```
進場 ──對正了──▶ 直飛 ──投完／飛過頭／逾時──▶ 脫離 ──補滿且夠遠──▶ 進場
 ▲                                                                    │
 └────────────────────────────────────────────────────────────────────┘
```

**進場**：第一版的行為，工作只剩「把飛機帶到起跑線」。

**直飛**：新的核心。**鎖定航向、停止逐步重瞄** —— 治好第一版那 37～58 m
誤差的就是這件事（見 §5.5 的 A/B）。進入之後**目標也鎖住** —— 換船等於
航向白鎖。

【它的長度是 0】`RUN_SETTLE = 0`，所以「鎖住航向」與「該放就放」實際上
發生在同一拍。這一段仍然是一個獨立的相位，因為它是「已經鎖定、正在等
釋放窗」與「還在找路」的分界。

**脫離**：背離、爬高，離開火網直到補滿且夠遠。

### 5.3 為什麼是重阻尼而不是完全凍結

完全凍結最穩，但鎖定當下對船速與自身速度的估計一有偏差，整趟就報銷而且
沒有機會修正。所以航向每個決策拍朝理想值收斂一點點（`RUN_TRIM`）——
量級小到不會讓落點橫掃，又足以吃掉系統性偏差。

### 5.4 幾何全部推導，一個常數都不留

三個距離都隨**機種與高度**變，寫死一定會錯一邊：

```
前拋       = solveImpact 從當下狀態積出來的水平距離
鎖定距離   = 前拋 + RUN_SETTLE
脫離距離   = 鎖定距離 + 2 × 持續迴旋半徑（sustainedTurnRate）
```

實測值（航路速度取極速八成）：

```
高度 1,000 m        速度   前拋   鎖定   迴旋半徑   脫離
  G4M 一式陸攻      88 m/s  1188   1188      534    2256
  B-17G            89 m/s  1204   1204      555    2314
  He 111           86 m/s  1162   1162      639    2440
  A6M5 零戰        113 m/s  1504   1504      487    2479

高度 4,000 m
  G4M              93 m/s  2312   2312      738    3788
  B-17G            96 m/s  2359   2359      765    3889
  He 111           89 m/s  2211   2211      914    4038
  A6M5            121 m/s  2917   2917      670    4257
```

【兩個反直覺的地方】**零戰退得最遠** —— 它快，前拋就遠，鎖定距離跟著大，
最小的迴旋半徑補不回來。**He 111 退得比 B-17 遠** —— 推重比最差、持續
迴旋率最低。

【原本寫死的 5,000 是 4,000 m 的值】拿到 `japan-m4` 的 1,000 m 就多飛了
一倍多的路：實測循環 111 s，改推導之後 41 s。

### 5.5 直線段訂 0（負責人 2026-09-06 裁定）

A/B 實測（一台 G4M、一艘**不開火**的威奇塔、五分鐘）：

```
                      平均循環   命中(<40m)   落點
 脫離5000 / 直線1200    111 s      6/6       6,33,12,33
 脫離3000 / 直線1200     66 s      8/8       6,33,15,25
 脫離3000 / 直線   0     67 s      4/8       6,45,11,54
 脫離5000 / 直線   0    111 s      3/6       6,45, 5,49
```

**每一趟的第一枚，四組完全一樣（6 m）。** 直線段對第一枚沒有作用 ——
治好第一版那 37～58 m 誤差的是**航向鎖定**，不是那段長度。直線段只影響
**連投的第二枚**：G4M 一趟兩枚間隔 0.35 s，飛機還在轉的話第二枚飛出去
45～54 m。

改成推導的脫離距離之後再比一次（直線段是唯一的變因）：

```
                平均循環   趟數      總命中
 直線段    0     41～44 s   7 / 4     7 / 7
 直線段 1200     67～69 s   5 / 2     8 / 4
```

**單枚命中率掉一半，但趟數多到總命中持平甚至更好**（會動的船是 7 對 4）。

負責人裁定：**「命中率低沒關係，AI 操作玩起來比較好玩比較重要」** ——
所以 `RUN_SETTLE = 0`。參數保留在 `makeBombProfile`，隨時可以調回來重測。

### 5.6 魚雷要共用這一套

專案負責人裁定：魚雷在另一支 worktree 上，這一套要能共用。

**狀態機與武器無關**（`ai/strikeRun.ts`），會變的只有一份 `StrikeProfile`：

| | 轟炸 | 雷擊（另一支） |
|---|---|---|
| 航路高度 | 維持現在的 | 降到投雷高度 |
| 鎖定距離 | 由彈道推 | 固定的投雷距離 |
| 放得中嗎 | `solveImpact` | 射程內 + 航向錐 |
| 瞄點 | 船的落彈時刻位置 | 船的雷程時刻位置 |

`ai/bombRun.ts` 因此只剩「彈道」與一份 `BOMB_PROFILE`。

【安全層仍然凌駕】鎖航向不代表可以撞山或失速；`applySafety` 照樣接管，
而且會取消投彈。代價是低空進場偶爾會被打斷一趟 —— 那是對的。

## 六、彈艙掛在 `Combatant` 上

```ts
/** 【不是 readonly】換裝機種容量會變，與 `cooldowns` 同一個理由。 */
bombBay: BombBay
```

`setSpec` 裡跟著 `resetBombBay(c.bombBay, bombBayOf(spec.id))` —— 那一段
本來就在處理「換裝機種時掛架數會變」的三個陣列，彈艙是第四個。

`stepBombBay(b, dt, trigger, drop)` 的簽名本來就吃 `dt`，物理步直接可用。
連投間隔與回補（`BOMB_SALVO_INTERVAL`、`BOMB_RELOAD_SECONDS`）因此與玩家
完全相同，不必另外訂一套 AI 的節奏。

## 七、驗收

### 7.1 決定性

同一場跑兩次，`bombs.dropped` 與每一顆的落點逐位元相同。

### 7.2 命中要有鑑別度，不能用統計

專案負責人 2026-09-04 的裁定（艦隊防空那一輪）：測試要用**測試專用的
無誤差條件**去打，才有鑑別度。

所以是一架 G4M 定高定速直線飛向一艘**靜止**的弗萊徹，斷言：

1. 投得出來（`bombs.dropped > 0`）
2. 落點落在船體盒內

### 7.3 承重的反證

把 §4.2 的船位外推拿掉（改用當下位置），落點必須偏出去。8 m/s × 14 s
≈ 112 m，遠大於 12 m 的釋放半徑與 114.75 m 的船長 —— 這一條必須殺得掉
測試，否則外推那一段沒有反證。

### 7.4 四份重播護欄照跑

`order-of-battle-replay`、`replay-determinism`、`turret-replay`，
加上 `ai-controller` 與 `ai-target`。

## 八、未解

- **AI 要多準是試飛的問題。** §4.4 的釋放半徑是唯一的旋鈕，先給船寬。
- **零戰護航先不做。** 專案負責人裁定：AI 會投彈之後投彈量那一半就解決了，
  兩個一起上可能從太難直接翻到太簡單。試飛之後再決定。
- 對地轟炸、投雷、編隊轟炸見 §一。
