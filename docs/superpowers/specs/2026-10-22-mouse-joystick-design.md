# 滑鼠搖桿操控（SPEC）

## 1. 目的

現在只有一種操控法：**滑鼠瞄準**。玩家用滑鼠指一個世界方向，飛行指揮儀（`FlightDirector`）
決定怎麼滾、怎麼拉、踩多少舵把機首帶過去。

加第二種：**滑鼠搖桿**。滑鼠是一支虛擬搖桿，左右是滾轉、上下是俯仰，A／D 是方向舵。
玩家自己決定坡度與拉桿量，做得出指揮儀不會做的動作（刻意側滑、桶滾閃避、
先滾後拉的時機）。

在設定頁切換，滑鼠瞄準仍是預設。

## 2. 玩家看到的

### 2.1 設定頁

兩列，接在「瞄準輔助」之後：

| 列 | 選項 | 預設 |
|---|---|---|
| 操控方式 | 滑鼠瞄準／滑鼠搖桿 | 滑鼠瞄準 |
| 搖桿回中 | 關／慢／快 | 關 |

- 「搖桿回中」在草稿是「滑鼠瞄準」時灰掉（`optRow` 的 `disabled`）
- 照既有設定頁的規則：按確定才套用、取消回到原值、恢復預設值兩列一起回預設
- 存在 `localStorage`（`input.controlMode`、`input.stickRecenter`），讀寫包 try，讀到不認得的值當成沒設定

### 2.2 飛行中

| 輸入 | 滑鼠瞄準（不變） | 滑鼠搖桿 |
|---|---|---|
| 滑鼠左右 | 瞄準方向左右 | 壓桿滾轉（右移＝右滾） |
| 滑鼠上下 | 瞄準方向上下 | 推拉桿（上移＝拉桿、機首往上） |
| A／D | 無 | 方向舵（D＝機首往右） |
| 右鍵拖曳 | 自由視角 | 自由視角（拖曳期間搖桿不動） |
| 其餘按鍵 | — | 與滑鼠瞄準相同 |

- 滑鼠上移＝機首往上，與滑鼠瞄準一致，玩家換模式不必反過來想
- 觸控裝置（觸控層顯示時）一律走滑鼠瞄準，設定不影響觸控

### 2.3 HUD

- 滑鼠搖桿下**不畫滑鼠圓圈與連線**（它們表示「瞄準方向」，這個模式沒有）
- 機首十字照畫（槍口方向、過熱顏色、命中 X 都不變）
- 新增**搖桿指示**：畫面中央一個細圓環（搖桿的可動範圍）＋一個點（目前搖桿位置）。
  點的顏色接手原本圓圈的失速警示：迎角接近臨界時轉黃、再近轉紅
- 按鍵提示列在滑鼠搖桿下多一項「A/D 方向舵」

### 2.4 鏡頭

- 滑鼠搖桿下鏡頭跟著**機首**，不跟瞄準方向。實作上每幀把 `input.aimWorld` 設成機首方向
  （與代飛 `I` 同一個做法）
- **鏡頭跟著滾**：上方向量追機體上方（時間常數 `ROLL_FOLLOW_TIME` 0.08 s，滾 90°/s 時落後約 7°），
  機外鏡頭的抬升也沿著它 —— 倒飛時鏡頭在機腹那一側，機身留在畫面的同一個位置，拉桿永遠是
  「機首往畫面上方走」。滑鼠瞄準不跟（那裡滑鼠沿鏡頭的螢幕軸推瞄準點，鏡頭一滾就正回饋）。
  代飛、死亡鏡頭不跟
- 追的方式是繞視線轉掉差角的一部分，不是線性混合：正飛翻到倒飛時目標恰在反方向，線性混合
  只會縮短不會轉
- 投彈瞄具視角（`B`）、上帝視角、死亡鏡頭照舊

## 3. 搖桿輸入（輸入層）

### 3.1 搖桿位置

`InputState` 加 `stickX`、`stickY`（−1…1，右、上為正），每幀在 `playerControl` 更新：

```
stick += 這一幀的滑鼠位移（aimDeltaX/Y） × STICK_GAIN
stick 夾進單位圓（超出就沿徑向縮回圓上）
stick *= exp(−dt / 回中時間)      回中「關」＝不衰減
```

- `aimDeltaX/Y` 是既有的累積器（已乘設定頁的靈敏度與 `MOUSE_SENSITIVITY` 1.6），不新增第二組
- `STICK_GAIN` = 2.5：靈敏度 1 時，滑鼠移動約四分之一個螢幕半高（1080p 約 135 px）＝滿桿
- 回中時間：慢 0.8 s、快 0.12 s。快的時候桿量約正比於滑鼠移動速度（速率式手感），
  關的時候是純位置式
- `dt` 用 `stepPlayerControl` 拿到的世界時間步長：暫停時不回中
- **以上三個數字是起始值，由試玩裁定**

### 3.2 搖桿歸零的時機

- 玩家控制器重新接上座位時（`I` 交還、離開上帝視角、接手僚機）
- **新的一場與重開**：這兩條路徑直接把玩家控制器裝上座位（`createBattle`、`battleRuntime`），
  不經過上面那個交還分支，要另外歸零。三條路徑（新的一場、兩種重開）都經過 `main.ts` 的
  `respawnPlayer`，在那裡歸零
- **有效模式換了**（設定改了、觸控層出現或消失）：不歸零的話切回搖桿時恢復上一次的桿量
- 陣亡那一幀
- 開場導覽期間：`holdIntroInput` 每幀把搖桿與方向舵清掉（它本來就清掉所有輸入、把瞄準點鎖在機首）
- 代飛、上帝視角、死亡鏡頭期間滑鼠位移不進搖桿（照既有的分支，位移被清掉或餵給鏡頭）

### 3.3 方向舵

`InputState` 加 `rudderLeft`、`rudderRight`（A、D 按住）。

- 飛行中（非上帝視角）寫；只有滑鼠搖桿讀它（`PlayerController`）。上帝視角下 A／D 照舊是平移
- 放開一律兩邊都清（與 W／S 同一條規則：按下時在飛行、放開時已經在上帝視角是做得到的）
- `clearInputHolds` 一併清

### 3.4 桿量曲線

送進控制律之前，搖桿位置經過：

1. **死區**：徑向長度 < 0.03 視為 0（滑鼠的微小抖動不讓飛機慢慢滾走）
2. **指數曲線**：`out = sign(s) · (E·|s|³ + (1 − E)·|s|)`，`E` = 0.25，兩軸各自套用。
   中段細、末段到滿 —— 瞄準時的微調不會一碰就甩。半桿 ≈ 0.39（0.5 時是 0.30，試玩回報中段太軟）

死區之後重新把範圍拉回 0…1，滿桿仍是 1。**死區與 `E` 是起始值，由試玩裁定。**

## 4. 指令與控制律（核心層）

### 4.1 `Command` 多四格

```ts
manual: boolean       // 這一步由搖桿直接給角速度，不經瞄準方向
stickRoll: number     // −1…1，右滾為正（已過死區與曲線）
stickPitch: number    // −1…1，拉桿為正
stickYaw: number      // −1…1，機首往右為正
```

- 每個控制器每步都要寫這四格（`Controller.update` 的既有約定：控制器可能在同一座位上替換）。
  AI、腳本靶機、演練的靶機、工具頁的控制器一律 `manual = false`、三軸 0
- `PlayerController`：滑鼠搖桿下 `manual = true` 並寫入三軸；滑鼠瞄準下同 AI
- 滑鼠搖桿下 `trackTurn` 仍寫 true，但不會被讀（見 4.3）

### 4.2 `Aircraft.update` 多一個參數

`manual: ManualStick | null = null`，`ManualStick` = `Command` 的三軸。`World` 傳
`c.command.manual ? c.command : null`。改出預演、Worker 這些只給 AI 用的路徑不傳，維持 null。

### 4.3 `FlightDirector.updateManual`

與 `update` 共用限制器與三個內環 PID，只換掉外環：

| 軸 | 期望角速度 |
|---|---|
| 滾轉 | 壓桿時**副翼直接等於桿量**，不經內環；回中時守住坡度（見下） |
| 俯仰 q | 見下 |
| 偏航 r | `yawOuter·β + stickYaw × maxYawRateCommand × 側滑權限` |

**俯仰**：搖桿置中＝1 G 配平飛行，拉滿＝限制器允許的最大俯仰率，推滿＝最小。

```
qTrim = g·(1 − gLoad) / V        讓機身法向過載 = 1 G 的俯仰率；V ≤ 1 m/s 時為 0
qTrim 夾進 [qMin, qMax]
stickPitch ≥ 0：q = qTrim + stickPitch × (qMax − qTrim)
stickPitch < 0：q = qTrim + stickPitch × (qTrim − qMin)
```

`gLoad`、`qMax`、`qMin` 與自動模式完全同一套（`gLoadFromOrientation`、`pitchRateLimit`、
`nNeg` 的推導）。

- **為什麼置中是 1 G 而不是 q = 0**：q = 0 是姿態保持。帶坡度放開搖桿時機首停在慣性空間裡不跟著轉彎，
  速度向量被重力往下拉，迎角一路變大，看起來像飛機卡住。1 G 配平是真飛機放開桿的樣子：
  正飛平飛時 q = 0，帶坡度時機首自己跟著轉、慢慢往下掉
- **保護保留**：拉滿就是 `qMax`，限制器照樣擋失速與結構過載（飛行員的 G 不夾，照舊由黑視懲罰；
  推桿那一側是 `nNeg`，含飛行員 −3 G）。滑鼠搖桿不會因為拉太猛而失速或結構超 G。
  要不要開放失速是試玩之後的決定
- **滾轉**：穩態滾轉率本來就正比於副翼，滿桿就是副翼打滿、這架飛機這個速度下的物理極限。
  原本的做法（估計的最大滾轉率 × 桿量，交給內環追）估計偏低、內環又追不上，滿桿只有瞄準模式的
  六成到七成（試玩回報「滾轉很慢」）。量測（3000 m）：

  | | 只壓桿 | 壓桿＋滿舵 | 瞄準模式 |
  |---|---|---|---|
  | P-51D 110 m/s | 76°/s | 102°/s | 96°/s |
  | P-51D 160 m/s | 112°/s | 148°/s | 128°/s |
  | P-51D 220 m/s | 127°/s | 173°/s | 148°/s |
  | Bf 109K-4 160 m/s | 58°/s | 99°/s | 93°/s |

  瞄準模式滾的時候自己會踩舵，側滑經上反角多給一截滾轉；搖桿要加 A／D 才比得上
- **回中守住坡度**：副翼單純回中的話機體的螺旋傾向會把坡度帶走（P-51D 五秒三十幾度），只把
  滾轉率壓在 0 也會慢慢漂（積分追不上螺旋力矩）。放桿之後先把滾轉收掉，滾轉率低於約 3°/s
  （`HOLD_CAPTURE_RATE`）那一刻記下坡度，之後用改平那一組增益（`wingsLevelGain`、`wingsLevelI`）
  守住它。放桿那一刻就記的話，收掉滾轉之後會被拉回放桿那一點，看起來像彈回去
- **偏航**：`yawOuter·β` 是自動模式就有的消側滑項，搖桿下照樣當協調轉彎用。A／D 在它上面
  疊一個偏航率指令，側滑權限（`betaFadeStart`…`betaMax`）照自動模式夾，所以踩舵側滑上限 10°。
  夾制有方向性：往加大側滑那一邊踩（`stickYaw > 0` 看 `−β`，`< 0` 看 `β`）才會被夾，往回踩永遠有權限
`dbg` 照填：`desiredP/Q/R`、`actualP/Q/R`、`limiter`、`qMin`。瞄準誤差、滾轉指令那幾格填 0。
壓桿時 `desiredP` 寫成實際滾轉率（那一軸不經內環）。

### 4.4 模式切換

`FlightDirector` 記上一步是哪一種模式。換模式的那一步清掉外環積分（`pitchIntegral`、
`levelIntegral`、`yawIntegral`）、`pushMode`、`lastRollCommand` 與跟瞄歷史（`resetTrack`）。
內環 PID 不清 —— 它們追的是角速度，兩種模式意義相同。

不清的話：玩家用搖桿飛了一陣子按 `I`，AI 接手的第一步帶著上一次自動模式殘留的積分。

## 5. 其他系統

| 系統 | 滑鼠搖桿下 |
|---|---|
| 瞄準輔助 | 不作用（它推的是瞄準方向，這個模式沒有）；每幀 `reset` |
| `slewAimWorld` | 不呼叫；`aimWorld` = 機首方向 |
| 投彈瞄具（`B`） | 視角照切，搖桿照飛；`aimWorld` = 機首方向 |
| 代飛 `I`、上帝視角 `G` | 照舊；交還時搖桿歸零 |
| 槍口過熱、投彈、望遠 | 不變 |
| 教學卡 | 不改。講的是預設的滑鼠瞄準；選了滑鼠搖桿的人是自己挑的 |

## 6. 量測出口

`window.__stick()` 回傳 `{ mode, x, y, roll, pitch, yaw }`（設定的模式、搖桿位置、
這一步送進指令的三軸）；`__stick(x, y)` 直接放搖桿位置。給 e2e 用：無頭瀏覽器裡取得
指標鎖的那一下會送一個很大的 `movementX/Y`，先把搖桿放回中心再開始量。

## 7. 護欄（單元測試）

1. **控制律**（`updateManual`）
   - 搖桿置中、正飛平飛：期望 q ≈ 0、p = 0
   - 帶 60° 坡度、搖桿置中：期望 q > 0（機首跟著轉），法向過載約 1 G
   - 拉滿：期望 q = `qMax`；推滿：期望 q = `qMin`
   - 壓桿時副翼等於桿量；滿桿加舵的滾轉率追得上瞄準模式、只壓桿至少六成
   - 方向舵滿：期望 r 往對的方向；側滑超過 `betaMax` 時往加大那邊踩權限歸零、往回踩權限 1
2. **飛起來**（`Aircraft` + 固定指令，P-51D，4000 m，160 m/s）
   - 右滾桿 1 秒後坡度往右；放開之後坡度保持（5 秒內變化 < 5°）
   - 拉桿 2 秒：高度或航跡角往上、過載 > 1.5
   - 拉滿 10 秒：迎角不超過臨界、過載不超過限制器的上限
3. **模式切換**：搖桿飛 → 自動的第一步，外環積分為 0
4. **指令欄位**：所有控制器寫 `manual = false` 與三軸 0（把既有的「接手既有命令」測試補上這四格）；
   `PlayerController` 在搖桿模式下寫 `manual = true` 與曲線後的三軸
5. **輸入**：
   - 搖桿累積、夾進單位圓、回中三檔（關不衰減、慢與快照時間常數衰減）、暫停（dt = 0）不回中
   - 死區與指數曲線：0 → 0、1 → 1、單調、死區內為 0
   - A／D：滑鼠搖桿＋飛行中寫方向舵、上帝視角下照舊平移、放開兩邊都清、`clearHolds` 清
6. **`playerControl`**：搖桿模式下 `aimWorld` = 機首、不呼叫瞄準輔助、滑鼠位移進搖桿；
   觸控層顯示時退回滑鼠瞄準；交還控制器、有效模式換了、`resetStick`（新的一場／重開）時
   非零的桿量與方向舵歸零；`holdIntroInput` 清掉搖桿與方向舵
7. **設定**：兩列的草稿／確定／取消／恢復預設；回中列在草稿是滑鼠瞄準時 disabled；存檔讀寫
8. **HUD**：搖桿模式下 `aimVisible` = false、搖桿指示畫在中央、點的顏色吃失速比
9. **i18n**：新增的字串兩種語言都有

## 8. E2E（`test/e2e/mouse-joystick.e2e.ts`）

照 `god-view.e2e.ts` 的跑法（`npm run dev` + `npx vite-node`）：

1. 開場前在 `localStorage` 寫入滑鼠搖桿，開遭遇戰，按掉教學卡、等物理時鐘開始走
2. 點畫面取得指標鎖，`__stick(0, 0)` 歸零
3. 滑鼠往右移 → `__stick().x > 0`；等 1.5 s → `__probe().bk` 往右
4. `__stick(0, 0)` → 等 2 s → 坡度保持（變化 < 10°）
5. `__stick(0, 0.8)` → 等 2 s → 航跡角上升
6. 按住 D → `__stick().yaw > 0`
7. 搖桿指示真的畫出來了：`__stick(0.8, 0)` 之後，圓環上、十字範圍之外（中心右方約一個圓環
   半徑處）有綠色；`__stick(−0.8, 0)` 之後那一點移到左邊。只數中央的綠色會被機首十字滿足，
   刪掉整個搖桿指示也照樣通過。存截圖給負責人看搖桿指示的樣子
8. 按 `I` 再按 `I`：搖桿歸零、沒有錯誤
9. 全程沒有 console 錯誤

幀率低時（無頭約 7.5 fps）物理照固定步長跑，只量方向不量時間。

## 9. 不做的

- 鍵盤直接打桿（WASD 滾轉俯仰）
- 開放失速與螺旋（保護保留，見 4.3）
- 兩軸分開的回中設定
- 俯仰反向選項
- 觸控版的搖桿
- 教學卡的搖桿版
