# 滑鼠搖桿操控（SPEC）

## 1. 目的

現在只有一種操控法：**滑鼠瞄準**。玩家用滑鼠指一個世界方向，飛行指揮儀（`FlightDirector`）
決定怎麼滾、怎麼拉、踩多少舵把機首帶過去。

加第二種：**滑鼠搖桿**。滑鼠是一支虛擬搖桿，左右是滾轉、上下是俯仰，A／D 是方向舵。
玩家自己決定坡度與拉桿量，做得出指揮儀不會做的動作（刻意側滑、桶滾閃避、
先滾後拉的時機）。

在設定頁切換，滑鼠瞄準仍是預設。

## 2. 玩家看到的

### 2.1 設定頁

兩列，接在「瞄準輔助」之後：

| 列 | 選項 | 預設 |
|---|---|---|
| 操控方式 | 滑鼠瞄準／滑鼠搖桿 | 滑鼠瞄準 |
| 搖桿回中 | 關／慢／快／瞬間 | 關 |

- 「搖桿回中」在草稿是「滑鼠瞄準」時灰掉（`optRow` 的 `disabled`）
- 照既有設定頁的規則：按確定才套用、取消回到原值、恢復預設值兩列一起回預設
- 存在 `localStorage`（`input.controlMode`、`input.stickRecenter`），讀寫包 try，讀到不認得的值當成沒設定

### 2.2 飛行中

| 輸入 | 滑鼠瞄準（不變） | 滑鼠搖桿 |
|---|---|---|
| 滑鼠左右 | 瞄準方向左右 | 壓桿滾轉（右移＝右滾） |
| 滑鼠上下 | 瞄準方向上下 | 推拉桿（上移＝拉桿、機首往上） |
| A／D | 無 | 方向舵（D＝機首往右） |
| 右鍵拖曳 | 自由視角 | 自由視角（拖曳期間搖桿不動） |
| 其餘按鍵 | — | 與滑鼠瞄準相同 |

- 滑鼠上移＝機首往上，與滑鼠瞄準一致，玩家換模式不必反過來想
- 觸控裝置（觸控層顯示時）選了滑鼠搖桿，左半邊拖曳改成推搖桿，見 §10

### 2.3 HUD

- 滑鼠搖桿下**不畫滑鼠圓圈與連線**（它們表示「瞄準方向」，這個模式沒有）
- 機首十字照畫（槍口方向、過熱顏色、命中 X 都不變）
- 新增**搖桿指示**：畫面中央一個細方框（搖桿的可動範圍）＋一個點（目前搖桿位置）。
  點的顏色接手原本圓圈的失速警示：迎角接近臨界時轉黃、再近轉紅
- 按鍵提示列在滑鼠搖桿下多一項「A/D 方向舵」

### 2.4 鏡頭

- 滑鼠搖桿下鏡頭跟著**機首**，不跟瞄準方向。實作上每幀把 `input.aimWorld` 設成機首方向
  （與代飛 `I` 同一個做法）
- **鏡頭跟著滾**：上方向量追機體上方（時間常數 `ROLL_FOLLOW_TIME` 0.08 s，滾 90°/s 時落後約 7°），
  機外鏡頭的抬升也沿著它 —— 倒飛時鏡頭在機腹那一側，機身留在畫面的同一個位置，拉桿永遠是
  「機首往畫面上方走」。滑鼠瞄準不跟（那裡滑鼠沿鏡頭的螢幕軸推瞄準點，鏡頭一滾就正回饋）。
  代飛、死亡鏡頭不跟
- 追的方式是繞視線轉掉差角的一部分，不是線性混合：正飛翻到倒飛時目標恰在反方向，線性混合
  只會縮短不會轉
- 投彈瞄具視角（`B`）、上帝視角、死亡鏡頭照舊

## 3. 搖桿輸入（輸入層）

### 3.1 搖桿位置

`InputState` 加 `stickX`、`stickY`（−1…1，右、上為正），每幀在 `playerControl` 更新：

```
G = STICK_GAIN × 倍率（「瞬間」4，其餘 1）
回中「關」：  stick += 位移 × G
其餘：        k = exp(−dt / 回中時間)
              stick = stick × k + 位移 × G × 回中時間 × (1 − k) / dt
stickX、stickY 各自夾在 ±1
```

- **與幀率無關**：第二式是對滑鼠速度的精確一階濾波，等速移動的穩態桿量正好是
  速度 × G × 回中時間，60 與 240 FPS 一樣。直接加位移再衰減的話，「瞬間」在 60 FPS 只剩 240 FPS 的八成

- **夾成方形**：兩軸各自獨立，跟實體搖桿一樣，斜推到底是滿舵加滿桿。夾成圓的話右上 45° 推到底
  兩軸都只有 0.707，過曲線後只剩 0.62

- `aimDeltaX/Y` 是既有的累積器（已乘設定頁的靈敏度與 `MOUSE_SENSITIVITY` 1.6），不新增第二組
- `STICK_GAIN` = 2.5：靈敏度 1 時，滑鼠移動約四分之一個螢幕半高（1080p 約 135 px）＝滿桿
- 回中時間：慢 0.8 s、快 0.12 s、瞬間 0.03 s。快與瞬間的時候桿量正比於滑鼠移動速度（速率式手感，
  滑鼠一停就回中），關的時候是純位置式
- 「瞬間」不是 0：滑鼠事件與畫面幀不同步，有的幀收到位移、有的幀沒有，0 的話桿量一幀有一幀沒有，
  飛機跟著抖。0.03 s 約兩幀，停手之後 0.1 s 內回到 5% 以下
- 「瞬間」的位移乘 4（快 ÷ 瞬間的時間常數）：同一個滑鼠速度推出的桿量與「快」一樣，只縮短回中
- `dt` 用 `stepPlayerControl` 拿到的世界時間步長：暫停時不回中
- **以上三個數字是起始值，由試玩裁定**

### 3.2 搖桿歸零的時機

- 玩家控制器重新接上座位時（`I` 交還、離開上帝視角、接手僚機）
- **新的一場與重開**：這兩條路徑直接把玩家控制器裝上座位（`createBattle`、`battleRuntime`），
  不經過上面那個交還分支，要另外歸零。三條路徑（新的一場、兩種重開）都經過 `main.ts` 的
  `respawnPlayer`，在那裡歸零
- **有效模式或搖桿來源換了**（設定改了、觸控層出現或消失）：不歸零的話切回搖桿時恢復上一次的桿量，
  或是把觸控最後的位置交給滑鼠接著累積
- 陣亡那一幀
- 開場導覽期間：`holdIntroInput` 每幀把搖桿與方向舵清掉（它本來就清掉所有輸入、把瞄準點鎖在機首）
- 代飛、上帝視角、死亡鏡頭期間滑鼠位移不進搖桿（照既有的分支，位移被清掉或餵給鏡頭）

### 3.3 方向舵

`InputState` 加 `rudderLeft`、`rudderRight`（A、D 按住）。

- 飛行中（非上帝視角）寫；只有滑鼠搖桿讀它（`PlayerController`）。上帝視角下 A／D 照舊是平移
- 放開一律兩邊都清（與 W／S 同一條規則：按下時在飛行、放開時已經在上帝視角是做得到的）
- `clearInputHolds` 一併清

### 3.4 桿量曲線

送進控制律之前，搖桿位置經過：

1. **死區**：每軸 |s| < 0.03 視為 0（滑鼠的微小抖動不讓飛機慢慢滾走）。每軸各自算，一軸推滿時
   另一軸的抖動照樣是 0
2. **指數曲線**：`out = sign(s) · (E·|s|³ + (1 − E)·|s|)`，`E` = 0.25，兩軸各自套用。
   中段細、末段到滿 —— 瞄準時的微調不會一碰就甩。半桿 ≈ 0.39（0.5 時是 0.30，試玩回報中段太軟）

死區之後重新把範圍拉回 0…1，滿桿仍是 1。**死區與 `E` 是起始值，由試玩裁定。**

## 4. 指令與控制律（核心層）

### 4.1 `Command` 多四格

```ts
manual: boolean       // 這一步由搖桿直接給角速度，不經瞄準方向
stickRoll: number     // −1…1，右滾為正（已過死區與曲線）
stickPitch: number    // −1…1，拉桿為正
stickYaw: number      // −1…1，機首往右為正
```

- 每個控制器每步都要寫這四格（`Controller.update` 的既有約定：控制器可能在同一座位上替換）。
  AI、腳本靶機、演練的靶機、工具頁的控制器一律 `manual = false`、三軸 0
- `PlayerController`：滑鼠搖桿下 `manual = true` 並寫入三軸；滑鼠瞄準下同 AI
- 滑鼠搖桿下 `trackTurn` 仍寫 true，但不會被讀（見 4.3）

### 4.2 `Aircraft.update` 多一個參數

`manual: ManualStick | null = null`，`ManualStick` = `Command` 的三軸。`World` 傳
`c.command.manual ? c.command : null`。改出預演、Worker 這些只給 AI 用的路徑不傳，維持 null。

### 4.3 `FlightDirector.updateManual`

與 `update` 共用限制器與三個內環 PID，只換掉外環：

| 軸 | 期望角速度 |
|---|---|
| 滾轉 | 壓桿時**副翼直接等於桿量**，不經內環；回中時守住坡度（見下） |
| 俯仰 q | 見下 |
| 偏航 r | `yawOuter·β + stickYaw × maxYawRateCommand × 側滑權限` |

**俯仰**：搖桿置中＝1 G 配平飛行，拉滿／推滿＝結構與飛行員的過載上下限。**不擋失速**。

```
qTrim = g·(1 − gLoad) / V        讓機身法向過載 = 1 G 的俯仰率；V ≤ 1 m/s 時為 0
qTrim 夾進 [qMin, qMax]（自動模式的上下限，擋失速）
qTrim −= K × 超過失速前上限的迎角   K = 2 /s；迎角在上限內時這一項為 0
qStickMax = max(g·(gPositive − gLoad)/V, QMAX_FLOOR)
qStickMin = min(g·(max(−3, gNegative) − gLoad)/V, −QMAX_FLOOR)
stickPitch ≥ 0：q = (1 − stickPitch)·qTrim + stickPitch·qStickMax
stickPitch < 0：q = (1 + stickPitch)·qTrim − stickPitch·qStickMin
```

`gLoad`、`qMax`、`qMin` 與自動模式完全同一套（`gLoadFromOrientation`、`pitchRateLimit`、
`nNeg` 的推導）；拉滿／推滿只拿掉其中的氣動（失速）那一項。

- **拉過頭就失速**：低速時結構過載對應的俯仰率遠大於失速前的上限，拉多了迎角越過臨界、升力崩掉、
  速度與高度一起掉。高速時結構先夾住，與瞄準模式同值。失速是左右對稱的，沒有掉翼、不進螺旋
- **置中的配平擋失速**：1 G 失速速度以下若照樣要 1 G，放著不動就一路拉進失速，所以配平仍夾在
  失速前的上限裡
- **放桿就脫離**：1 G 配平假設航跡跟著機首轉；失速後航跡跟不上，只靠配平的話機首被撐在大迎角。
  超過的迎角由置中那一份（乘 `1 − |桿量|`）壓回去，拉滿時不作用
- 量測（P-51D，3000 m）：

  | 速度 | 2 秒內失速的最小桿量 | 拉滿到越過臨界 | 失速後放桿回到臨界以下 |
  |---|---|---|---|
  | 110 m/s | 0.57 | 0.68 s | 0.80 s（沒有壓回項時 2.83 s） |
  | 160 m/s | 拉滿 2 秒也還沒 | — | — |
  | 230 m/s 拉滿 10 秒 | 速度掉下來之後才失速 | | 過載最大 7.13 G（結構 8） |

  Bf 109K-4 110 m/s：0.58、0.72 s、0.75 s

- **為什麼置中是 1 G 而不是 q = 0**：q = 0 是姿態保持。帶坡度放開搖桿時機首停在慣性空間裡不跟著轉彎，
  速度向量被重力往下拉，迎角一路變大，看起來像飛機卡住。1 G 配平是真飛機放開桿的樣子：
  正飛平飛時 q = 0，帶坡度時機首自己跟著轉、慢慢往下掉
- **滾轉**：穩態滾轉率本來就正比於副翼，滿桿就是副翼打滿、這架飛機這個速度下的物理極限。
  原本的做法（估計的最大滾轉率 × 桿量，交給內環追）估計偏低、內環又追不上，滿桿只有瞄準模式的
  六成到七成（試玩回報「滾轉很慢」）。量測（3000 m）：

  | | 只壓桿 | 壓桿＋滿舵 | 瞄準模式 |
  |---|---|---|---|
  | P-51D 110 m/s | 76°/s | 102°/s | 96°/s |
  | P-51D 160 m/s | 112°/s | 148°/s | 128°/s |
  | P-51D 220 m/s | 127°/s | 173°/s | 148°/s |
  | Bf 109K-4 160 m/s | 58°/s | 99°/s | 93°/s |

  瞄準模式滾的時候自己會踩舵，側滑經上反角多給一截滾轉；搖桿要加 A／D 才比得上
- **回中守住坡度**：副翼單純回中的話機體的螺旋傾向會把坡度帶走（P-51D 五秒三十幾度），只把
  滾轉率壓在 0 也會慢慢漂（積分追不上螺旋力矩）。放桿之後先把滾轉收掉，滾轉率低於約 3°/s
  （`HOLD_CAPTURE_RATE`）那一刻記下坡度，之後用改平那一組增益（`wingsLevelGain`、`wingsLevelI`）
  守住它。放桿那一刻就記的話，收掉滾轉之後會被拉回放桿那一點，看起來像彈回去
- **偏航**：`yawOuter·β` 是自動模式就有的消側滑項，搖桿下照樣當協調轉彎用。A／D 在它上面
  疊一個偏航率指令，側滑權限（`betaFadeStart`…`betaMax`）照自動模式夾，所以踩舵側滑上限 10°。
  夾制有方向性：往加大側滑那一邊踩（`stickYaw > 0` 看 `−β`，`< 0` 看 `β`）才會被夾，往回踩永遠有權限
`dbg` 照填：`desiredP/Q/R`、`actualP/Q/R`、`limiter`、`qMin`。瞄準誤差、滾轉指令那幾格填 0。
壓桿時 `desiredP` 寫成實際滾轉率（那一軸不經內環）。

### 4.4 模式切換

`FlightDirector` 記上一步是哪一種模式。換模式的那一步清掉外環積分（`pitchIntegral`、
`levelIntegral`、`yawIntegral`）、`pushMode`、`lastRollCommand` 與跟瞄歷史（`resetTrack`）。
內環 PID 不清 —— 它們追的是角速度，兩種模式意義相同。

不清的話：玩家用搖桿飛了一陣子按 `I`，AI 接手的第一步帶著上一次自動模式殘留的積分。

## 5. 其他系統

| 系統 | 滑鼠搖桿下 |
|---|---|
| 瞄準輔助 | 不作用（它推的是瞄準方向，這個模式沒有）；每幀 `reset` |
| `slewAimWorld` | 不呼叫；`aimWorld` = 機首方向 |
| 投彈瞄具（`B`） | 視角照切，搖桿照飛；`aimWorld` = 機首方向 |
| 代飛 `I`、上帝視角 `G` | 照舊；交還時搖桿歸零 |
| 槍口過熱、投彈、望遠 | 不變 |
| 教學卡 | 不改。講的是預設的滑鼠瞄準；選了滑鼠搖桿的人是自己挑的 |

## 6. 量測出口

`window.__stick()` 回傳 `{ mode, x, y, roll, pitch, yaw }`（設定的模式、搖桿位置、
這一步送進指令的三軸）；`__stick(x, y)` 直接放搖桿位置。給 e2e 用：無頭瀏覽器裡取得
指標鎖的那一下會送一個很大的 `movementX/Y`，先把搖桿放回中心再開始量。

## 7. 護欄（單元測試）

1. **控制律**（`updateManual`）
   - 搖桿置中、正飛平飛：期望 q ≈ 0、p = 0
   - 帶 60° 坡度、搖桿置中：期望 q > 0（機首跟著轉），法向過載約 1 G
   - 低速拉滿：期望 q = 結構過載的俯仰率（大於 `qMax`）；推滿：負過載上限（小於 `qMin`）
   - 高速拉滿（結構先夾住）：期望 q = `qMax`
   - 1 G 失速速度以下、搖桿置中：期望 q ≤ `qMax`
   - 壓桿時副翼等於桿量；滿桿加舵的滾轉率追得上瞄準模式、只壓桿至少六成
   - 方向舵滿：期望 r 往對的方向；側滑超過 `betaMax` 時往加大那邊踩權限歸零、往回踩權限 1
2. **飛起來**（`Aircraft` + 固定指令，P-51D，4000 m，160 m/s）
   - 右滾桿 1 秒後坡度往右；放開之後坡度保持（5 秒內變化 < 5°）
   - 拉桿 2 秒：高度或航跡角往上、過載 > 1.5
   - 3000 m 110 m/s 拉滿 2 秒：迎角越過臨界 10° 以上；放桿 1.2 秒內回到臨界以下
   - 3000 m 230 m/s 拉滿 10 秒：過載不超過結構上限
3. **模式切換**：搖桿飛 → 自動的第一步，外環積分為 0
4. **指令欄位**：所有控制器寫 `manual = false` 與三軸 0（把既有的「接手既有命令」測試補上這四格）；
   `PlayerController` 在搖桿模式下寫 `manual = true` 與曲線後的三軸
5. **輸入**：
   - 搖桿累積、每軸各自夾在 ±1（斜推到底是 (1, 1)）、回中四檔（關不衰減、其餘照時間常數衰減）、暫停（dt = 0）不回中
   - 等速移動的穩態桿量與幀率無關（60 與 240 FPS）；「瞬間」與「快」同一個滑鼠速度推出同一個桿量、停手 0.1 s 內回中
   - 死區與指數曲線：0 → 0、1 → 1、單調、死區內為 0
   - A／D：滑鼠搖桿＋飛行中寫方向舵、上帝視角下照舊平移、放開兩邊都清、`clearHolds` 清
6. **`playerControl`**：搖桿模式下 `aimWorld` = 機首、不呼叫瞄準輔助、滑鼠位移進搖桿；
   觸控層顯示時搖桿位置照抄觸控給的值（§10）；交還控制器、有效模式或搖桿來源換了、`resetStick`（新的一場／重開）時
   非零的桿量與方向舵歸零；`holdIntroInput` 清掉搖桿與方向舵
7. **設定**：兩列的草稿／確定／取消／恢復預設；回中列在草稿是滑鼠瞄準時 disabled；存檔讀寫
8. **HUD**：搖桿模式下 `aimVisible` = false、搖桿指示畫在中央、點的顏色吃失速比
9. **i18n**：新增的字串兩種語言都有

## 8. E2E（`test/e2e/mouse-joystick.e2e.ts`）

照 `god-view.e2e.ts` 的跑法（`npm run dev` + `npx vite-node`）：

1. 開場前在 `localStorage` 寫入滑鼠搖桿，開遭遇戰，按掉教學卡、等物理時鐘開始走
2. 點畫面取得指標鎖，`__stick(0, 0)` 歸零
3. 滑鼠往右移 → `__stick().x > 0`；等 1.5 s → `__probe().bk` 往右
4. `__stick(0, 0)` → 等 2 s → 坡度保持（變化 < 10°）
5. `__stick(0, 0.8)` → 等 2 s → 航跡角上升
6. 按住 D → `__stick().yaw > 0`
7. 搖桿指示真的畫出來了：`__stick(0.8, 0)` 之後，十字範圍之外（中心右方約 0.8 個方框半寬處）
   有綠色；`__stick(−0.8, 0)` 之後那一點移到左邊。只數中央的綠色會被機首十字滿足，
   刪掉整個搖桿指示也照樣通過。存截圖給負責人看搖桿指示的樣子
8. `__stick(0, 1)` 拉滿到 `__stick().alpha` 越過 `alphaCrit`（最多 8 s）；`__stick(0, 0)` 等 1.2 s，
   迎角回到臨界以下
9. 按 `I` 再按 `I`：搖桿歸零、沒有錯誤
10. 全程沒有 console 錯誤

幀率低時（無頭約 7.5 fps）物理照固定步長跑，只量方向不量時間。

## 10. 觸控搖桿

設定是「滑鼠搖桿」而且觸控層顯示時，**左半邊拖曳推搖桿**，取代滑鼠瞄準的拖曳。右半邊拖曳
（自由視角）與所有按鈕不變。設定是「滑鼠瞄準」時觸控照舊。

### 10.1 位置怎麼算

以手指**按下的那一點**為搖桿中心：

```
stickX = clamp( (手指 x − 按下點 x) / R, −1, 1)
stickY = clamp(−(手指 y − 按下點 y) / R, −1, 1)      畫面 y 往下，搖桿上為正
R = TOUCH_STICK_RADIUS × 視窗高度                      TOUCH_STICK_RADIUS = 0.12
```

- 每軸各自夾，與 §3.1 一樣是方形：斜拖到底是 (1, 1)
- **手指按著**：桿量照手指位置，手指停住桿量不變。觸控的位置是手指給的絕對位置，**不經過 §3.1 的
  累積與衰減** —— 套衰減的話「回中：快」會在 0.12 s 內把按住不動的手指吃掉
- **放開之後**（pointerup／pointercancel）照「搖桿回中」設定走：

  | 設定 | 放開之後 |
  |---|---|
  | 關 | 桿量留在放開那一刻，像配平 |
  | 慢／快 | 照 §3.1 的時間常數滑回中間（不吃位移） |
  | 瞬間 | 下一幀就是 0 |

- **從留著的桿量接著推**：按下時搖桿中心放在「手指減掉留著的桿量 × R」那裡，桿量不先跳回 0；
  方框跟著搖桿中心
- 切到背景、轉直放、觸控層收起來（暫停）都會放掉所有手指（既有的 `releaseAll`），觸控層出現或消失
  的那一幀搖桿歸零（§3.2）
- 不吃靈敏度設定：R 固定，畫面上的框（§10.2）恰好是滿桿的位置
- 之後一樣過 §3.4 的死區與曲線
- `TOUCH_STICK_RADIUS` 是起始值，由試玩裁定

### 10.2 畫面

- 按下時出現一個**方框**（邊長 2R，中心是搖桿中心，`index.html` 的 `.t-ring.stick`，大小由程式
  依 R 寫成像素），取代滑鼠瞄準的圓圈。框邊就是滿桿；桿量是 0 時中心就是按下點
- 中央的搖桿指示（§2.3）照舊顯示目前桿量

### 10.3 接法

- `input/touchStick.ts`：`touchStickPosition(dxPx, dyPx, radiusPx, out)` 換算，寫進 `out`、不配置
- `input/touch.ts`：按下時 `state.controlMode === 'stick'` 而且不在上帝視角，握點是 `stick`
  （不是 `aim`），搖桿中心取「手指減掉 `state.stickX/Y` × R」；移動時用相對搖桿中心的位移換算，
  寫進 `TouchControls.stick`（`{ x, y }`）；不累加 `aimDeltaX/Y`。`TouchControls.held` 是「有手指在推」。
  放開時 `stick` 歸零、藏方框（`releaseTouchGrip`）
  - **上帝視角下左半邊照舊是瞄準**：上帝鏡頭吃的是 `aimDeltaX/Y`，推搖桿的話鏡頭轉不動
  - **只認一根手指**：已經有手指在推時，左半邊再按下去的手指整段不算數。兩根一起寫同一份位置
    的話，放開任一根都會把另一根的桿量清掉、方框也跟著藏起來
  - `TouchControls.recentre()`：還按著的那根手指，它現在的位置變成新的中心，位置歸零
- `app/playerControl.ts`：
  - `stickActive` = `controlMode === 'stick'`（拿掉「觸控層沒顯示」那個條件）
  - 搖桿來源 = 觸控層顯示時是觸控、否則是滑鼠；來源或有效模式換了的那一幀歸零
  - 搖桿分支：來源是觸控而且手指按著時 `stickX/Y` 照抄 `touch.stick`；放開時「瞬間」直接歸零、
    其餘 `stepStick(input, 0, 0, dt)`；兩者都清掉這一幀的 `aimDeltaX/Y`。是滑鼠時照舊 `stepStick`
  - **歸零一律連觸控一起**（`centreStick` 加 `touch.recentre()`）：只清 `stickX/Y` 的話，下一幀
    照抄觸控又把按著的手指的位移灌回來，代飛交還、陣亡接手都會帶著舊桿量飛
- 代飛、上帝視角、死亡鏡頭、開場導覽：照 §3.2 走既有的分支，觸控的位置不進搖桿

### 10.4 護欄

1. `touchStickPosition`：原點 0、位移 R 是 ±1、超過 R 仍夾在 ±1、斜拖到底 (1, 1)、畫面往上拖是正、寫進 `out`
2. `releaseTouchGrip`：放開 `stick` 握點時位置歸零、方框藏起來
3. `playerControl`：
   - 觸控層顯示＋設定搖桿：`stickActive` 為真、`stickX/Y` 照抄觸控、`aimWorld` = 機首、不呼叫瞄準輔助
   - 手指不動、回中「快」：多步之後位置不變
   - 放開之後：「關」留著、「快」很快回中、「慢」比快慢、「瞬間」下一幀是 0
   - 觸控層出現或消失的那一幀桿量歸零
   - 設定是滑鼠瞄準＋觸控：照舊走瞄準（`stickActive` 為假）
   - 交還、陣亡接手之後，按著不動的手指不把舊桿量灌回來
4. 觸控層（假的視窗與事件）：依設定分搖桿與瞄準、方框位置與大小、不累加瞄準位移、上帝視角下是瞄準、
   第二根手指不搶、`recentre` 之後從手指現在的位置重新算、按下時從留著的桿量接著推（方框以搖桿中心為準）

### 10.5 E2E（`test/e2e/touch-stick.e2e.ts`）

手機橫放的視窗（`hasTouch`、`isMobile`），`localStorage` 寫入滑鼠搖桿，開遭遇戰：

1. 觸控層顯示、左半邊按下：方框出現在按下點
2. 往右拖 R：`__stick().x` ≈ 1；等 1.5 s 坡度往右
3. 手指不動 1 s：`__stick().x` 不變
4. 往上拖：`__stick().y` > 0
5. 放開（回中「快」）：方框藏起來，物理時間 0.5 s 內 `__stick()` 回到 0.05 以下
6. 截圖給負責人看方框的樣子
7. 全程沒有 console 錯誤
