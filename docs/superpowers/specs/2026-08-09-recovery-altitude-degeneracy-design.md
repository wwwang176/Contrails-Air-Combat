# 拉起高度在「拉不動」時的退化 —— 設計

> 2026-08-09。起因是撤退令棘輪（`2026-08-09-withdraw-anchor-design.md`）的
> 護欄調查挖出來的既有缺陷，與那份 spec 的機制無關。

## 1. 現象

`ai-command-channel.test.ts` 的護欄 `命令期間不動用安全層的撞地接管`
（`o.groundUnderOrder === 0`）是紅的。

把每一次事件的狀態印出來之後，六次事件的高度是：

| 高度 m | TAS m/s | 垂直速度 m/s | 航跡角 |
|---|---|---|---|
| 5,038 | 50 | −0.5 | −0.57° |
| 5,038 | 50 | −0.5 | −0.57° |
| … | 48–58 | ≈ −0.5 | −0.5° 上下 |
| 7,671 | 58 | −0.5 | −0.49° |

**五公里以上、幾乎不下沉的飛機被判定為快要撞地。** 這不是命令層把飛機送
進硬限制的作用區（護欄原本要守的事），是硬限制自己誤觸發。

【原本的假設是錯的】調查初期我猜是 `rally` 把飛機飛進海裡。實測否決：
沒有任何一次事件靠近地面。

## 2. 根因

```ts
export function recoveryAltitude(tas: number, gamma: number, nMax: number): number {
  if (gamma >= 0) return 0
  if (!(nMax > 1)) return Infinity          // ← 這裡
  const radius = (tas * tas) / (G0 * Math.sqrt(nMax * nMax - 1))
  return radius * (1 - Math.cos(Math.abs(gamma)))
}
```

鏈條：

1. TAS 50、5,038 m 的飛機 `nMax = 0.71`（實測，P-51D）。
2. 只要 `gamma` 是**任何一個負值** —— 哪怕 −0.57° —— 就回傳 `Infinity`。
3. `needed = Infinity × factor + clearance = Infinity`。
4. `margin <= needed` 在**任何有限高度**都成立 → 撞地分支接管。
5. 撞地分支命令 +20° 爬升、WEP 油門。

第 5 步是最糟的一步：**那台飛機已經失速了**，而爬升正是它最不該做的事。

【失速分支必定接得住，卻永遠輪不到】`nMax ≤ 1` 的定義是氣動過載上限不到
1 g，等價於 `tas ≤ Vs(1 g)`，也就是 `tas / Vs ≤ 1`。而失速硬介入的門檻是
`stallMargin = 1.1`。所以

> `nMax ≤ 1` ⟹ `tas / Vs ≤ 1 < 1.1` ⟹ 失速分支**保證**成立。

撞地分支排在失速分支之前（§4.5），於是每一次這種誤觸發，正確的補救都被
一個方向相反的命令蓋掉。

【為什麼既有的「不誤觸發」護欄沒抓到】`ai-safety-matrix.test.ts` 的
`SPEEDS = [120, 200, 300]`，而 4,000 m 的 1 g 失速速度約 56 m/s。那組掃描
的每一格都遠在 `nMax > 1` 的一側，從來沒踩進退化區。

## 3. 為什麼不是加一道守衛（已實測否決）

最直覺的修法是把撞地分支的條件收緊：

```ts
if (margin <= needed && nMax > 1) {   // 試過，否決
```

實測 `npx vitest run test/unit/ai-safety.test.ts test/integration/ai-safety-matrix.test.ts`
→ **331 passed / 1 failed**。失敗的是：

```
失速硬介入 > 同時有撞地風險與失速時，走撞地分支（拉起）
```

那條測試的場景是 150 m、速度 `(0, −10, −30)`，即 TAS 31.6、γ = −18.4°、
**`nMax = 0.468`**。它現在之所以會走撞地分支，用的正是要被拿掉的
`Infinity` 那條路。而它的註解記著 §4.5 的裁定：

> 撞地優先，因為失速還有機會改出，撞地沒有。

**守衛等於把 §4.5 在 `nMax ≤ 1` 的整個區域關掉，而那正是 §4.5 唯一會用到
的區域** —— 兩個關切方向相反，只在低速時才會同時成立，而低速正是
`nMax ≤ 1`。

真正的分野不是「拉不拉得動」，是「還有多少高度」：

| | 高度 | 下沉率 | 應該怎麼判 |
|---|---|---|---|
| 誤觸發 | 5,038 m | 0.5 m/s | 有的是高度，先改出失速 |
| 真的危險 | 150 m | 10 m/s | 沒有高度了，拉 |

`nMax` 在這兩格是同一個量級（0.71 對 0.468），區分不了它們。

## 4. 判準：`Infinity` 是錯的答案，不是被錯用的答案

`nMax ≤ 1` 說的是「**用現在這個速度**拉不平」，不是「救不回來」。俯衝會把
高度換成速度，而 `nMax ∝ V²`（固定高度下 `n = q̄·S·CL_max / W`）。所以改出
動作本來就是兩段：

1. **換速度** —— 俯衝到拉得動的速度 `v`；
2. **拉平** —— 在 `v` 上走現行的閉式解。

兩段的高度代價都是有限的，加起來就是這個狀態真正需要的高度。

【現行公式是它的特例】當現在的速度就已經拉得動時，第一段長度為零，總代價
退回 `R·(1 − cos|γ|)` —— 一個字都沒變。**這不是換一個模型，是把同一個模型
的定義域補完。**

## 5. 最佳拉起速度有閉式解，不需要新參數

第一段越長，速度越高、拉起半徑越小，但換速度本身要付高度。中間有一個最佳
點，而它可以直接解出來。

令 `c = 1 − cos|γ|`、`u = v²`。固定高度下 `n(v) = a·u`，`a = nMax / tas²`。

```
總代價 H(u) = (u − tas²) / (2g)          ← 換速度（能量守恆）
            + u·c / (g·√(a²u² − 1))      ← 拉平
```

對 `u` 微分：

```
dH/du = 1/(2g) − c·(a²u² − 1)^(−3/2) / g
```

注意 `d/du [ u·(a²u²−1)^(−1/2) ] = −(a²u²−1)^(−3/2)`（分子的 `a²u²` 恰好
消掉）。令導數為零：

```
(a²u² − 1)^(3/2) = 2c
a²u² = 1 + (2c)^(2/3)
```

而 `a·u = n`，所以

```
n* = √( 1 + (2·(1 − cos|γ|))^(2/3) )
```

**最佳的拉起過載只與航跡角有關，與速度、高度、機種都無關。** 沒有要掃的
定值。

| γ | −1° | −5° | −18.4° | −30° | −45° | −60° | −89° |
|---|---|---|---|---|---|---|---|
| n\* | 1.0023 | 1.0192 | 1.1041 | 1.1898 | 1.3039 | 1.4142 | 1.6028 |

`n*` 恆大於 1，所以 `nMax ≤ 1` 必定落在「要先換速度」那一側。

## 6. 新的 `recoveryAltitude`

```ts
export function recoveryAltitude(tas: number, gamma: number, nMax: number): number {
  if (gamma >= 0) return 0
  if (!(nMax > 0)) return Infinity
  const c = 1 - Math.cos(Math.abs(gamma))
  const root = Math.cbrt(2 * c)          // √(n*² − 1)
  const nStar = Math.sqrt(1 + root * root)
  if (nMax >= nStar) {
    // 現在就拉得動，而且再加速也不划算 —— 與修改前逐位元相同
    const q = nMax * nMax - 1
    return q > 0 ? ((tas * tas) / (G0 * Math.sqrt(q))) * c : Infinity
  }
  // 先俯衝把 n 換到 n*，再拉平。拉起項 = v²·c/(G0·root)，而 c/root ≡ root²/2
  const v2 = (tas * tas * nStar) / nMax
  return (v2 - tas * tas) / (2 * G0) + (v2 * root * root) / (2 * G0)
}
```

【拉起項為什麼不照字面寫】`c = 1 − cos|γ|` 在 `|γ| < 2×10⁻⁸` rad 時
`Math.cos` 捨入成 1，於是 `c = 0`、`root = 0`。照字面寫成 `v²·c / (g·root)`
就是 `Infinity × 0 = NaN`。**而 `NaN` 比誤觸發更糟** —— `margin <= NaN` 恆為
假，安全層會**永遠不介入**。

用恆等式 `c / root ≡ root² / 2`（把 `root = (2c)^(1/3)` 代進去即得）改寫成
`v²·root² / (2g)`：`root = 0` 時它就是 0，除法整個消失。

【單段那一支的 `q > 0` 守衛】同一個角落裡 `n*` 也會捨入成 1，於是
`nMax = 1` 會落進單段支並除以 `√(1−1) = 0`。回 `Infinity` —— 那既是拉起半徑
真正的極限，也與修改前 `!(nMax > 1) → Infinity` 完全一致。

【試過半正矢 `c = 2·sin²(|γ|/2)`，退掉了】它在數學上恆等、浮點下確實不會塌成
0，但**沒有多擋掉任何東西** —— NaN 是上面那個純乘法擋掉的，實測把 `c` 換成
半正矢之後，「極淺負俯衝不會算出 NaN」那條測試在字面除法版仍然紅、在純乘法版
本來就綠。代價卻是實測 288 格安全矩陣裡有 **144 格**回傳值差 1 ULP
（`worstRel = 2.28×10⁻¹⁶`）。那等於拿「拉得動的那一側逐位元不變」這個最強的
迴歸證據，去換一個買不到的東西。

【為什麼 `nMax >= nStar` 而不是 `nMax > 1`】用 `nMax > 1` 當分界會在
`nMax → 1⁺` 留一個跳到無限大的斷點。用 `n*` 當分界，兩側在接縫上相等 ——
接縫的定義就是「最佳速度剛好等於現在的速度」。實測 γ = −45°、TAS 200、
`n* = 1.3039` 附近：

| nMax − n\* | +0.01 | +0.001 | −0.001 | −0.01 |
|---|---|---|---|---|
| 回傳值 m | 1401.8 | 1425.2 | 1430.5 | 1454.6 |

【`v²` 不需要開根號】兩段的公式都只用到 `v²`，所以實作裡沒有多餘的 `sqrt`。
熱路徑（240 Hz × 40 架）多付的是一個 `cbrt`、一個 `sqrt` 與幾次乘除。

## 7. 退化與邊界

| 情況 | 回傳 | 理由 |
|---|---|---|
| `gamma >= 0` | 0 | 不變。沒有在下降就不需要拉起高度 |
| `nMax <= 0` | `Infinity` | 完全沒有升力，換多少速度都拉不動。這是真正的「救不回來」 |
| `tas → 0` | 有限 | `v² = tas²·n*/nMax`，而 `nMax ∝ tas²`，`tas²` 上下抵消。`v*` 有極限，不是奇點 |
| `nMax` 為 `NaN` | `Infinity`（`!(NaN > 0)` 為真） | 與修改前的 `!(nMax > 1)` 同一種寫法，行為一致 |
| `gamma` 極接近 0⁻（`nMax < n*`） | 有限 | 由 §6 的純乘法拉起項保證。照字面寫成除法會回 `NaN` |
| `gamma` 極接近 0⁻ **且** `nMax` 恰為 1 | `Infinity` | 同一個角落裡 `n*` 捨入成 1，於是走單段支。`q > 0` 守衛把它接成 `Infinity` —— 拉起半徑真正的極限，也與修改前一致 |

`tas` 與 `gamma` 為 `NaN` 的情形**不在契約內**：上游 `applySafety` 由
`vel.length()` 與 `Math.asin` 產生這兩個值，兩者都不會是 `NaN`。為一個到不了
的狀態加守衛只會多一行測不到的程式。

【能量模型忽略了什麼】第一段用 `Δh = (v² − tas²) / 2g`，等於假設推力與阻力
相消。實際上 WEP 下的低速段推力大於阻力，所以這個式子**高估**所需高度 ——
偏保守。反方向的偏差是「俯衝過程中 γ 還會變陡」，那一項由既有的
`factor = 1.5` 與 `lookahead = 0.25` 覆蓋，與現行閉式解面對的是同一件事、
同一組補償。**本次不動這兩個值。**

## 8. 影響範圍（實測）

**安全矩陣完全不受影響。** 對 `ai-safety-matrix.test.ts` 的 288 組
（2 機種 × 4 高度 × 3 速度 × 4 俯衝角 × 3 坡度）逐格比對新舊的 `needed`：

```
{"cells":288,"changed":0,"inContract":198,"minRatio":3.332}
```

每一格的 `nMax` 都在 `n*` 的 3.3 倍以上，全部走「與修改前完全相同」那一支。
所以 `withinContract` 的分界不動、`MIN_IN_CONTRACT = 190` 不動、198 組契約內
案例一組不增不減。

【這件事必須逐格比對，不能靠「矩陣測試全綠」】那個測試只斷言每格有限、
契約內不觸海、契約內案例 ≥ 190 —— 它連實測的 198 都沒釘住。少數幾格的
`needed` 變了它仍然可能全綠。實作時要另外跑一次逐格比對並記錄
`changed` 與 `inContract`（見 plan Task 1 Step 9）。

**§4.5 那一格的 263.5 m 是未套 `lookahead` 的瞬時值。** `applySafety` 會先把
γ 往前推 0.25 s；那台飛機是新建的、`diag.loadFactor` 為 0，前瞻後
`worst ≈ −22.65°`，實際 `needed ≈ 282 m`。兩個數字都 > 150，結論相同。

**兩個關鍵場景**（`needed = recoveryAltitude × 1.5 + 120`）：

| 場景 | 高度 | TAS | γ | nMax | 修改前 needed | 修改後 needed | 判定 |
|---|---|---|---|---|---|---|---|
| §4.5 裁定的低空案 | 150 | 31.6 | −18.4° | 0.468 | ∞ | **263.5** | 仍然 `ground` ✓ |
| 誤觸發（P-51D） | 5,038 | 50 | −0.57° | 0.710 | ∞ | **198.8** | 轉為 `stall` ✓ |
| 誤觸發（Bf 109） | 5,038 | 50 | −0.57° | 0.740 | ∞ | 188.1 | 轉為 `stall` ✓ |
| 誤觸發（高的那個） | 7,671 | 58 | −0.49° | 0.712 | ∞ | 225.2 | 轉為 `stall` ✓ |

第一列是這次修改的整個難點：**它必須留在 `ground`**，而它會 —— 263.5 > 150。
第二到四列的 `tas / Vs` 分別是 0.843、0.860、0.844，都低於 `stallMargin`
= 1.1，所以失速分支確實接得住，不會變成「兩邊都不管」。

## 9. 不動的東西

- **§4.5 的順序不動**：撞地判在失速之前。這份 spec 不推翻它，是把「快撞地」
  的判準修對，讓它只在真的快撞地時成立。
- **`DEFAULT_SAFETY` 的六個值不動**：`factor`、`clearance`、`recoveryPitch`、
  `stallMargin`、`stallRecoveryPitch`、`lookahead` 一個都不掃。
- **撞地分支的命令內容不動**：仍然是保持航向、抬 `recoveryPitch`、依角落
  速度決定油門與減速板、停火。
- **`lookahead` 的 `gamma < 0` 限制不動**：它另有理由（平飛套用前瞻會製造
  出一個不存在的俯衝）。但它註解裡「低速時 `nMax ≤ 1`，`recoveryAltitude`
  回 Infinity」那一段講的是本次要修掉的行為，要一併改寫，否則會留下一句
  描述已不存在之機制的註解。

## 10. 測試

### 10.1 單元（`test/unit/ai-safety.test.ts`）

| 斷言 | 為什麼 |
|---|---|
| `nMax` 遠高於 `n*` 時，回傳值與舊公式逐位元相同 | 釘住「不是換模型」。用 `(200, −45°, 6)` 對照手算的 `R·(1−cos45°)` |
| 拉不動（`nMax = 0.5`）時回傳**有限**值 | 取代原本的「回傳 Infinity」。這是缺陷本身 |
| 拉不動時，回傳值仍隨俯衝角變陡而單調遞增 | 兩段模型沒有把方向搞反 |
| 拉不動時，`nMax` 越小回傳值越大 | 越拉不動要換越多速度 |
| **回傳值等於兩段代價在所有 `v ≥ tas` 上的數值掃描最小值** | 這是兩段模型的定義，也是唯一守得住 `n*` 的斷言。涵蓋 `nMax = 1.1`、`1.3`（即 `1 < nMax < n*`）才抓得到「分界誤寫成 `nMax > 1`」 |
| `nMax` 為 0、負值或 `NaN` 時回傳 `Infinity` | `NaN` 若流到 `margin <= needed`，那個比較永遠為假，安全層會**永遠不介入** —— 比誤觸發更糟 |
| 極淺的負俯衝角（`−10⁻⁴` 到 `−10⁻¹²`）回傳有限值 | 守住 §6 的純乘法拉起項 |
| 俯衝角極淺**且** `nMax` 恰為 1 時回傳 `Infinity` | 守住 §6 的 `q > 0` 分支 |
| 拉得動時與單段閉式解**逐位元**相同 | 釘住「不是換模型，是把定義域補完」。整張矩陣 `changed = 0` 就是靠這件事 |
| `tas` 趨近 0 時回傳有限值 | 抵消掉的那個 `tas²` 真的抵消了 |

【接縫連續不另立測試】它由「回傳值是最小值」蘊含：接縫的定義就是最佳速度
等於現在的速度，兩支在該點算的是同一件事。§6 的實測表已把它記錄下來，再寫
一條斷言只會多一條沒有任何 mutation 打得紅的測試。

## 11. 驗收

**主判準**：`ai-command-channel.test.ts` 的
`命令期間不動用安全層的撞地接管`（`groundUnderOrder === 0`）轉綠。

【它不是這份 spec 的假設，是它要回答的問題】修改前那條護欄量到的六次事件
全部是本缺陷。若修改後仍不為 0，代表還有第二個來源 —— 那時**先量、先報告、
先問**，不放寬門檻。同一條護欄在 `ai-command-tactics.test.ts` 有三份
（`rally` / `flank` / `focus`），一併看。

**副判準**：`test/integration/ai-withdraw-anchor.test.ts` 的觀測輸出
（半徑成長、傷害、撤退佔用率）不得惡化。安全層在高空少接管一次，AI 就少
被推去爬一次，預期是持平或變好；若變差要查。

## 12. 不做的事

- **不改「拉不動時撞地分支該下什麼命令」。** 150 m、`nMax = 0.468` 的飛機
  被命令爬升，物理上兌現不了多少 —— 但那是 §4.5 已裁定的政策，改它要另開
  一份 spec。本次只修「什麼時候算快撞地」。
- **不處理 `ai-command-channel` 的撤退佔用率 2.81% < 5%。** 那是撤退令棘輪
  那份 spec 留下的獨立待決項。
- **不掃 `factor` / `clearance` / `lookahead`。** 本次沒有引入新的自由參數，
  沒有要掃的東西；既有三個值的取值理由不因這次修改而失效。
- **不動 `recoveryAltitude` 的簽名。** 仍是 `(tas, gamma, nMax)` 三個純數字，
  仍不需要 `spec` 與高度 —— 因為 `n(v) = nMax·(v/tas)²` 讓「任意速度下的
  過載上限」可以只從傳進來的這三個數推出來。

### 13.6 Mutation 驗證

實作在執行途中換過一次形狀（見 plan 的「執行中的偏離」），所以六個 mutation
是對**最終**版本重跑的：

| # | mutation | 打紅了哪一條 |
|---|---|---|
| 1 | 刪掉 `if (!(nMax > 0)) return Infinity` | `nMax 為 0、負值或 NaN 時回傳 Infinity` |
| 2 | `nMax >= nStar` → `nMax > 1` | `回傳的是…最小值`、`nMax 恰為 1…` |
| 3 | `sqrt(1 + root*root)` → `sqrt(1 + root)` | `回傳的是…最小值` |
| 4 | `nMax*nMax - 1` → `nMax*nMax + 1` | `拉得動時與單段閉式解逐位元相同` 等三條 |
| 5 | 拉起項改回除法 `(v2 / (G0*root)) * c` | `極淺的負俯衝角不會算出 NaN` |
| 6 | 拿掉單段支的 `q > 0` 三元 | `nMax 恰為 1 且俯衝角極淺時回傳 Infinity 而不是 NaN` |

六個全部轉紅，且每一個都只打到它該守的那幾條。
