# 音訊動態：限幅、去相關與 HDR 混音 —— 設計

2026-09-23

## 目標

1. **任何場面都不破音。**
2. **該聽到的一定聽得到**：爆炸不會被一片機槍蓋掉，警告與無線電永遠穿得出去。
3. **安靜時聽得到細節**：沒有大場面時，風聲、彈殼、遠處的引擎浮得出來。

## 現況與根因

### 破音

主匯流排上**沒有任何限幅**。鏈路是「每個聲道 → 主音量 → 淡入 → 喇叭」，
所有聲音直接相加，超過 0 dBFS 就削平。

實際踩到的情境：上帝視角貼著航母，八架同時用機槍打艦體（每發 +6 dB 的低頻
悶響）、艦砲 +5 dB、炸彈爆炸 +6 dB 又疊兩層 —— 全部在參考距離內等於全音量，
峰值上到 +18 dB 以上。

`audio/catalog.ts` 開頭那段「爆炸是天花板，+6 已經接近破音」就是這個限制的
症狀：目前唯一的手段是手動把每一類配好，沒有任何自動機制兜底。

### 同檔同相疊加

同一個檔案同時播兩份是**完全同相**，直接 +6 dB。爆炸的第二層已經有隨機延遲，
但機槍打在艦體（`impact`）這種一秒好幾次的沒有。

### 聲道（已修，列在這裡當基線）

2026-09-23 之前一次性聲道只有 40 個。盟 M3「沖繩外海」實測 120 秒：艦砲要求
1,573 次、被擋 365 次，空聲道長時間掛在 0，軍火爆炸被擋 21/54。加到 64 並給
每一類上限之後，同一組量測下爆炸與軍火爆炸 0 次被擋（commit `208b4a0`）。

## 四個部分

### 一、真峰值限幅器（最後一道）

放在鏈路最後：`主音量 → 淡入 → 限幅器 → 喇叭`。

**為什麼要自己寫 `AudioWorklet`**：瀏覽器沒有 look-ahead 限幅器。
`DynamicsCompressorNode` 是壓縮器，起音再快第一個瞬間也會漏過去 —— 而爆炸
正好全是瞬態。自寫的 worklet 用幾毫秒的預看緩衝，看得到還沒送出的峰值，
才壓得住。

起始參數（**由試聽裁定**）：

| 參數 | 起始值 | 理由 |
|---|---|---|
| 預看 | 5 ms | 夠蓋住瞬態的上升緣；延遲小到聽不出 |
| 天花板 | −1 dBFS | 留給 mp3 解碼與重取樣的誤差 |
| 起音 | 0（預看之內瞬間到位） | 預看的意義就是不必犧牲起音 |
| 釋放 | 120 ms | 短了會抖（失真），長了大聲之後整體悶一段 |

**壞掉會怎樣**：worklet 載入失敗時**必須直接連通**（bypass），不能整個世界沒
聲音。這是這一層唯一不可妥協的失敗模式。

### 二、同檔去相關

同一刻播同一個檔案時：

- 播放速度已經有 ±8% 隨機（沿用）。
- **新增**：起始位置隨機 0–15 ms（單次音效目前一律從 0 開始）。
- **新增**：同一檔在 30 ms 內的第二份，延遲 3–12 ms 再播。

兩份同相是 +6 dB，錯開之後約 +3 dB。

### 三、HDR 動態窗口

**概念**：每個聲音跟「當下最響的那一個」比，差太多就不發聲；輸出增益由相對
響度決定，而不是絕對音量。安靜時窗口下移，細節自己浮出來；爆炸時窗口上移，
機槍自動退到背景。

**輸入已經有了**：`voiceLoudnessDb`（類別增益＋距離衰減＋空氣吸收）就是「這個
聲音到耳朵大概多響」，現在用來搶聲道，HDR 直接沿用同一個值。

**狀態**：一個全域的 `loudest`，快起音、慢釋放。

```
每一幀：
  peak = 場上所有發聲中的最大響度
  loudest = max(peak, loudest − RELEASE_DB_PER_SEC × dt)
  floor   = loudest − WINDOW_DB
  每個聲音的輸出增益 = clamp01((loudness − floor) / WINDOW_DB) 對應的 dB
  loudness < floor 的：一次性音效不發、循環音靜音（不停，避免反覆重播）
```

起始參數（**由試聽裁定**）：

| 參數 | 起始值 | 壞掉會怎樣 |
|---|---|---|
| 窗口寬度 `WINDOW_DB` | 45 dB | 太窄：安靜場景只剩最響那一個，世界變空。太寬：等於沒有 HDR |
| 釋放速率 | 12 dB/s | 太快：一聲爆炸結束整個世界突然變大聲。太慢：爆炸後好幾秒聽不到東西 |
| 起音 | 立即 | 爆炸要立刻壓下其他人，慢一拍就聽到「先吵後退」 |

**保底類別**：警告、無線電、自己的引擎、自己的槍、選單按鈕**不受窗口影響**。
玩家必須聽到的東西不能因為場面吵就消失；Valve 的 HDR 也是這樣特例處理。
保底不等於不衰減 —— 它們本來就多半是不定位的。

**與側鏈閃避的關係**：HDR 做的是逐音源版本的閃避，**做了它就不需要**再另外
拉一條爆炸的側鏈去壓武器匯流排。少一層要調的東西。

### 四、聲道管理（已完成，這一份只寫它與上面三層的關係）

依估計響度搶聲道、每類配額。HDR 上線後被擋的次數會再降（太小聲的根本不進
池子），但兩者防的不是同一件事：**HDR 防「聽不見的還佔著位」，配額防「一類
把池子吃光」**。兩個都留。

## 既有的每類增益不動

素材本身已經是同一個響度（−16 LUFS ＋峰值補償），`CATEGORY` 的那些數字是
**試玩之後定下來的期望音量**，不是為了搶天花板才堆上去的。所以這三層都不
以「改增益」為前提：

- 限幅器只在意外的疊加時介入，平時不作用 —— 它不該改變已經調好的相對關係。
- HDR 改的是**同一刻誰讓誰**，安靜時每一類仍然照既有的數字發聲。
- 上線後若試聽覺得整體被壓得太多，**先退 HDR 的窗口寬度**，而不是去動每一類
  的增益。重新定值是負責人的決定。

## 驗收

| 項目 | 方法 | 門檻 |
|---|---|---|
| 不破音 | 探針在盟 M2 上帝視角貼航母，錄 30 s 取樣真峰值 | 峰值 ≤ −1 dBFS，削平樣本數 0 |
| 爆炸不被蓋 | 既有的 `__audioStats` 探針（120 s 盟 M3） | `explosion`、`blast` 被擋 0 次 |
| 安靜時有細節 | 遭遇戰開場 20 s，統計 HDR 靜音掉的次數 | 靜音比例 < 10% |
| 限幅器壞掉不會沒聲音 | 單元測試：worklet 載入失敗時走 bypass | 鏈路仍然通 |
| 熱路徑不配置 | 逐幀的 HDR 更新與去相關 | 不配置 |

## 風險

- **worklet 的相容性**：`AudioWorklet` 在目標瀏覽器都有，但載入是非同步的，
  而且需要同源的模組檔。載入前先走直通，載好再切。
- **HDR 的調音是主觀的**：三個參數彼此耦合，要留時間試聽。上線後若覺得「變
  得很怪」，第一個要退的是窗口寬度而不是釋放速率。
- **測不到的部分**：真峰值可以量，「聽起來對不對」量不到。這一份的每一個
  起始值都由試聽裁定。

## 不做

- 分匯流排壓縮（武器／爆炸／引擎各一條再各壓一次）。HDR 已經處理了類別之間
  的讓位，多一層只是多一組要調的參數。
- 音樂與選單的動態（選單只有按鈕在響）。
- 環繞或 HRTF（定位模式維持 `equalpower`，見既有的音效設計）。
