# 音訊動態：限幅、去相關與 HDR 混音 —— 設計

2026-09-23

## 目標

1. **任何場面都不破音。**
2. **該聽到的一定聽得到**：爆炸不會被一片機槍蓋掉，警告與無線電永遠穿得出去。
3. **安靜時聽得到細節**：沒有大場面時，風聲、彈殼、遠處的引擎浮得出來。

## 現況與根因

### 破音

主匯流排上**沒有任何限幅**。鏈路是「每個聲道 → 主音量 → 淡入 → 喇叭」，
所有聲音直接相加，超過 0 dBFS 就削平。

實際踩到的情境：上帝視角貼著航母，八架同時用機槍打艦體（每發 +6 dB 的低頻
悶響）、艦砲 +5 dB、炸彈爆炸 +6 dB 又疊兩層 —— 全部在參考距離內等於全音量，
峰值上到 +18 dB 以上。

`audio/catalog.ts` 開頭那段「爆炸是天花板，+6 已經接近破音」就是這個限制的
症狀：目前唯一的手段是手動把每一類配好，沒有任何自動機制兜底。

### 同檔同相疊加

同一個檔案同時播兩份是**完全同相**，直接 +6 dB。爆炸的第二層已經有隨機延遲，
但機槍打在艦體（`impact`）這種一秒好幾次的沒有。

### 聲道（已修，列在這裡當基線）

2026-09-23 之前一次性聲道只有 40 個。盟 M3「沖繩外海」實測 120 秒：艦砲要求
1,573 次、被擋 365 次，空聲道長時間掛在 0，軍火爆炸被擋 21/54。加到 64 並給
每一類上限之後，同一組量測下爆炸與軍火爆炸 0 次被擋（commit `208b4a0`）。

## 四個部分

### 一、真峰值限幅器（最後一道）

放在鏈路最後：`主音量 → 淡入 → 限幅器 → 喇叭`。

**為什麼要自己寫 `AudioWorklet`**：瀏覽器沒有 look-ahead 限幅器。
`DynamicsCompressorNode` 是壓縮器，起音再快第一個瞬間也會漏過去 —— 而爆炸
正好全是瞬態。自寫的 worklet 用幾毫秒的預看緩衝，看得到還沒送出的峰值，
才壓得住。

起始參數（**由試聽裁定**）：

| 參數 | 起始值 | 理由 |
|---|---|---|
| 預看 | 5 ms | 夠蓋住瞬態的上升緣；延遲小到聽不出 |
| 天花板 | −1.5 dBFS 的**樣本**峰值 | 見下一段 |
| 起音 | 0（預看之內瞬間到位） | 預看的意義就是不必犧牲起音 |
| 釋放 | 120 ms | 短了會抖（失真），長了大聲之後整體悶一段 |

**樣本峰值不等於真峰值**：限幅器看得到的是樣本，而樣本之間的波形可以更高
（ITU-R BS.1770 附錄 2）。最壞情況下重建峰值比樣本峰值高約 1 dB。所以天花板
訂在 −1.5 dBFS 樣本峰值，等於留下約 0.5 dB 的真峰值餘裕；**驗收量的是真峰值**
（見驗收那一節的過取樣定義），不是樣本峰值。

**兩種失敗都要直通**：

- **載入失敗**：`audioWorklet.addModule()` 拋例外 → 不插節點，鏈路照舊。
- **執行期失敗**：模組載好之後，建構或 `process()` 拋未捕捉例外會觸發
  `processorerror`，那個節點從此**永遠輸出靜音** —— 而它在最後一道，症狀是
  整場突然全部沒聲音。所以要掛 `onprocessorerror`，收到就把節點旁路掉。

**暫停與換場要清緩衝**：預看緩衝在 `fade` 的下游，裡面那 5 ms 是**已經乘過
舊的淡入增益**的樣本。context 暫停時 worklet 不跑，恢復時那幾毫秒會先送出去，
於是聽到「舊聲音的一小段爆點，然後才淡入」。恢復與 `stopAll()` 都要透過
`port` 送一則重設訊息，讓 processor 把緩衝歸零。

### 二、同檔去相關

同一刻播同一個檔案時：

- 播放速度已經有 ±8% 隨機（沿用）。
- **新增**：同一檔在 30 ms 內的第二份，延遲 3–12 ms 再播（`start(when)`，不動
  起始位置）。

兩份同相是 +6 dB，錯開之後約 +3 dB。

**不做隨機起始位置**：一度考慮過跳掉開頭 0–15 ms，但那會直接裁掉起音。實測
`hit-1.mp3` 前 15 ms 的峰值 −6.77 dBFS、整段峰值 −6.15 dBFS —— 撞擊的力量就在
那一段裡。症狀會是同一種命中有時候「軟掉」，而且從非零的波形中途起播還會多
一個突變。既有的播放程式刻意不做音量漸變，就是為了保住這段起音。

### 三、HDR 動態窗口

**概念**：每個聲音跟「當下最響的那一個」比，差太多就不發聲；輸出增益由相對
響度決定，而不是絕對音量。安靜時窗口下移，細節自己浮出來；爆炸時窗口上移，
機槍自動退到背景。

**輸入**：`voiceLoudnessDb`（類別增益＋距離衰減＋空氣吸收）是「這個聲音**剛
發出來**時到耳朵大概多響」，現在用來搶聲道。HDR 沿用它，但**必須再乘上素材
自己的包絡**（見下一段）。

**素材包絡是必要的，不是精修**：`voiceLoudnessDb` 沒有播放進度。實測
`explosion-5.mp3` 全長 7 秒，前半秒 RMS −15 dBFS、最後一秒只剩 −52.5 dBFS ——
只看它的話，一聲爆炸會把窗口頂住 7 秒，背景要等檔案播完才回得來。

作法：`manifest.json` 每個檔案多一欄 `envelopeDb`，是每 0.25 s 一格、相對整段
峰值的 RMS（**由既有的素材處理腳本產生**，與 `makeupDb` 同一條路）。播放中的
聲音其響度 = `voiceLoudnessDb` ＋ 這一格的包絡值，逐幀查表，不插值。
沒有這一欄的檔案退回 0（等於現在的行為）。

**狀態**：一個全域的 `loudest`，快起音、慢釋放。

```
每一幀：
  peak    = 場上所有發聲中的最大「即時響度」（含包絡）
  loudest = max(peak, loudest − RELEASE_DB_PER_SEC × dt)
  floor   = min(loudest − KNEE_DB − WINDOW_DB, ABS_FLOOR_DB)
  對每個聲音：
    over = loudness − (floor + WINDOW_DB)      // 進入不衰減區多少
    衰減 dB = over >= 0 ? 0 : max(MAX_DUCK_DB, over × (MAX_DUCK_DB / WINDOW_DB))
    loudness < floor 的：一次性音效不發、循環音靜音（不停，避免反覆重播）
```

**衰減是加在既有增益上的，不是取代**。而且有兩道保證，讓「安靜時維持既有的
相對音量」成立：

- 離最響者 `KNEE_DB` 以內的一律不衰減。安靜場景裡所有東西通常都落在這一段，
  於是整場等於沒有 HDR。
- `floor` 另外夾在絕對值 `ABS_FLOOR_DB`。場上只有一隻蒼蠅時窗口不會跟著掉到
  蒼蠅的高度、把別的東西全部算成「相對很響」。

起始參數（**由試聽裁定**）：

| 參數 | 起始值 | 壞掉會怎樣 |
|---|---|---|
| 不衰減區 `KNEE_DB` | 20 dB | 太小：安靜場景也被改音量。太大：爆炸壓不下機槍 |
| 窗口寬度 `WINDOW_DB` | 25 dB | 太窄：衰減變成硬切。太寬：讓位太慢 |
| 最大衰減 `MAX_DUCK_DB` | −18 dB | 太深：被壓的類別整個消失。太淺：等於沒讓位 |
| 絕對地板 `ABS_FLOOR_DB` | −40 dB | 太高：安靜場景的細節被砍。太低：窗口失去作用 |
| 釋放速率 | 12 dB/s | 太快：爆炸一停整個世界突然變大聲。太慢：爆炸後好幾秒聽不到東西 |
| 起音 | 立即 | 爆炸要立刻壓下其他人，慢一拍就聽到「先吵後退」 |

**保底類別**：警告、無線電、自己的引擎、自己的槍、選單按鈕**不受窗口影響**。
玩家必須聽到的東西不能因為場面吵就消失；Valve 的 HDR 也是這樣特例處理。
保底不等於不衰減 —— 它們本來就多半是不定位的。

**狀態的生命週期**：`loudest` 跨幀存在，所以要說清楚誰清它。

- **暫停、切分頁、關音量**：保留。回來時場面沒變，窗口不該重來。
- **`stopAll()`（換場、離場、重新開始）**：立刻歸零到 `ABS_FLOOR_DB`。不清的話
  上一場最後那顆炸彈的窗口會帶進新的一場，開頭好幾秒細節被壓掉。

**與側鏈閃避的關係**：HDR 做的是逐音源版本的閃避，**做了它就不需要**再另外
拉一條爆炸的側鏈去壓武器匯流排。少一層要調的東西。

### 四、聲道管理（已完成，這一份只寫它與上面三層的關係）

依估計響度搶聲道、每類配額。HDR 上線後被擋的次數會再降（太小聲的根本不進
池子），但兩者防的不是同一件事：**HDR 防「聽不見的還佔著位」，配額防「一類
把池子吃光」**。兩個都留。

### 五、音訊執行緒的成本

音訊執行緒算不完時，瀏覽器塞靜音補上 —— 聽起來是一陣劈啪，**輸出峰值與
限幅量完全不變**。大場面（三十條以上同時發聲）的爆音就是這一種。

Chrome 看到 panner 或 listener 的位置參數有排程，就改走逐取樣重算方位與距離
的路徑；listener 一有排程，每一個 panner 都被拖進去。離線渲染量到的負載（40 條
「增益 → 兩級低通 → panner」）：

| 更新方式 | 負載 |
|---|---|
| 不動 | 6% |
| 每幀直接設 `.value` | 19% |
| 每幀排 `linearRampToValueAtTime`（three 的預設） | 67% |
| 兩級低通每幀排 `setTargetAtTime` | ＋11% |
| 限幅器逐格掃 240 格的窗 | 1.5～8%（單獨一條） |

所以：

- 聲源與 listener 用 `spatial.ts` 的子類別，位置**只在變了才寫 `.value`**，
  不排漸變；panner 朝向不寫（全部聲源都是全向）。
- 低通的截止頻率變動超過 3% 才重排。
- 限幅器的窗內峰值用單調佇列（每個樣本攤還 O(1)），實測 0.6%。

錶上的「落後」是音訊時鐘相對牆上時鐘少走的毫秒數，持續往上長就是算不完。
盟 M3 貼航母 80 秒：改前累計落後 5.6 s，改後 0～5 ms。

## 既有的每類增益不動

素材本身已經是同一個響度（−16 LUFS ＋峰值補償），`CATEGORY` 的那些數字是
**試玩之後定下來的期望音量**，不是為了搶天花板才堆上去的。所以這三層都不
以「改增益」為前提：

- 限幅器只在意外的疊加時介入，平時不作用 —— 它不該改變已經調好的相對關係。
- HDR 改的是**同一刻誰讓誰**，安靜時每一類仍然照既有的數字發聲。
- 上線後若試聽覺得整體被壓得太多，**先退 HDR 的窗口寬度**，而不是去動每一類
  的增益。重新定值是負責人的決定。

## 驗收

**真峰值怎麼量**：在限幅器之後接一個 `MediaStreamDestination` 錄下 PCM（或在
worklet 裡把輸出樣本經 `port` 送出），對每一個聲道各自做 **4 倍過取樣**
（多相 FIR 內插，ITU-R BS.1770 附錄 2 的作法），取內插後的最大絕對值。
只數「樣本是否達到 ±1.0」會漏掉樣本之間的超標。

| 項目 | 方法 | 門檻 |
|---|---|---|
| 不破音 | 盟 M2 上帝視角貼航母，錄 30 s，4 倍過取樣算真峰值 | 真峰值 ≤ −1.0 dBTP；連續三個樣本同號且 |x| ≥ 0.999 的段落數 0 |
| 爆炸聽得到 | 同一段錄音，取每次爆炸起音後 200 ms 的 A 加權能量，與同時間其他類別的能量比 | 爆炸的占比 ≥ 50%；另外 `explosion`、`blast` 被擋 0 次 |
| 安靜時不被動到 | 遭遇戰開場 20 s，記錄每個聲音的 HDR 衰減量 | 95 百分位的衰減 ≤ 1 dB；被靜音的比例 < 2% |
| 爆炸時真的有讓位 | 同上，取爆炸後 300 ms 內武器類別的衰減量 | 中位數 ≥ 6 dB |
| 限幅器失敗不會沒聲音 | 單元測試：載入失敗與 `processorerror` 兩條路 | 兩條都旁路，鏈路仍然通 |
| 恢復不爆點 | 暫停 2 s 再恢復，錄音檢查恢復後 20 ms | 峰值不超過恢復前 100 ms 的均值 |
| 換場不帶狀態 | `stopAll()` 之後讀 `loudest` | 等於 `ABS_FLOOR_DB` |
| 熱路徑不配置 | 逐幀的 HDR 更新與去相關 | 不配置 |
| 音訊執行緒算得完 | 盟 M3 貼航母 80 s，每 10 s 讀錶上的「落後」 | 累計落後 ≤ 30 ms |

## 風險

- **worklet 的相容性**：`AudioWorklet` 在目標瀏覽器都有，但載入是非同步的，
  而且需要同源的模組檔。載入前先走直通，載好再切。
- **HDR 的調音是主觀的**：五個參數彼此耦合，要留時間試聽。上線後若覺得「安靜
  時被動到」，先加大不衰減區；覺得「爆炸壓不住機槍」，先加深最大衰減。
- **包絡表要跟著素材走**：換過的素材沒有重跑處理腳本的話，`envelopeDb` 會對不
  上，症狀是那一個音效的讓位時機怪怪的。退回 0 是安全的預設。
- **測不到的部分**：真峰值可以量，「聽起來對不對」量不到。這一份的每一個
  起始值都由試聽裁定。

## 不做

- 分匯流排壓縮（武器／爆炸／引擎各一條再各壓一次）。HDR 已經處理了類別之間
  的讓位，多一層只是多一組要調的參數。
- 音樂與選單的動態（選單只有按鈕在響）。
- 環繞或 HRTF（定位模式維持 `equalpower`，見既有的音效設計）。
