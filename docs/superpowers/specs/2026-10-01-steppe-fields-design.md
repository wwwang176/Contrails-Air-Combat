# 草原田：俄國南部的集體農場大田

2026-10-01

## 1. 要做的事

庫斯克的地面現在用中歐那一套田（200～300 m 的小矩形、每塊再對切、田界長樹籬），只是把
樹籬機率調低。史實上 1943 年那一帶的田是**集體化之後合併的大田**，沒有樹籬：

- 大矩形，約 500～1,100 m，邊界多半是直線
- 田界是一條淺色的田埂或土路，不長樹（防風林帶是 1948 年之後才大規模種）
- 樹只長在沖溝（balka）、河谷與村子周圍
- 陡坡與沖溝邊是沒耕的牧草地

**另寫一套地面算法**（風格 `steppe`），不去調中歐那套的參數：中歐那套的假設（小地塊、田界
即樹籬、田圍著村、寫死的地塊上限 `PARCEL_HALF_DIAG = 293`）都在著色器常數與 CPU／GPU
對照測試裡。

負責人裁決（2026-10-01）：另寫一套新的地面算法；第一版做大矩形田加田埂加牧草地，
沖溝與沿溝的樹留到第二版。

| 地塊 | 大矩形、朝向跟著區域角度、不對切 | |
| 田界 | 淺色田埂 | |

## 3. 做法

### 3.1 風格由季節表選

`FieldColors` 加 `layout: 'european' | 'steppe'`。夏季與晚秋是 `european`，七月麥田是
`steppe`。`fieldGlsl(season)` 依它產生不同的著色器；`european` 的輸出逐字不變（夏季基準
雜湊、`fields.test.ts` 的金本位行不動）。

### 3.2 地塊

沿用「區塊（Voronoi，3,200 m）＋區塊自己的角度」的框架（`regionAt`），因為凹路（土路）、
村站址、菜園都掛在它上面。區塊裡的地塊換成新的：

- 格寬 544～896 m、格長 653～1,075 m（照區塊雜湊在範圍內
  變化），格線仍然抖動（`EDGE_JITTER` 小一點），讓邊界不是尺畫的直線
- **不對切**
- 地塊雜湊決定作物與是不是牧草地

### 3.3 田界與牧草地

- 田界：離最近一條格線不到 `STEPPE_BALK / 2`（約 4 m）的帶，畫成田埂色（比麥淺、偏土黃）
- 牧草地：每塊田以 `PASTURE_CHANCE`（約 0.14）變成牧草地，色取 `FieldColors.open`／`openAlt`
  兩色低頻漸變，沒有條播紋
- 凹路壓過田埂（與現在的優先權一樣）

### 3.4 植被

- `steppe` 風格沒有田裡的樹籬與樹林田：`farmHedgeFlora`／`farmWoodFlora`／開放地圖的兩支
  都不接（散佈器清單裡不放）
- 建築、果樹與菜園照 `steppeVillage.ts`（已做）
- 第二版再加沖溝樹帶

### 3.5 CPU 版

**沒有。** `fieldSurfaceColor` 只剩測試在呼叫，而 `fieldAt` 讀的是中歐那一組常數；草原田的
植被不讀田界，執行期沒有任何呼叫者。`fieldSurfaceColor` 對 `steppe` 風格直接丟錯，不回
一個靜靜地錯的色。

### 3.6 實作的形狀

著色器只有一份 `fieldColorAt`，兩種格局換的是 `fieldGlslBase` 的幾個常數（格寬、格長比、
抖動、對切機率、田界寬與機率、「樹林田」的比例）與牧草地那一行顏色；`european` 輸出的字串
逐字不變。`createInlandTerrain` 在 `steppe` 時不開 `open`、田裡的散佈器清單是空的。

## 4. 不做

- 不動 `european` 風格的任何輸出
- 不做真的沖溝地形（高度場 80 m 一格，做不出窄溝）；第二版的沖溝只是地面上的一條帶加樹
- 不做作物隨季節變化

## 5. 測試（只測小部件）

- `european`：既有基準全部不動（`summer-palette-baseline`、`fields`、`open-land`）
- `steppe` 著色器在真的 GPU 上編譯通過（`glsl-compile.e2e.ts`）
- 地塊大小落在範圍內（取樣 CPU 版的格寬）
- 同一點 CPU 版取色是田埂色／牧草色／作物色三者之一，凹路壓過田埂
- 庫斯克地形的散佈器清單裡沒有樹籬與樹林田
