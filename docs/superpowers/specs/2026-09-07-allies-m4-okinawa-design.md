# 盟 M4「沖繩外海」—— 守住艦隊

2026-09-07

## 1. 要做的事

把 `allies-m4` 由 `battle: null` 變成打得起來的一關。

```
  我方   F6F-5 地獄貓（玩家）
  敵方   A6M5 零戰 → 打退之後 G4M 一式陸攻低空進場雷擊
  要守   第 58 特遣艦隊：Essex ×1、Wichita ×2、Fletcher ×6
  時地   1945 年 4 月，沖繩外海　慶良間列島以西
```

負責人裁定兩件事：

1. **艦隊編成走方案甲**（9 艘，一艘航母）
2. **波次觸發是「時間到 **或** 零戰剩 30%」，先到先算** —— 要的是緊迫感

## 2. 缺的東西

這一輪之前的四種規則（`mission.ts`）沒有一種表達得出「我方的船被打沉就輸」：

| kind | 講的是什麼 | 為什麼不適用 |
|---|---|---|
| `annihilate` | 哪一邊的**飛機**先全滅 | 完全不看船 |
| `evacuate` | 玩家飛到某個點 | 不是這一關的敘述 |
| `convoy` | 某一隊的**轟炸機**抵達或全滅 | `protectedMask` 是 `Combatant` 的索引（`target.ts:549`），而**船不是 `Combatant`**（`ships.ts` 檔頭） |
| `sink` | 擊沉 N 艘**敵艦** | 方向相反 |

`mission.ts:157` 上一輪就把這件事標記好了：

> 【為什麼只算敵方】友軍的船在 `allies-m4` 那種「守住艦隊」的關才有意義，
> 而**那是另一條規則**。

`setup.ts:1511` 的計數迴圈也寫著同一句。**這一輪就是去補那條規則。**

### 已經在的（查證過，不必做）

- **三個艦級模型**：Essex CV-9、Fletcher DD-445、Wichita CA-45，含艦體命中盒與血量
- **艦載三層防空**：5″/38 兩用砲（空中引爆）、40 mm Bofors、20 mm Oerlikon。
  `shipGuns.ts:366` 的 `o.team === ship.team` 早退 —— **藍艦會打紅機**
- **`placeFleet` 逐字透傳 `e.team`**（`setup.ts:920`），藍隊艦隊在結構上成立
- **紅方 AI 會打藍方船**：`pickShipTarget` 的 `s.team === selfTeam` 早退
  （`shipAttack.ts:117`）
- **AI 的雷擊剖面**（`ai/torpedoRun.ts`）—— 日 M4 已經在用，那是 AI 開 G4M 投雷
- **波次的存活數選擇器含 `role`**：`MissionTrigger` 的 `alive` 有
  `role?: 'fighter' | 'bomber'` 與**必填的 `byLatest`**（`missions.ts:51`）

**`byLatest` 就是負責人要的「或時間到」** —— 它的註解寫著「到了這個秒數
無條件成立」，而德 M4 的註解把兩者的關係講明了：「兩個是**誰先到算誰**」。

### 2.2 但不是「只加一條規則」—— 另外三件事

查證之後發現三件不是資料的事：

1. **預警期間會提前判勝**（§5.3 的 `redInbound`）。`setup.ts:1467` 的既有
   註解說「節拍排在編制之前」解決了「最後一架被擊落的**同一步**要能加第二
   波」，但**沒有解決 `warned` 到 `dueAt` 之間那幾秒**。盟 M4 是第一關
   「整場都是殲滅形狀、而且波次由敵方消耗觸發」的卡，所以第一次踩到。
2. **Essex 沒有預載。** `main.ts:2199` 是
   `preloadShipModels(['wichita', 'fletcher'])`，註解還寫著「只載會用到的
   兩艘 —— japan-m4 沒有航母」。不補就是進關丟例外。
3. **紅方 G4M 對藍方船的整條路徑從來沒跑過。** 每一層查起來都是團隊感知的
   （`pickShipTarget` 的 `s.team === selfTeam`、`shipGuns.ts:366` 的
   `o.team === ship.team`、`placeFleet` 逐字透傳 `e.team`），但既有的整合
   測試**全部是藍打紅**。要有一條反向的（§7.4）。

## 3. 範圍

**不做新模型、不做新 AI、不動彈道。**

- **不做輕航母、不做戰艦。** 沒有模型，而這一關不需要它們才成立（見 §4）。
- **不做雷達哨戒驅逐艦。** 史實上它們派在 70–130 km 外單獨站崗，那是另一
  張地圖的尺度。
- **不做神風。** 那是一套自殺衝撞的行為，與現有的雷擊剖面是兩回事。
- **不動 `sink` 規則。** 日 M4 靠它，這一輪一個字都不碰。
- **不把船畫進小地圖。** `main.ts` 的 minimap 只吃 `hudFrame.contacts`，而
  那一份只填飛機 —— **紅方的船在日 M4 也一樣不在小地圖上**，這是既有的
  行為不是這一關的迴歸。船已經有 HUD 標記（倒三角形，依隊別上色），而
  艦隊就在雙方的中點上、玩家一開場就朝著它飛。要不要補進小地圖等試飛之後
  再看。

## 4. 艦隊

### 4.1 史實的一個特遣支隊

TF 58（Mitscher 中將）1945 年 4 月分成四個支隊。單一支隊的典型編成：

```
  艦隊航母 CV      2–3      輕航母 CVL   1–2
  快速戰艦 BB      2–3      巡洋艦       3–5
  驅逐艦   DD     13–18     合計      約 22–28 艘
```

環形防空序列：航母在中心（彼此 2,300–2,750 m）、戰艦與巡洋艦內環、驅逐艦
外環（半徑 3,600–5,500 m）。

### 4.2 遊戲裡放 9 艘

```
  Essex     ×1   中心
  Wichita   ×2   內環，左右各一
  Fletcher  ×6   外環警戒幕
```

**為什麼航母只有一艘**：只有三個艦級模型，兩艘 Essex 並排會讓重複很明顯
（日 M4 的「12 艘取 8 艘」是同一個理由），而且**「守兩艘」會讓失敗判定變
模糊**。一艘航母＝一個要守的東西，這一關的情緒才立得住。

**為什麼還要六艘驅逐艦**：它們不是佈景 —— 每一艘都有完整的三層防空，是
玩家真正的火力支援。史實上外環的密度正是航母能活下來的原因。

陣型沿用 `RENNELL_FLEET` 的尺度（整隊橫跨約 1.8 km），數值起始值待試飛。

### 4.3 艦隊擺在原點

雙方 `headOn` 進場都收斂到中點，所以艦隊放原點時**空戰自然發生在艦隊
上空** —— 艦載防空因此真的參戰，而不是遠遠看著。玩家從 +Z 出發迎擊，
艦隊在他背後到中間的那一段。

## 5. 新規則 `defend`

```ts
| {
  /**
   * 守住我方艦隊。**勝負都寫在這一條裡。**
   *
   *   負  任何一艘要害艦被擊沉（**排在勝之前**，見 §5.4）
   *   勝  紅方飛機全滅，而且沒有敵機正在進場的路上
   *   負  藍方飛機全滅
   */
  kind: 'defend'
}
```

### 5.1 為什麼不是「沉 N 艘就輸」

`lossLimit: number` 表面上更泛用，實際上更難讀：九艘裡沉三艘算輸的話，
玩家看不出**哪三艘**要緊，而「掉一艘驅逐艦就往失敗前進三分之一」與畫面上
發生的事對不起來。

**要害艦是那一艘航母。** 護衛艦的價值在它們的防空火網，那已經是機制上真的
（`shipGuns.ts` 每一艘都在開火），不必再寫進勝負條件。

### 5.2 哪一艘是要害：`MissionFleet` 的一個旗標

```ts
readonly ships: readonly {
  readonly cls: ShipClassId
  readonly team: Team
  readonly offset: Vector3
  /** 這一艘沉了就輸。**只有 `defend` 規則讀它。** */
  readonly vital?: true
}[]
```

**為什麼是旗標而不是 `cls === 'essex'`**：把艦級寫進規則的話，哪天換一艘船
當主角就要改規則；而旗標與艦名單住在同一個地方，看得到編成就看得到誰要緊。

**為什麼是 `?: true` 而不是 `boolean`**：`exactOptionalPropertyTypes` 開著，
與 `FlightPlan.player` 同一個寫法 —— 手寫的關卡表不必為每一艘補 `vital: false`。

### 5.3 `MissionInputs` 加兩格

```ts
/** 我方**要害艦**已經沉了幾艘。`defend` 以外的規則不讀 */
vitalSunk: number
/**
 * 還有敵機正在進場的路上 —— **已經預警、還沒生出來**。
 *
 * 【為什麼勝利要看它】`stepBeats` 在觸發那一步先把節拍轉成 `warned`，飛機
 * 要等 `warnLead` 秒才生成（`setup.ts` 的 `dueAt`），而 `stepMission` 只
 * 數場上活著的。那幾秒之內紅方歸零的話會**先判勝，第二波永遠不來** ——
 * 這一關的下半場整段跳過，而畫面上一切正常。
 *
 * 【為什麼不是只有 `defend` 讀】任何「把對方打光就贏」的規則都有同一個洞。
 */
redInbound: boolean
```

`setup.ts` 那個既有的迴圈本來就掃過每一艘（`sh.team === 'blue'` 早退），
**在同一個迴圈裡多一個計數**，不另開一輪；兩格都要**每一步先歸零**，與
既有的 `shipsSunk` 逐字同一個做法。

**沒有 `vitalTotal`。** 一艘 `vital` 都沒有時 `vitalSunk` 恆為 0，`defend`
自然退化成 `annihilate` —— 再寫一條顯式的 fallback 是死碼（刪掉它行為
完全相同，所以那條護欄殺不死）。「卡片漏標 `vital`」由卡片測試守（§7.3）。

### 5.4 判定順序：**要害艦排在勝利之前**

```
  vitalSunk > 0                        → defeat
  否則 紅方全滅 且 !redInbound          → victory
  否則 藍方飛機全滅                     → defeat
```

**這一條刻意不沿用「victory 先於 defeat」。** 那條慣例的理由是 `evacuate`
的「飛進圓環那一步剛好時限歸零，判贏才符合玩家的認知」—— 那是**同一個
目標在邊界達成**。這裡不是：最後一架零戰與航母同一步沉，而這一關的整句話
就是「航母被擊沉就輸」。判成勝利的話，結算畫面會在一艘沉到海底的航母上
寫「任務成功」。

**沒有要害艦時這一條恆為 false**，順序因此不影響其他關卡。

## 6. 波次

### 6.1 觸發

```ts
when: {
  kind: 'alive', side: 'theirs', role: 'fighter',
  atMost: 2,        // 開場 8 架零戰的 25%（30% 是 2.4）
  byLatest: 120,    // 或者兩分鐘到，先到先算
}
```

`role: 'fighter'` **不能省**：`MissionTrigger` 的註解已經寫著「盟 M4 是
『打退**戰鬥機**之後魚雷機才來』，不是『紅隊剩幾架』」。省了的話第一批
G4M 進場之後會把自己算進存活數，第二批就永遠不來。

兩個數字都是**起始值，由試飛裁定**。

### 6.2 編成

```
  開場   藍 F6F-5 ×4（玩家在長機）      紅 A6M5 ×8
  波次   紅 G4M ×4    warn「雷擊機低空進場」  warnLead 6 s
```

一個波次就是一支小隊，上限 `SCHWARM_SIZE`（4 架）—— 要更多就再加一則。
第一版只放一批，試飛之後再決定要不要第二批。

### 6.3 開場高度 2,000 m

低於預設的 4,000：G4M 進場之後要降到 `RUN_ALTITUDE`（150 m）才投得出雷，
從 4,000 m 掉下來那一段是空白時間。**起始值，由試飛裁定。**

## 7. 護欄

### 7.1 `defend` 的三條路各自成立

- 紅方全滅、`redInbound` 為 false → victory（要害艦還在）
- 藍方飛機全滅 → defeat
- 要害艦沉 → defeat（**雙方飛機都還在**，證明這一條自己就判得出來）

### 7.2 要害艦沉的那一步紅方也全滅 → **defeat**

**這一條會抓到判定順序寫反**（§5.4）。它與既有那條「victory 先於 defeat」
的慣例方向相反，所以更需要釘住。

### 7.3 沒有要害艦時與 `annihilate` 逐格相同

同一組輸入餵給 `defend`（`vitalSunk = 0`）與 `annihilate`，逐格斷言整個
`MissionState` 相同。

**這一條不做 mutation 宣稱** —— `vitalSunk` 恆為 0 時那一條分支本來就
不影響結果，拿掉它行為完全一樣。真正守「卡片漏標 `vital`」的是 §7.6 的
卡片測試（`allies-m4` 的艦隊恰好一艘 `vital`）。

### 7.4 紅方 G4M 真的打得到藍方的船

**這一條是這一輪最重要的新測試。** 既有的整合測試**全部是藍打紅**，
反向從來沒跑過。固定場景，逐步斷言：

```
  紅方 G4M 選中藍船        pickShipTarget 回傳那一艘
  進入雷擊剖面             TORPEDO_PROFILE 的 phase 走到 run
  投得出去                 世界上真的多一枚魚雷
  藍船掉血                 hp 實際下降
```

少了任何一段，前面那幾條護欄都還是綠的，而玩起來是「敵機繞著艦隊飛，
什麼也不做」。

### 7.5 預警期間不判勝

節拍已經 `warned`、飛機還沒生出來的那幾秒，把紅方存活數壓到 0 →
**仍然 `fighting`**。少了這一條，這一關的下半場會整段跳過而畫面上一切正常。

### 7.6 卡片與透傳

- `allies-m4` 的艦隊恰好 9 艘、恰好一艘 `vital`、**全部 `team: 'blue'`**
- `missionRules` 給出 `defend`
- **透傳**：`fleet`（含 `vital`）原樣到 `BattleConfig`；`waves` **轉成等價的
  `cfg.beats`** —— `BattleConfig` 上**沒有** `waves` 這一格
  （`missionConfigFrom` 會轉譯），不要為了測試新增一個
- `campaigns.test.ts` 的可玩／鎖定數要一起更新（現在精確斷言鎖定 6 關）

### 7.7 日 M4 一個字都不能動

`sink` 規則、`RENNELL_FLEET`、`mission.test.ts` 既有的每一條全綠。

## 8. 開放項

- 架數（4 v 8、G4M ×4）、`atMost 2`、`byLatest 120`、開場高度 2,000 m、
  艦隊陣型的間距 —— 全部是**起始值，由試飛裁定**。
- 要不要第二批 G4M：等第一批試飛完再決定。
- HUD 的目標讀數第一版沿用殲滅那一套（敵機剩幾架）。「航母中雷」要不要
  有預警訊息，等試飛看得出需不需要。
