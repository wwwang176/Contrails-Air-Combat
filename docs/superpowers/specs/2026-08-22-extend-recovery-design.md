# 脫離之後回得來 —— `extend` 的出場條件與回場方向

**狀態**：待專案負責人審。實作尚未開始。

**前置**：本文與 `2026-08-22-energy-tactics-design.md`（AI 的主動能量經營）
是**兩件事**。那一份加的是戰術層（`quota` 預設 0，尚未上線）；這一份修的是
**意圖層既有的 `extend`**，與戰術層開不開無關。

---

## 1. 人工回報

> 「當我觸發 extend 能量時，飛機會以目前方位向前飛，通常你向前飛，等於是
> 遠離戰場了，結果等到能量補完要回頭根本追不上（轟炸機已被打或是戰場已
> 轉移）。」

同一次驗收另外回報：`extend` 的理由**九成是「能量」**，偶爾是「能量＋見底」。

## 2. 實測

### 2.1 `extend` 沒有「往哪裡退」這個概念

`steer.ts` 的 `extend` 分支只呼叫 `unloadAim(self, extendPitchAngle(…), out)`。
`unloadAim` 的實作註解逐字寫著「**維持航向**、把航跡角設成 pitch」。

**水平方向完全不參與決策。** 這條路徑回答的是「要不要退」與「退得多陡」，
從來沒有回答「退到哪裡去」。機頭當下指著哪，就一路飛向哪。

### 2.2 出場條件對劣勢方不可達

```
extendEnergyLatch   energyAdvantage < −300 m 觸發
                    energyAdvantage > +100 m 才解除
```

**進場與出場都是相對的。** 而會觸發脫離的定義上就是劣勢的一方 —— 要「比對手
多 100 公尺比能量」才准回頭，這個條件在整場戰鬥中都達不到（對手也在休息）。
實測玩家座位代飛時，能量閂鎖曾連續開著 46 秒、166 秒不曾關過。

【它與 §1 的關係】方向缺失（2.1）本身不致命，**是「退很久」把它放大成致命**。
退三秒沒有方向不要緊，退四十秒沒有方向就飛出戰場了。

### 2.3 戰場真的被推出去了，而且早就有測試在抗議

`test/integration/ai-withdraw-anchor.test.ts`「撤退令不得把戰鬥推出戰場」：

```
戰場半徑上界   6,500 m
實測           11,110 m
```

**這條在本分支的起點（`af8f976`）就已經是紅的**，不是任何一輪改動造成的。
它量的正是人工回報那件事在 20v20 尺度上的樣子。

### 2.4 這個量對設定極度敏感，不要拿它比大小

玩家座位代飛、只把初速擾動 ±0.5%，`extend` 佔時：

```
axis-escort   bf109g6    6.2%   29.1%   11.8%   36.4%   27.6%
allies-escort p51d      43.6%   27.0%   72.8%   17.0%   16.9%
```

兩張卡的範圍完全重疊。**「哪一張卡比較嚴重」這個問題，目前的方法答不了**，
所以本文不用它下任何逐卡的結論；驗收一律用 §8 的半徑指標。

## 3. 根因：三個各自獨立的缺口

| | 缺口 | 症狀 |
|---|---|---|
| 甲 | 出場條件是相對的，劣勢方不可達 | 一退幾十秒 |
| 乙 | 脫離沒有水平方向 | 退去的方向由當下機頭決定，等於隨機 |
| 丙 | 「有人在追我」與「我比他弱」被當成同一件事 | 修好乙之後會轉向追兵 |

三者相互獨立：甲不修，乙修了也只是換個方向飛遠；乙不修，甲修了仍會往外偏
一小段；丙是乙的前置安全條款 —— **沒有丙就不該做乙**。

---

## 4. 改動一：出場條件多一條絕對的出路

### 4.1 做什麼

`extendEnergyLatch` 的**解除**多一條路：

```
解除 =  energyAdvantage > energyExit          （既有，相對）
     或 cornerRatio      > recoverRatio        （新增，絕對）
```

`cornerRatio` = 自己的 TAS ÷ 自己在當下高度的角落速度。**它與對手無關**，
所以劣勢方達得到。

【為什麼用 `cornerRatio` 而不是別的量】`extendFloorLatch` 已經用它（0.75 /
0.95），兩條規則因此共用同一把尺 —— 「我還飛不飛得動」只需要一個定義。新增
一個獨立的絕對量會讓兩條規則對「能打了沒」給出不同的答案。

【為什麼是「多一條出路」而不是換掉】進場仍然該是相對的：「他比我強」本來就是
該脫離的理由。**要換掉的只是出場** —— 讓一個相對的理由用一個絕對的條件收場，
這個不對稱是刻意的，而且正是 §2.2 那個陷阱的解。

### 4.2 必須配一個再進入冷卻

【為什麼】`latch` 的遲滯只在**同一個量**上成立。用 `cornerRatio` 解除之後，
`energyAdvantage` 很可能仍然低於 −300 —— 下一個決策拍就重新閂上，變成 10 Hz
的抖動。

所以絕對出路解除的那一次，要記一段**再進入冷卻**（`extendRecoverHold`，秒）：
冷卻期間 `extendEnergyLatch` 不得因為 `energyAdvantage` 重新閂上。相對出路
（`energyAdvantage > energyExit`）解除時**不需要**冷卻 —— 那條路本來就有遲滯。

【它不是新概念】戰術層的 `cooldown` 是同一個手法：一個止損結束之後給一段
不准馬上重來的時間。

### 4.3 不動的東西

`extendTurnLatch`（機體轉不贏）與 `extendFloorLatch`（我飛不動了）**一個字
不動**。前者談的是機體，補能量改變不了它；後者本來就是絕對的。

## 5. 改動二：補能量時把機頭飄回戰場

### 5.1 做什麼

`extend` 的瞄準解在 `unloadAim` 之外，加一個**受限的水平偏置**：把水平方向
朝「回場方向」轉，但**轉的力道有上限**。

### 5.2 上限用傾斜角訂，不是用角度差

轉彎的代價是可以算的。傾斜角 φ 決定過載 `n = 1 / cos φ`，誘導阻力正比於 `n²`：

```
傾斜  15°    過載 1.035    誘導阻力 +7%
傾斜  30°    過載 1.155    誘導阻力 +33%
傾斜  45°    過載 1.414    誘導阻力 +100%
```

**15 度以內近乎免費。** 所以上限訂在**傾斜角**（`extendBankMax`，起始值
15°），不是「機頭與目標的夾角不得超過 X」。

【為什麼這個分野重要】用角度差當上限的話，敵人在正後方時它會一次轉一大把；
用傾斜角當上限，不管敵人在哪，**每一秒的能量代價都是同一個固定值**，只是
轉回去要花的時間不同。這與專案一貫的作法一致 —— 限制的是代價，不是誤差。

【它天然是連續的】傾斜角上限是一個夾住的量，不是一個門檻，所以不會在任何
一條線上翻號。

### 5.3 回場方向指向誰

**指向被保護單位，不是指向當前目標。**

人工回報在意的不是「追不上那架 P-51」，是「回去的時候轟炸機沒了」。
`TargetBoard.protectedMask` 已經知道哪幾架是這一關要護送／攔截的（2026-08-22
戰術層那一輪加的），取其中最近的一架的方位當回場方向。

**`protectedMask` 全 0 的關卡（遭遇戰、掃蕩）退回當前目標的方位。** 那些關卡
沒有「戰場中心」這種東西，而目標在哪裡戰場就在哪裡。

### 5.4 只偏水平，不動俯仰

俯仰仍然完全由 `extendPitchAngle` 決定。**這一項只碰水平方向** —— 兩者混在
一起改，之後就分不出是誰造成的。

## 6. 改動三：背後有人追的時候不飄

### 6.1 為什麼

`extend` 觸發的理由是「我比他弱」，而**最常見的成因就是有人咬在後面**。
這種時候把機頭轉向敵人等於自己送上去 —— §5 單獨上線會製造一個新的死法。

### 6.2 判準

回場偏置的力道乘上一個 0..1 的抑制係數，由**威脅**連續決定：

```
抑制 = 1 − min(1, threatInstant / extendThreatFull)
```

`Situation.threatInstant` 是既有欄位。`extendThreatFull`（起始值待掃描）是
「威脅到這個程度就完全不轉回去」的飽和點。

【為什麼是連續的而不是一個布林】門檻式的開關會在威脅邊界上讓水平指令跳變，
那正是這個專案反覆治過的病。連續衰減沒有翻轉點。

【`defend` 不必特別處理】真的被咬到要閃的時候意圖已經是 `defend`，根本不走
`extend` 這條路徑。這一項擋的是「還沒到要閃、但後面確實有人」那一段。

## 7. 順序與相依

**必須分三次上線，而且照這個順序。**

```
第一步   §4（出場條件）           單獨量一次半徑
第二步   §6（威脅抑制）           它是 §5 的安全前置，先落地
第三步   §5（回場偏置）           量半徑與 §8 的副判準
```

【為什麼不一起做】三件事都會動到「戰場半徑」這個驗收指標。一起改的話，
半徑變好或變壞都分不出是誰造成的 —— 而 §2.4 已經證明這個系統的量測雜訊很大，
沒有乾淨的單變數對照就等於沒有結論。

【為什麼 §4 先】它最小、沒有任何新幾何、而且沒有風險（縮短脫離不會讓 AI 死得
更快）。**如果 §4 就讓脫離縮到數秒，§5 的收益會小很多** —— 那時候要不要付
那個複雜度就是一個有數據的決定，而不是一個猜測。

## 8. 驗收

### 8.1 主判準：既有的那條紅測試

`test/integration/ai-withdraw-anchor.test.ts`「半徑有界」：戰場半徑 ≤ 6,500 m
（現況 11,110 m）。

**這條不是新訂的門檻**，是本分支起點就存在、就已經紅的護欄。它變綠就是這份
spec 成立；它沒變綠，這份 spec 就沒有解決人工回報的那件事。

### 8.2 副判準：不得把 AI 變弱

三步各自跑完之後都要比對：

- `test/integration/ai-targeting.test.ts` 的 `fireShare`
- `test/integration/ai-duel-matrix.test.ts`
- `test/unit/perf-gate.test.ts`（單獨跑）
- 五次 ±0.5% 初速微擾下的存活數與擊墜數

【為什麼要微擾】§2.4 量到單次跑的分散度極大。**單一次比對得到的差別，八成
落在雜訊裡** —— 這個教訓在這一輪已經付過兩次學費。

### 8.3 逐事件的觀察

`test/tools/extend-trigger.probe.ts`（已存在）逐次列出進入 `extend` 的前因。
三步之後應該看到：

- 能量閂鎖的持續時間由「數十秒到數分鐘」掉到**數秒**
- 進入 `extend` 的次數可以上升（退得短、退得勤是預期的），但**每次的持續時間
  要下降**
- 進入時的距離分布不該系統性往近距離集中（那表示脫離變成了原地抖動）

## 9. 起始值（**全部待掃描**）

| 參數 | 起始值 | 依據 |
|---|---|---|
| `recoverRatio` | 0.95 | 與 `cornerExit` 同值 —— 「飛得動了」只該有一個定義 |
| `extendRecoverHold` | 8 s | 起始值，量級取自戰術層的 `cooldownSeconds`（12 s）略短 |
| `extendBankMax` | 15° | 誘導阻力 +7%，見 §5.2 的表 |
| `extendThreatFull` | 待定 | 沒有可引用的量級，第一步實作前先量 `threatInstant` 的分布 |

**四個都是起點不是定值。** 專案的規矩是先落地再掃描，而掃描出來的重新定值
要專案負責人裁定。

## 10. 明確不做的事

- **不動 `energyEnter` / `energyExit` / `cornerEnter` / `cornerExit` /
  `floorExempt` / `extendRange`。** 那六個是掃描定案的護欄值，重新定值是專案
  負責人的決定。這份 spec 全部靠**新增**的條件與參數達成目的。
- **不動 `extendTurnLatch` 與 `extendFloorLatch` 的判準。**
- **不碰戰術層。** `quota` 的預設值、`order-of-battle-replay` 的基準重跑，
  都是另一份 spec 的待裁定事項。
- **不做「退向錨點 vs 退離敵人」的取捨機制。** §5.3 選的是被保護單位，
  沒有引入「錨點在敵人方向時怎麼辦」這個新問題；那個取捨如果真的需要，
  應該由實測逼出來，不是預先發明。

## 11. 要專案負責人裁定的

1. **`ai-withdraw-anchor` 的 6,500 m 上界要不要沿用。** 它是這份 spec 的主
   判準，而它從分支起點就是紅的 —— 若那個上界本身已經過時，整份驗收要重訂。
2. **§9 的四個起始值掃描出來之後的定值。**
3. **三步之中若某一步讓副判準退步超過雜訊**，是要退回那一步，還是接受退步。
