# 烘進地面的林子與屋頂隨視角變亮暗

> **地面那一部分已拿掉**：烘進地面的林子與屋頂當一般地面貼圖，不乘視角係數、不排除反光；
> 畫樹的地方地面改用近處的樣子。見 `2026-10-19-ground-under-drawn-trees-design.md`。
> 這份文件留下的是點的視角係數（§2.1 的樹種三列、§2.3 的點池）。

## 1. 問題

遠處的樹與房子不畫立體模型，分成三層：

| 距離 | 畫法 | 明暗跟什麼有關 |
|---|---|---|
| 植被圈外（6 km） | 烘進地面的顏色（樹冠色、屋頂色塊） | 只看太陽高度，任何方向看都一樣 |
| 3～6 km | 點（`gl.POINTS`，不吃光照） | 只看俯角（`POINT_TOPDOWN_GAIN`） |
| 3 km 內 | 立體網格（`MeshStandardMaterial`，平面著色） | 看鏡頭在太陽哪一側 |

烘圖與點都是「定死的顏色」，立體模型不是。實測正午、俯角 10°、1.5 km：迎光 30、背光 52、
正上方 52（畫面亮度）。迎著太陽飛向林子，過了 3 km 樹突然暗一截；黃昏背光時反過來亮一截。
房子更明顯：低太陽背光時牆面被照亮，立體房子是屋頂色塊的三到四倍亮。

## 2. 做法

**烘圖只存「這裡有多少樹、多少屋頂」，從這個角度看多亮在畫的時候才算。**

### 2.1 視角係數 K

`K(V) = R(V) / R(正上方)`，逐通道（RGB）。`R(V)` 是一類物件從方向 `V`（物件指向鏡頭）看過去，
每單位投影面積的平均輻射：

```
R(V) = Σ_面 A·max(0, n·V)·albedo·E(n)  /  Σ_面 A·max(0, n·V)
E(n) = 太陽色·強度·max(0, n·L) + mix(地色, 天色, ½ + ½·n.y)·半球強度 + 環境光
```

與 three 的 Lambert 那一份相同（`BRDF_Lambert` 的 1/π 約掉）；鏡面項不算（粗糙度 0.9）。
面取**實際的中級幾何**（`createFloraGeometries` 的 `broadMid`、`coneMid`、`bushMid`、`house`），
轉向 16 個方位平均（實例的轉向是亂數）。房子的箱體頂面藏在屋頂底下，用「沿法線的射線碰到別的面」
剔掉。

**房子那一列不帶顏色**（每一面當白色算）：四種房子與教堂的牆／屋頂配色不同，帶顏色的話
係數裡會混進「紅瓦換成米色牆」的比例，套到石板瓦上是錯的。屋頂色塊本來就照 `WALL_SHARE` 混了
三成牆色，係數只管光照與幾何。實例的非等比縮放、草原村沿路排列的朝向不算 —— 一列一種房子、
轉向平均是近似。

**正上方 = 1** 是約定：烘圖本來就是俯視的顏色，現有的地色、點的亮度在俯視時不動。實測正午立體
樹冠俯視 52、點 54、烘圖與點已經校過，所以這個參考點與既有的校正一致。

驗證（量測台，四個時段 × 四個俯角 × 五個方位，與 CPU 算的比）：闊葉正午／雷雨誤差 3～4%，
房子 7～12%，針葉迎光偏亮約一成；低太陽的闊葉 14～18% 是量測只取了一個轉向（八面體四重對稱）。

### 2.2 查表

`K` 只與「水平視線與太陽水平方向的夾角餘弦 c」與「視線仰角的正弦 s」有關（太陽方向開局後固定）。
CPU 在 `setPalette` 時算一張 32（c）× 16（s）的表，一類一列：闊葉、針葉、灌木、房子、地面林子
（這張地圖的樹種比例混出來的）。半浮點 RGBA 貼圖，線性過濾。著色器查一次表。

### 2.3 用在哪裡

| 地方 | 改法 |
|---|---|
| 點池（`vegetationPools.ts`） | `POINT_LIGHT × foliage × POINT_TOPDOWN_GAIN × K_樹種(V)`，取代只看俯角的增益 |
| 雷伊泰地面（`leyteGround.ts`） | 樹冠圖那一份的顏色乘 `K_地面林子`（場內查圖、場外頂點色反推的那兩支） |
| 群島地面（`island.ts`） | 頂點多一條覆蓋率屬性，林相那一份乘 K |
| 農地內圈與遠景環（`farmGround.ts`、`farHorizon.ts`） | `fieldColorAt` 同時記「樹冠佔了多少亮度」，乘 K |
| 田色 clipmap（`fieldClipmap.ts`） | 第二張 RG8 貼圖（MRT）存樹冠／屋頂的亮度份量，地面著色器讀它乘 K |
| 疊圖（`buildingBake.ts` 的色塊、河漫灘林地） | 頂點多一條 `viewShade`（這一點的顏色的亮度有幾成來自樹冠、幾成來自屋頂），烘圖時乘上顏色的亮度寫進第二張；其他疊圖寫 0，照不透明度蓋掉底下的份量。河漫灘的林地與草甸混色，給的是亮度佔比不是混色比例 |
| 河漫灘的遠處粗網格（`leunaFeatures.ts` 的 `floodplainFar`） | 直接畫的網格，材質掛鉤（`beyondFar`）裡乘 K |

**農地只在「遠處的樣子」裡算**（`fieldFar = 1`：遠圖、最外兩層、內圈在近窗外的那一段）。近圖
裡的林地色與樹籬色是真的樹底下的地，不是樹冠。

旁路（`setBypass`，A/B 用）時被烘掉的網格照原材質畫，河漫灘的林地不乘 K。

### 2.4 農地為什麼存「亮度份量」而不是覆蓋率

遠圖一格 7.3 m，加上 mipmap，大多數像素是田與樹籬混在一起。若存覆蓋率 f、整個像素乘
`1 + f(K−1)`，亮的田會跟著暗的樹籬一起被壓暗（f = 0.2、K = 0.4 時那一格暗一成）。存的是
`樹冠顏色的亮度 × 覆蓋率`（線性），畫的時候用 `份量 / 這一格的亮度` 當樹冠的佔比：

```
col ← col ⊙ (1 + (K_林 − 1)·s_林 + (K_屋 − 1)·s_屋)，s = 份量 / lum(col)
```

份量與顏色都是線性平均，mipmap 後兩者仍對得上。

**這是近似**：純樹冠、純屋頂的像素（s = 1）是精確的；混色像素的亮度變化對，但變化照整格的
色相分配，不是照樹冠的色相（田的那一份跟著變了一點、樹冠那一份少變一點）。一個像素只顯示混好的
那一個顏色，差別在色相上，量級是 (K−1)·s 乘兩者色相的差。要精確得存樹冠的 RGB 貢獻，一層多
三個通道，記憶體付不起。

**比例尺逐季節、逐通道**：份量乘一個數再存進 8 位元，那個數是 `0.95 / 這個季節最亮的那一種
（樹冠色 × 明度抖動上限）`，屋頂另算一個。冬季覆雪的樹冠亮度到 0.75、屋頂色塊到 0.85，夏季的
樹冠只有 0.03～0.05 —— 共用一個固定的數不是截斷冬季就是夏季只剩十幾階。

### 2.5 記憶體與效能

近圖烘的是近處的樣子，份量恆為 0，**不配第二張**。遠圖、最外兩層各多一張 RG8：遠圖 4096²
約 43 MB（含 mipmap），兩張 2048² 各約 11 MB，合計約 65 MB（原本約 148 MB）。農地、洛伊納、
勒熱夫在這台（Iris Xe）實跑都沒有掉 context。

GPU 時間（農地正午、700 m 平視、地面佔滿畫面、1600×900，與 main 同機位交錯量六輪的中位數）：
2.90 → 3.07 ms（+0.17 ms）。壓到這裡靠三件事，每一件都量過：

| 做法 | 省下 |
|---|---|
| 視角係數在地面逐頂點查（三角形 80 m，份量只在 2 km 以遠）；遠景環一格將近 100 km，另一份材質逐像素查 | 約 0.2 ms |
| 第二張不開各向異性過濾 | 約 0.1 ms |
| 份量那一段不包 `if`（份量為 0 的像素乘 1） | 約 0.2 ms |

點池在頂點著色器查表，量不出差別。

### 2.6 地面的光照（`matteGround.ts`）

6 km 線內的點與線外烘在地上的林子，迎著太陽時仍差一階（林子正中央 33 對 48），關掉距離霧
也一樣。原因是標準材質把地面當成平滑的面：斜看時菲涅耳把鏡面放大，正午迎光 18° 的鏡面約是
林子漫射的一半，而視角係數只乘在漫射上。地面（雷伊泰、群島、農地、遠景環、貼片）改兩件事：

- **烘在地上的林子與屋頂不算鏡面**：地面著色器把樹冠與屋頂佔的比例寫進 `groundTreeShare`，
  那一份的鏡面拿掉。田、草地、路照舊反光（`GROUND_SPECULAR` = 1）—— 整片地拿掉鏡面的話
  迎光的田暗一成多，比主線暗；把鏡面染成地面色則保住亮度，但看起來不對
- **太陽那一份漫射走 Oren-Nayar**，粗糙度 σ = 0.2（`GROUND_ROUGH`）：小凸起順光露出受光面、
  逆光露出背光面與影子，地面背光亮、迎光暗，與林子的係數同一個方向。天空光、環境光、爆炸的
  點光源照舊

結果（正午、同一機位）：林子正中央迎光 30 對 31、背光 50 對 50；700 m 巡航的地面平均亮度
迎光 81.6（主線 82.8）、背光 77.0（主線 76.5）。GPU 中位數多約 0.1 ms。`__groundSpecular`、
`__groundRough` 可以同頁對照。

## 3. 不動的東西

  `ROOF_GROW`、`WALL_SHARE`、`POINT_LIGHT`、`POINT_TOPDOWN_GAIN`、各時段的 `foliage`／`foliageTint`
- 立體模型的材質與光照

## 4. 驗收

- 單元：K 在正上方恆為 1；正午低俯角迎光 < 背光；太陽方向鏡射，表跟著鏡射；房子的箱體頂面被剔掉
- `flora-card.e2e.ts`：中級樹冠（2.5 km）與點（3.6 km）在迎光／側光／背光／俯視四個方位都要接得上
  （差 8% 內）；拿掉點的 K 必紅。順手修好量測台的半徑（20 km 超過格數上限）
- `glsl-compile.e2e.ts`、i18n 護欄
- 截圖：日 M2（雷雨）、正午農地、黃昏，同一機位 K 開／關
- 效能：同頁 A/B，`uViewShadeOff` 開關
