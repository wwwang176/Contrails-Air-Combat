# 船的失速滑行與命中點火災

2026-09-07

## 1. 要做的事

專案負責人：

1. **船血量歸零後，速度慢慢降低** —— 現況是瞬間煞停。
2. **船被炸到的地方（炸彈與魚雷都算）要起火。** 火災是每 0.3 秒一次的迷你
   爆炸，另外生一道**垂直向上**的煙（持續比較久）。每個火點燒 **1 分鐘**。

## 2. 現況

### 2.1 沉了就瞬間停

```ts
// world/ships.ts
export function stepShips(ships, dt) {
  for (const s of ships) {
    if (!s.alive || s.speed === 0) continue   // ← 這一行
    ...
  }
}
```

`alive` 一轉 false，那一艘在**同一個物理步**內從 8 m/s 變成 0。一萬噸的船
在畫面上像撞到牆。

### 2.2 命中點只有一朵爆炸，然後什麼都沒有

`emitBombBlasts` / `emitTorpedoBlasts` 各放一次煙火就結束。船身上不留任何
痕跡 —— 一艘挨了三枚魚雷的巡洋艦與一艘全新的長得一模一樣。

## 3. 失速滑行

### 3.1 規則

`alive === false` 的船**繼續前進**，速度以固定減速度歸零：

```
speed ← max(0, speed − COAST_DECEL · dt)
```

`COAST_DECEL = 0.3 m/s²`（**起始值，待試飛**）。艦隊航速 8 m/s ⇒ 約 27 秒
停下、滑行約 107 m。

【為什麼是固定減速度而不是指數衰減】指數衰減永遠到不了 0 —— 畫面上那是
一艘永遠在慢慢爬的船，而且 `speed === 0` 的捷徑永遠不成立。

【為什麼不做 v² 阻力】它的尾巴更長，而「還在動」與「停住了」之間的那段
沒有任何玩法內容。

### 3.2 `speed` 現在會變，所以重設要復原它

`Ship.speed` 原本的註解是「固定不變」，`resetShip` 因此沒有碰它。加一格
`readonly cruiseSpeed`（`createShip` 收到的那個值），`resetShip` 抄回去。

**少了這一條的症狀**：第二場的沉船從 0 起步 —— 而 `rematch` 那一組護欄
比的是耗時，抓不到。

## 4. 火災

### 4.1 資料

火點必須**跟著船走**，所以存的是**艦體座標**：

```ts
interface ShipFire {
  ship: number      // Ship.index
  x: number         // 艦體座標
  y: number
  z: number
  left: number      // 還要燒幾秒
  puff: number      // 距離下一次迷你爆炸還有幾秒
}
```

【為什麼不存世界座標】船在動。存世界座標的話火會留在原地，船從火裡開出去。

### 4.2 命中點怎麼來

`bombEvents` / `torpedoEvents` 的 `nz` 欄位**目前恆為 0**：

```
bombEvents     x, y, z, kind(0陸/1水/2船), damage, 0
torpedoEvents  x, y, z, kind(0岸/1船),     damage, 0
```

把 `nz` 改成**命中的船的索引，沒中船是 −1**。`World.bombShip` /
`torpedoShip` 已經在欄位裡拿著那一艘，只是沒推出去。

【為什麼不加第七個欄位】`IMPACT_STRIDE` 是 6，改它要動每一個消費端；而
`nz` 是一格現成的空位。

### 4.3 燃燒

```
FIRE_SECONDS     60     這個火點燒多久
FIRE_PUFF        0.3    迷你爆炸的間隔
```

每 `FIRE_PUFF` 秒往既有的爆炸池放一朵 `FIRE_BLAST`（新的一份 `BlastParams`，
`LAND_BLAST` 的縮小版：只有火與煙、沒有塵土水柱），同時往**船火專用的煙池**
放一團。

【為什麼煙要另一個池】通用的 `SMOKE_LIFE` 是 2.5 秒、上升 3 m/s ⇒ 柱高
7.5 m。那個高度在 1,000 m 的投彈高度上看不見，而「哪幾艘在燒」正是玩家要
從空中讀的東西。船火的煙要 **12 秒壽命、上升 8 m/s** ⇒ 柱高約 96 m。

【垂直向上，不吃初速】負責人明講「垂直向上的煙霧」。爆炸那一份的煙是
錐狀噴出去的，這一份不是。

### 4.4 沉了還燒不燒

**燒完既有的 60 秒，但不再開新的火點。** 一艘剛沉的船在海面上冒煙是對的；
而它已經 `alive === false`，不會再挨彈，所以「不開新的」是自動成立的。

### 4.5 容量

一艘船一次最多幾個火點？八艘船 × 每艘挨滿彈。取 **64**，滿了覆寫最舊的
（與 `Bombs` 的環狀池同一個做法）—— 火是純裝飾，掉一個沒有人看得出來。

## 5. 分層

火災**沒有任何模擬後果**：不扣血、不影響 AI、不進判定。所以：

- 火點的池與步進住在 `render/shipFires.ts`
- `World` 只負責把 `nz` 填成船的索引（那是它已經知道的事）
- `main.ts` 每幀把火點的艦體座標轉成世界座標，餵給既有的爆炸池與新的煙池

【為什麼不放進 `World`】放進去就要進逐位元重播的討論，而它連一個字節的
判定都不影響 —— 與 `sparks`／`smoke`「純裝飾，不參與判定也不需要決定性」
是同一條。

## 6. 護欄

| 測什麼 | 怎麼測 |
|---|---|
| 沉了會滑行不會煞停 | 沉沒後一步，`speed` 比 0 大且比原速小；位置有前進 |
| 會真的停下來 | 跑 60 秒後 `speed === 0` |
| 活著的船速度不變 | 跑 60 秒，`speed` 等於 `cruiseSpeed` |
| 重設復原航速 | 沉沒滑行到 0 之後 `resetShip`，`speed` 回到 `cruiseSpeed` |
| 命中事件帶得到船 | 炸彈打中船 ⇒ `nz === ship.index`；落水 ⇒ `nz === -1` |
| 火點跟著船走 | 船前進 100 m，火點的世界座標跟著移動 100 m |
| 燒 60 秒 | 59 秒時還在、61 秒時不在 |
| 迷你爆炸的節拍 | 3 秒燒出 10 朵（`3 / 0.3`） |
| 池滿了覆寫最舊的 | 塞 65 個，`live` 是 64 |

**變異測試**：把火點的座標改成世界座標（不跟船轉換）必須讓「跟著船走」紅；
把 `FIRE_PUFF` 的計時改成每幀一朵必須讓「節拍」紅。
