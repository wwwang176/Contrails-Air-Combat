# 上帝視角：離開座艙看戰場

## 1. 為什麼要有這一份

前三份把指揮 AI 從無到有做了出來，而驗收它的手段全部是**離線量測** ——
傷害數字、佔時比例、命令的發出與到達張數。實際看它打的唯一辦法是第一
人稱或跟拍鏡頭，而那個視角裡看得到的只有自己周圍那幾百公尺。

一支分隊的尺度約 1 km，兩隊質心的距離在開場是好幾公里。**指揮層做的事
沒有一件在座艙裡看得見。**

這一份加一個可以離開飛機的鏡頭，並在鏡頭離開的期間把自機交給 AI。

## 2. 玩家看到的東西

按 `G`：自機交給 AI 代飛，鏡頭跳到自機正上方 800 m、45° 俯角。滑鼠轉
鏡頭，`WASD` 在水平面上平移，`Q`/`E` 升降，`Shift` 加速。再按 `G` 回到
自己飛。

代飛期間**指揮 AI 管得到玩家那一支分隊**（第一份 spec §2.1 原本裁定
「指揮 AI 不用跟玩家這個小隊給指令」，那是為了不跟人類搶操縱；座位上
沒有人類時那個理由就不成立了）。

## 3. 兩個結構性的決定

### 3.1 鏡頭是純函數，不進 `CameraRig`

新檔 `src/camera/godCamera.ts`，只有狀態與更新規則，不認識 three 的
scene、不認識飛機、不認識 `CameraRig`。

理由由 `menuCamera.ts` 的既有註解寫好了：

> 【為什麼不用 `CameraRig`】那一整套是為了追一架飛機而存在的（彈簧、
> 自由視角、FOV 隨速度變化）。選單期間沒有飛機。

上帝視角也沒有。`CameraRig` 裡的每一樣東西 —— 彈簧阻尼、追逐偏移、隨
速度變化的 FOV、瞄準點 —— 在這個模式下都不適用，塞進去等於在一個已經
很微妙的類別裡加一個什麼都不共用的大分支。

抽成純函數的回報是**移動軸、夾擠、進場姿態全都是普通的單元測試**，與
`menuCameraPose` 同一個範式。

### 3.2 指揮權用推導的，不用鏡射的

`stepCommandLayer` 現在這樣算要跳過哪一支分隊：

```ts
const playerFlight = b.flights.pinned >= 0 ? b.flights.flightOf[b.flights.pinned]! : -1
```

改成「玩家座位上坐的**如果是 `AiController`，就沒有人要跳過**」：

```ts
const seat = b.world.combatants[b.flights.pinned]
const human = seat !== undefined && !(seat.controller instanceof AiController)
const playerFlight = human ? b.flights.flightOf[b.flights.pinned]! : -1
```

**零新欄位、零新參數、零新的同步責任。** 規則本身就是「座位上沒有人類，
就沒有人會跟指揮官搶操縱」。

`pinned < 0`（沒有玩家）時 `combatants[-1]` 是 `undefined` → `human` 為
false → `playerFlight` 為 −1，**與改之前逐字相同**。那條路徑不變。

這與 `wireStations` 靠 `instanceof AiController` 自動跟上、編制每步重算
而不是增量維護，是同一條紀律：**推導比鏡射安全，因為鏡射要求每一條會
改變狀態的路徑都記得更新，漏掉任何一條就留下一個永遠不消失的幽靈狀態**
（`setup.ts` 的既有註解）。

副作用是**既有的 `I`（代飛但鏡頭照舊跟拍）也一併拿到指揮**。那是刻意的：
下令權跟著代飛走，不跟著鏡頭走。代價要記著 —— `I` 的原始用途是
「讓同一顆 AI 同時開兩台，從外面看它到底怎麼打」，接上命令之後看到的
就不再是純粹的個體行為了。

### 3.3 為什麼指揮層的接線幾乎是免費的

`stepCommandLayer` 的每一處接線都用 `instanceof AiController` 判斷
（站位、命令投遞、`shotInstant` 抄寫），而 `main.ts` 代飛用的那顆正是
`AiController` —— 所以**那些接線現在就已經對它生效**，唯一擋著的是
`skipFlight`。這一份因此不需要碰 `src/ai/` 的任何一行。

## 4. 模式與按鍵

```
G          進出上帝視角（同時開／關代飛）
滑鼠       轉鏡頭（不用按鍵）
W / S      前 / 後（水平面上，不含俯仰）
A / D      左 / 右（水平面上）
Q / E      下降 / 上升（世界垂直）
Shift      加速
```

- 左鍵、右鍵在這個模式下**無作用**。開火由 AI 的開火紀律決定（`I` 的
  既有行為），自由視角是鏡頭之上的偏移、在這裡沒有意義。
- `V`（第一／三人稱）不生效但**保留設定值**，離開後照舊。
- `Tab` 記分板照常。
- `A`/`D`/`Q`/`E`/`Shift` 在飛行時**仍然沒有綁定**（滾轉靠滑鼠），所以
  這一份不搶任何既有按鍵。`W`/`S` 是唯一共用的，見 §7.3。

`InputState` 加兩個欄位：

```ts
/** 是否在上帝視角 */
godView: boolean
/** 上帝視角的移動輸入。`godView` 為 false 時全部為 false */
godMove: {
  forward: boolean   // W
  back: boolean      // S
  left: boolean      // A
  right: boolean     // D
  up: boolean        // E
  down: boolean      // Q
  boost: boolean     // Shift
}
```

滑鼠位移沿用既有的 `aimDeltaX` / `aimDeltaY`（欄位的語意本來就是
「本幀累積的滑鼠位移，單位螢幕半高」），上帝視角下由 `main.ts` 餵給
鏡頭而不是 `slewAimWorld`。**不新增第二組滑鼠累積欄位** —— 兩組累積器
只會製造「這一幀該清哪一個」的問題。

### 4.1 `G` 離開時 `playerAi` 一律設回 false

直接對應「取消上帝視角後就回到我自己飛」。

**副作用**：若進入前就開著 `I`，`G` 進出之後 `I` 也會被關掉。刻意不記憶
原本的值 —— 那是隱藏狀態，而這個副作用按一下 `I` 就回來了。

## 5. 鏡頭的狀態與規則

```ts
export interface GodCameraState {
  readonly position: Vector3
  /** 方位角，rad */
  yaw: number
  /** 俯仰角，rad。負值為俯視 */
  pitch: number
}
```

### 5.1 更新規則

- `yaw` / `pitch` 由滑鼠位移累積，**不反轉**：滑鼠右移 → 視線右轉，滑鼠
  上移 → 視線上抬。**`pitch` 夾在 ±`pitchLimit`** —— 不夾的話鏡頭會翻過
  天頂，而「上」的定義在那一瞬反過來。
- `yaw` **不夾也不取模**，可以無限累積。取模會在 ±π 的邊界上製造一個
  沒有必要的不連續，而三角函數本來就是週期的。
- `W`/`S` 沿 **`yaw` 決定的水平方向**，**完全不含 `pitch`**；`A`/`D` 沿
  其右側；`Q`/`E` 直接改 `y`。
- **對角線要正規化**。不正規化的話斜著走比直著走快 41% —— 那是一個會被
  當成「手感很怪」而查不出原因的 bug。
- `y` 夾在 `[minAltitude, maxAltitude]`。
- `Shift` 把水平與垂直速度**一起**乘上 `boostFactor`（只加速水平的話，
  加速中想爬升會變成幾乎水平的長弧）。

### 5.2 進場姿態

`position` = 自機位置 + `(0, entryHeight, 0)`，`yaw` = 自機當下航向，
`pitch` = −`entryPitch`。**每次進場都重新定位**，不記憶上次離開的位置 ——
按下去永遠知道自己在看哪裡，而玩家那一支分隊正好是新拿到命令的那一支。

### 5.3 參數起始值

| 參數 | 值 | 來歷 |
|---|---|---|
| `moveSpeed` | 300 m/s | 略高於巡航 TAS（200），追得上一團正在移動的纏鬥 |
| `boostFactor` | 4 | 1200 m/s，橫越幾公里的戰場約幾秒 |
| `minAltitude` | 50 m | 高於浪。撞地判定見 `aircraft/crash.ts` |
| `maxAltitude` | 12000 m | P-51D 的升限量級 |
| `pitchLimit` | 85° | 見 §5.1 |
| `entryHeight` | 800 m | 看得到一個分隊的散布（分隊尺度約 1 km） |
| `entryPitch` | 45° | 這個俯角下自機落在畫面中央 |
| `lookSensitivity` | 5.5 | 沿用 `bindings.ts` 的 `LOOK_SENSITIVITY`：自由視角要能一把甩過去，上帝視角同一個需求 |

**全部是起始值，待手動試飛回填。** 這一份沒有可以自動掃描的判準
（見 §8.3）。

## 6. HUD

`HudFrame` 加 `godView: boolean`。為真時 `Hud.render` 只畫三個 widget：

- `drawMinimap` —— **以鏡頭為中心**
- `drawRoster` —— 名冊與戰績
- `drawHints` —— 按鍵提示

其餘（姿態儀、速度高度帶、準星、過載黑視、受擊邊框、儀表、血條、能量、
接觸點）全部不畫。它們是座艙儀表，鏡頭都不在飛機上了，留著只是雜訊 ——
**準星更是直接誤導**，它會讓人以為那個方向會有子彈出去。

小地圖不必改任何一行：它吃的是 `worldX` / `worldZ` / `heading`，上帝視角
下由 `main.ts` 填鏡頭的 x / z / yaw。

## 7. 邊界情況

### 7.1 陣亡

**不受影響。** 鏡頭繼續自由飛，跳過死亡鏡頭；既有的接手機制照跑（兩秒
後接手一架僚機），玩家切回來時已經在新機上。

理由：上帝視角的意思就是「我現在不附身在任何一架飛機上」，被死亡鏡頭
打斷與這件事矛盾。

`main.ts` 既有的 `dying` 分支（陣亡等待接手期間不換控制器）不必動。

### 7.2 進出時要清乾淨的東西

| 時機 | 動作 | 為什麼 |
|---|---|---|
| 進入 | 清掉所有按鍵 hold | 與 `bindings.ts` 已記載的「切出視窗扳機卡住」同一類 bug |
| 進入 | `camera.fov` = `fovBase` | 隨速度變化的 FOV 在這裡沒有意義 |
| 離開 | 清掉所有按鍵 hold | 同上，反方向 |
| 離開 | `rig.snapTo()` | 否則相機會從上帝位置一路彈簧飛回來 |
| 離開 | 瞄準點回機首 | `main.ts` 交還操縱時既有的動作，會自動發生（`playerAi` 轉 false 走的就是那一支） |

### 7.3 上帝視角期間不套用油門變化率

`W`/`S` 是唯一與飛行共用的按鍵。`attachInput` 的 `tick()` 每幀呼叫
`applyThrottleRate`，若照跑，你切回來時油門已經飄到 0 或 1.1 了。

### 7.4 地形的跟隨點

`terrain.update(elapsed, x, z)` 現在餵的是玩家的算繪位置，上帝視角下要
改餵鏡頭位置 —— 否則鏡頭飛遠了，海面網格還留在飛機那裡。

**這不影響物理**：`heightAt(x, z, time)` 只吃世界座標與時間，與 `update`
的中心點無關。§8.3 的護欄靠這件事成立。

### 7.5 重開一場

走選單的 `onRestart` → `restartBattle()`（**沒有 `R` 鍵**；`KeyR` 只存在
於 `src/tools/range.ts` 那個開發工具）。上帝視角要在 `restartBattle()`
裡退出並清狀態。

> 順帶：`setup.ts` 的 `playerSeat` 註解寫著「R 重開時要還原回這裡」，
> 那句話是過期的。這一份會順手改掉 —— 就在同一個檔案裡。

## 8. 驗收

### 8.1 單元：`test/unit/god-camera.test.ts`

1. 水平移動**完全不受 `pitch` 影響**（同一個 `yaw`、俯角 0° 與 −80°，
   按 `W` 一秒的位移逐位元相同）
2. 對角線不加速（`W`+`D` 一秒的位移長度等於 `W` 一秒）
3. `Q` / `E` 只改 `y`，不動 x / z
4. `y` 夾在 `[minAltitude, maxAltitude]`
5. `pitch` 夾在 ±`pitchLimit`
6. `Shift` 讓水平**與**垂直速度都乘上 `boostFactor`
7. 進場姿態：位置在自機正上方 `entryHeight`、`yaw` 等於自機航向、
   `pitch` 等於 −`entryPitch`
8. 決定性：同一個輸入跑兩次，逐位元相同
9. 沒有輸入時完全不動（沒有慣性、沒有漂移）

### 8.2 單元：`test/unit/bindings.test.ts` 追加

10. `G` 切換 `godView`
11. 上帝視角下按 `W`/`S` **不動 `throttle`、不設 `braking`**
12. 進入與離開都把所有 hold 清掉
13. 上帝視角下 `W`/`A`/`S`/`D`/`Q`/`E`/`Shift` 寫進 `godMove`

### 8.3 護欄：鏡頭不得改變戰局

> 「代飛 + 上帝視角」跑一場，與「代飛 + 跟拍」跑一場，**傷害逐位元相同**。

對照挑代飛對代飛，因為代飛本身會改戰局（那是它該做的），而鏡頭不該。

實作成整合測試時，「上帝視角」由**每個物理步都推進一次
`stepGodCamera`（帶著非零的移動輸入）**來模擬，不需要瀏覽器。

**這條護欄實際在守什麼，要說清楚。** 它看起來近乎恆真 —— `godCamera.ts`
不 import `src/battle/`，怎麼可能改到戰局？但這個專案裡有一個真的會踩到
的機制：**模組層級的共用暫存池**（`core/pool.ts` 的 `makeScratch`，
`src/ai/` 與 `CameraRig` 都在用）。鏡頭若借用了別人的池子，就會在別人
用到一半時把內容改掉，而症狀是「戰局悄悄變了」而不是任何錯誤。

它**守不到**的是 `main.ts` 的算繪路徑（`terrain.update` 的中心點接錯之
類），那一段沒有無頭測試 —— 由 §8.6 的 Playwright 人工驗收補。

### 8.4 整合：指揮權

14. 玩家座位坐 `AiController` 時，玩家那一支分隊**拿得到**命令
15. 坐人類控制器時**永遠拿不到**（整場跑完 `orders[playerFlight]` 恆為
    `null`）

### 8.5 否決條件

- 上帝視角的更新在有輸入時配置記憶體（它每幀跑，與 `src/ai/` 的熱路徑
  同一條紀律）
- `src/camera/godCamera.ts` import `src/battle/`、`src/render/` 或
  `src/hud/`
- 8.3 那條護欄紅掉

### 8.6 Playwright 驗收（無頭測試守不到的那一半）

`main.ts` 的算繪路徑沒有單元測試，所以用 Playwright 開真的遊戲、真的按
鍵、真的截圖。腳本放 `test/e2e/god-view.spec.ts`（**新目錄**，不進
`vitest` 的 `test/` 掃描範圍，見計畫）。

要驗的：

16. 按 `G` 之後畫面確實變了（截圖與按之前不同），而且 HUD 的準星消失
17. `WASD` 之後畫面再次改變（鏡頭真的動了）
18. 鏡頭飛遠之後**海面仍然鋪滿畫面**（`terrain.update` 的中心點沒接錯 ——
    §8.3 守不到的正是這一條）
19. 再按 `G` 回到跟拍，準星回來
20. 全程 console 沒有錯誤

截圖存 `.shots/`，與既有的手動驗收截圖同一個位置。

### 8.7 手動試飛（沒有自動判準的部分）

§5.3 的八個參數只能試飛。要看的是：追得上一團正在移動的纏鬥嗎；`Shift`
橫越戰場要幾秒；800 m / 45° 進場時看得到整支分隊嗎；貼著海面時
`minAltitude` 夠不夠。

## 9. 這一份不做的事

- **不做「鎖定某一架跟拍」。** 上帝視角是自由鏡頭，追誰由玩家自己開過去。
  鎖定跟拍是另一個功能（而且它會需要一整套目標選擇的 UI）。
- **不記憶離開時的鏡頭位置**（§5.2）。
- **不做上帝視角下的指令介面。** 玩家在這個模式下是觀察者，不是指揮官 ——
  「玩家自己下令給分隊」是一個獨立的、大得多的題目。
- **不碰 `src/ai/`。** 指揮層一行都不改（§3.3）。
- **不碰 `CameraRig`**（§3.1）。
- **不改開火、接手、重生的任何行為。**
