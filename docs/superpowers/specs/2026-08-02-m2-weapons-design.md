# M2：武器、彈道與命中判定 —— 設計文件

日期：2026-08-02
前置里程碑：M0 + M1（`2026-07-31-m0-m1-flight-model-design.md`）

---

## 1. 概述

M1 交付了一架可駕駛、性能對得上史料的飛機。M2 讓它**打得到東西**：機槍機砲、彈道、命中判定、部位化損傷，以及一個不反擊的靶機。

M2 同時付一筆重構：把 `main.ts` 的「世界上只有一架飛機」假設拆掉，改成「世界裡有 N 架」。M4 的 AI 與 M5 的 40 架都從這個結構長出來，晚做只會更貴。

**不含**：敵機 AI（M4）、選單與任務模式、音效、性能減損型損傷、地形。

---

## 2. 已定案的裁決

以下四項是專案負責人在設計討論中直接裁決的，**不是待辦、不是簡化的權宜之計**。日後看到它們與「史實優先」的專案基調衝突時，請先讀理由再動。

| 裁決 | 內容 | 理由 |
|---|---|---|
| **彈道無衰減、無重力** | 初速與射速照史實，但彈丸等速直線飛行 | 街機感。**飛行時間仍然保留**，所以提前量、相對運動、能量幾何這些設計重點全部成立；被拿掉的只有「下墜補償」這一層操作負擔 |
| **彈藥無限** | 不計彈藥數量，不做彈藥 HUD | 見 §6.3 的平衡後果 |
| **不做性能減損** | 中彈只扣血，不影響滾轉率、推力、操縱權限 | §17 已定（M1 spec）。資料結構預留 `effects` 欄位供未來啟用 |
| **P-51 翼槍匯聚 300 m** | 固定值，不提供玩家調整 | §17 已定（M1 spec） |

## 4. 架構

### 4.1 新增模組

```
src/world/
  World.ts        Aircraft[] + 彈丸池 + 每步推進 + 命中判定的呼叫點
  Projectiles.ts  彈丸池（純資料）、推進、失效回收
  hit.ts          線段 vs AABB、部位判定            ← 純函數
  lead.ts         預瞄解                            ← 純函數
src/weapons/
  types.ts        WeaponSpec / Battery
  p51d.ts         6× M2 .50 cal
  bf109g6.ts      1× MG 151/20 + 2× MG 131
src/control/
  PlayerController.ts    滑鼠 → aimWorld + throttle + 扳機
  ScriptedController.ts  預錄機動 → 同一組輸出
```

命中盒（`HitBox`）不放在 `weapons/`——它描述的是**機體**不是武器。型別放 `src/world/hit.ts`（消費它的模組），各機種的盒子清單與 HP 一起放 `src/specs/`，與 `AircraftSpec` 同一份資料。

`src/aircraft/Aircraft.ts` **不改介面**。它已經是 `update(aimWorld, throttle, dt)`，靶機只是 `aimWorld` 的來源不同。多機重構的重量全在 `main.ts` 與渲染／HUD 層。

### 4.2 每步的順序

```
1. 各控制器產生指令（aimWorld、throttle、扳機）
2. 全部 Aircraft 推進
3. 彈丸推進
4. 命中判定
```

彈丸在飛機**之後**推進，所以判定用的是這一步的新位置。順序顛倒會讓彈丸打到上一步的殘影，在高速接近時是可觀察的誤差。

### 4.3 純函數邊界

`lead.ts` 與 `hit.ts` 不持有狀態、不碰 three.js 場景圖，與 M1 的 `physics/`、`analysis/` 同一條紀律。理由有三：可在 node 裡直接測；M4 的 AI 瞄準要重複使用同一個 `lead.ts`；L4 矩陣需要在沒有瀏覽器的情況下跑幾百個案例。

## 5. 彈道

### 5.1 模型

```
V_bullet = 槍口方向 × 初速 + 射手速度
位置 += V_bullet · dt          （無阻力、無重力）
飛行距離超過**有效射程 800 m** 即回收
```

800 m 同時是三件事的門檻：彈丸回收距離、預瞄環顯示的距離上限、目標框顯示的距離上限。用同一個數字，玩家看到預瞄環就代表打得到。

**彈丸繼承射手速度**是零成本的真實性，也是偏射困難的來源：側向速度會讓彈道偏離槍軸。無阻力時這件事是精確的，不需要近似。

### 5.2 預瞄解

在**射手座標系**求解。設相對位置 `P = 目標位置 − 射手位置`、相對速度 `V = 目標速度 − 射手速度`、初速 `s`：

```
|P + V·t| = s·t
(V·V − s²)·t² + 2(P·V)·t + P·P = 0
```

記 `a = V·V − s²`、`b = 2(P·V)`、`c = P·P`（`c > 0` 恆成立，除非目標與射手重疊）。取**最小正根**，預瞄方向 = `normalize(P + V·t)`。閉式解，不迭代。

分支必須逐一寫對——「目標比彈快就無解」是**錯的**，迎頭接近時仍然有解：

| 情形 | 處理 |
|---|---|
| `a < 0`（彈比目標快） | **恆有唯一正根**，取它 |
| `a > 0` 且 `b ≥ 0`（目標比彈快**且在遠離**） | 無解，預瞄環不顯示 |
| `a > 0`、`b < 0`、判別式 < 0 | 無解 |
| `a > 0`、`b < 0`、判別式 ≥ 0 | 兩根皆正，取小的 |
| `\|a\| < ε`（退化成一次式） | `t = −c/b`，且僅在 `b < 0` 時有效。不可直接除以 `a` |

L1 測試必須逐格覆蓋這五種——這是整個 M2 最容易寫錯又最不容易被發現的地方。

### 5.3 武器資料

| | P-51D | Bf 109 G-6 |
|---|---|---|
| 武裝 | 6× M2 Browning .50 cal（翼） | 1× MG 151/20（軸心，穿槳轂）+ 2× MG 131（機首） |
| 初速 | 887 m/s | 705 m/s（20 mm）／750 m/s（13 mm） |
| 射速 | 800 rpm ×6 | 700 rpm ×1 ／ 900 rpm ×2 |
| 匯聚 | **300 m** 固定 | 軸心武裝，**無匯聚問題** |

109 的武裝在中軸線上，任何距離都不必修正匯聚。這個史實優勢從資料自然落出來，不需要另外設計。P-51 則是「300 m 附近最密、太近太遠都散」——這是它要學的東西。

槍口位置取自 M1 量出來的機翼與機首資料（見 §7.1 的同一條原則）。

## 6. 命中與損傷

### 6.1 命中判定

彈丸每步走一段線段。判定是**線段 vs 六個 AABB，取最近命中**。

AABB 定義在**機體座標**，判定前把線段轉進機體座標——等價於世界座標的 OBB，飛機滾轉不失真。機翼是薄板，用盒子貼合遠好於球體。

### 6.2 部位與倍率

| 部位 | 倍率 |
|---|---|
| 座艙 | ×2.5 |
| 引擎 | ×2.0 |
| 尾翼 | ×1.2 |
| 機身 | ×1.0 |
| 左翼 | ×0.7 |
| 右翼 | ×0.7 |

### 6.3 損傷數值與平衡

HP 進 `AircraftSpec`，戰鬥機 **1000**。

| | 單發傷害 | DPS | TTK（全中機身） |
|---|---|---|---|
| .50 BMG ×6 | 6 | 480 | 2.1 s |
| MG 151/20 | 28 | 327 | — |
| MG 131 ×2 | 10 | 300 | — |
| **Bf 109 合計** | | **627** | **1.6 s** |

**彈藥無限的平衡後果（已知且接受）**：原本的三角是「109 打得快但機砲 13 秒見底」。拿掉彈藥限制後，109 在 DPS 與命中精度（中軸線）上**兩項全贏**。

這在史實上站得住：109 G-6 的單位時間殺傷力確實更高；P-51 的優勢在速度、高空、滾轉率、航程——**那些 M1 已經做進飛行模型並由 L3 的 17 條斷言守著**。整體平衡靠飛行模型撐，火力這一塊就是 109 佔優。

L3 要守的是**相對關係**，不是絕對值（數值可調）：

1. MG 151/20 的單發傷害顯著高於 .50 BMG
2. Bf 109 的總 DPS 高於 P-51
3. P-51 的彈著散佈在 300 m 處最密，太近與太遠都變差

## 7. 命中盒的來源

### 7.1 原則

命中盒的數字**取自 M1 量出來的機身資料**，不是手打的：座艙盒用 `CANOPY` 的站位、翼盒用 `WING` 的弦長與翼展、機首盒用首環。

### 7.2 一致性測試

一條跨模組測試斷言：**每個命中盒必須包住對應 mesh 的全部頂點**。

這是 M1 那條「四分之一弦線必須壓在原點」測試的同一個模式——外型改了而命中盒沒跟上，測試會紅。沒有這條，兩份資料會靜靜地分岔，而且只會在玩家抱怨「明明打中了卻沒扣血」時才被發現。

## 8. HUD 增補

沿用 M1 的 Canvas 2D overlay 與 `widgets/` 結構。

| 元件 | 說明 |
|---|---|
| 預瞄環 | 射程內目標，畫在預瞄方向的投影處。無解時不顯示（§5.2） |
| 命中回饋 | 命中時機首十字周圍出現 `X` |
| 目標框 | 敵紅我藍，隨距離縮放 |
| 畫面外指示 | 螢幕邊緣的相對方位箭頭 |
| 小地圖符號 | **高於我 = 三角、同層 = 方、低於我 = 倒三角**；敵紅我藍 |
| 目標 HP | 當前目標的血量 |

**當前目標**：離機首方向**角度最小**且在 800 m 內的敵機。M2 只有一架靶機，但規則要先寫下來，M4 有多架時才不會臨時發明。

**開火鍵**：滑鼠左鍵。左鍵目前的用途是取得指標鎖——已鎖定時左鍵即為開火，未鎖定時左鍵請求鎖定（`bindings.ts` 已有 `document.pointerLockElement` 判斷，沿用即可）。

命中 `X` 標記顯示 **0.15 s**，期間再命中則重新計時。

不做彈藥餘量（§2 裁決）。

## 9. 測試策略

沿用 M1 的分層。

### 9.1 L1 純函數

`lead.ts` 的解與四種退化情形、`hit.ts` 的線段 vs AABB（含正好擦邊、線段完全在盒內、線段起點在盒內）、彈丸推進與回收。

### 9.2 L2 史實值

各武器的初速與射速對得上史料。與 M1 的 `specs.test.ts` 同一個模式：資料表本身就是被測物。

### 9.3 L3 平衡

§6.3 的三條相對斷言，加上 300 m 匯聚點的幾何驗證。

### 9.4 L4 命中矩陣

**M2 的重頭戲**，對應 M1 的指揮儀 120 案例矩陣。

```
距離     {100, 300, 500, 750} m      ← 全部在 800 m 有效射程內
相對角度 {尾追, 側方 45°, 正交 90°, 迎頭}
目標速度 {150, 250} m/s
目標機動 {等速直線, 定盤旋}
```

每個組合：把射手機首對準預瞄環開火，**必須命中**。

這一條的價值在於它把預瞄解、彈丸推進、命中判定三個模組**綁在一起**驗證。任何一個算錯——預瞄公式、彈丸繼承速度、機體座標轉換——都會在這裡露出來，而且看得出是哪一類組合失敗。

### 9.5 幾何一致性

§7.2。

## 10. 效能

| 項目 | 目標 |
|---|---|
| 彈丸池容量 | 4,000 發（按 **M5 的 40 架**抓，不是 M2 的 2 架） |
| 滿載時 | 60 FPS |
| 曳光彈 draw call | **1**（單一 `LineSegments`，逐幀更新頂點） |
| 熱路徑配置 | 零（沿用 M1 §15 紀律與 `makeScratch` 模式） |

**池滿時覆寫最舊的彈丸**，不是拒絕發射。射擊永遠有反應，比「扣了扳機沒動靜」好——後者玩家會當成 bug。

## 11. 靶機

同一個 `Aircraft` 類別配 `ScriptedController`，按鍵切換機動：

| 機動 | 驗證什麼 |
|---|---|
| 等速直線 | 預瞄解的基本正確性 |
| 定盤旋 | 持續提前量 |
| 蛇行 | 預瞄環會不會抖動 |
| 爬升 | 垂直分量 |

靶機不開火、不迴避。它的存在是為了驗證 M2，不是為了對戰——那是 M4 的事。

## 12. 風險

| 風險 | 對策 |
|---|---|
| 多機重構動到 M1 已驗證的路徑 | `Aircraft` 介面不動；重構只在 `main.ts` 與渲染層。M1 的 542 條測試全程必須維持全綠 |
| 預瞄環在退化情形跳動或消失得突兀 | §5.2 逐一列出四種退化並明確處理；L1 對每一種都有測試 |
| 命中盒與外型分岔 | §7.2 的一致性測試 |
| 40 架時彈丸成為熱點 | 池容量按 M5 抓，M2 就用滿載跑效能驗收，不等到 M5 才發現 |
| 彈藥無限使 109 火力全面壓過 P-51 | 已知且接受（§6.3）。整體平衡由飛行模型承擔，L3 守相對關係 |
