# M2：武器、彈道與命中判定 —— 設計文件

日期：2026-08-02
前置里程碑：M0 + M1（`2026-07-31-m0-m1-flight-model-design.md`）

---

## 1. 概述

M1 交付了一架可駕駛、性能對得上史料的飛機。M2 讓它**打得到東西**：機槍機砲、彈道、命中判定、部位化損傷，以及一個不反擊的靶機。

M2 同時付一筆重構：把 `main.ts` 的「世界上只有一架飛機」假設拆掉，改成「世界裡有 N 架」。M4 的 AI 與 M5 的 40 架都從這個結構長出來，晚做只會更貴。

**不含**：敵機 AI（M4）、選單與任務模式、音效、性能減損型損傷、地形。

## 2. 已定案的裁決

以下四項是專案負責人在設計討論中直接裁決的，**不是待辦、不是簡化的權宜之計**。日後看到它們與「史實優先」的專案基調衝突時，請先讀理由再動。

| 裁決 | 內容 | 理由 |
|---|---|---|
| **彈道無衰減、無重力** | 初速與射速照史實，但彈丸等速直線飛行 | 街機感。**飛行時間仍然保留**，所以提前量、相對運動、能量幾何這些設計重點全部成立；被拿掉的只有「下墜補償」這一層操作負擔 |
| **彈藥無限** | 不計彈藥數量，不做彈藥 HUD | 見 §6.3 的平衡後果 |
| **不做性能減損** | 中彈只扣血，不影響滾轉率、推力、操縱權限 | §17 已定（M1 spec）。資料結構預留 `effects` 欄位供未來啟用 |
| **P-51 翼槍匯聚 300 m** | 固定值，不提供玩家調整 | §17 已定（M1 spec） |

## 4. 架構

### 4.1 新增模組

```
src/world/
  World.ts        Aircraft[] + 彈丸池 + 每步推進 + 命中判定的呼叫點
  Projectiles.ts  彈丸池（純資料）、推進、失效回收
  hit.ts          線段 vs AABB、部位判定            ← 純函數
  lead.ts         預瞄解                            ← 純函數
src/weapons/
  types.ts        WeaponSpec / Battery
  p51d.ts         6× M2 .50 cal
  bf109g6.ts      1× MG 151/20 + 2× MG 131
src/control/
  PlayerController.ts    滑鼠 → aimWorld + throttle + 扳機
  ScriptedController.ts  預錄機動 → 同一組輸出
```

命中盒（`HitBox`）不放在 `weapons/`——它描述的是**機體**不是武器。型別放 `src/world/hit.ts`（消費它的模組），各機種的盒子清單與 HP 一起放 `src/specs/`，與 `AircraftSpec` 同一份資料。

`src/aircraft/Aircraft.ts` **不改介面**。它已經是 `update(aimWorld, throttle, dt)`，靶機只是 `aimWorld` 的來源不同。多機重構的重量全在 `main.ts` 與渲染／HUD 層。

### 4.2 每步的順序

```
1. 各控制器產生指令（aimWorld、throttle、扳機）
2. 全部 Aircraft 推進
3. 彈丸推進
4. 命中判定
```

彈丸在飛機**之後**推進，所以判定用的是這一步的新位置。順序顛倒會讓彈丸打到上一步的殘影，在高速接近時是可觀察的誤差。

### 4.3 純函數邊界

`lead.ts` 與 `hit.ts` 不持有狀態、不碰 three.js 場景圖，與 M1 的 `physics/`、`analysis/` 同一條紀律。理由有三：可在 node 裡直接測；M4 的 AI 瞄準要重複使用同一個 `lead.ts`；L4 矩陣需要在沒有瀏覽器的情況下跑幾百個案例。

## 5. 彈道

### 5.1 模型

```
V_bullet = 槍口方向 × 初速 + 射手速度
位置 += V_bullet · dt          （無阻力、無重力）
飛行時間超過**壽命 1.2 s** 即回收
```

### 5.1.1 為什麼上限是「壽命」而不是「射程」

彈丸繼承射手速度之後，**能不能打到取決於攔截點，不是目標當下的距離**：

- **尾追**時目標在跑，攔截點比現在遠 → 目標在 700 m 卻打不到
- **迎頭**時目標在衝過來，攔截點比現在近 → 目標在 900 m 反而打得到
  （雙方各 200 m/s 迎頭、目標 900 m：`t = 0.70 s`，彈丸在射手座標系只飛了 621 m）

用「距離上限」在兩端都會判錯。改用飛行時間之後，§5.2 解出來的 `t` 直接就是判準：`t ≤ lifetime`，一個減法，不必另外算距離。回收條件與預瞄環判準用**同一個數字**，兩邊不可能互相矛盾——「看得到預瞄環」就精確等於「打得到」。

各武器的相對射程於是由初速自然分開：

| | 初速 | 1.2 s 的相對射程 |
|---|---|---|
| .50 BMG | 887 m/s | **1064 m** |
| MG 131 | 750 m/s | 900 m |
| MG 151/20 | 705 m/s | **846 m** |

P-51 的 .50 比 109 的機砲打得遠，是初速差直接落出來的，不用另外設計。

**1.2 s 是初版值。** 二戰實戰的有效空戰射程通常在 400 m 以內，1.2 s 給到 850~1060 m 相當寬鬆，符合街機取向。專案負責人裁決先用這個數字，之後依手感調整。

**彈丸繼承射手速度**是零成本的真實性，也是偏射困難的來源：側向速度會讓彈道偏離槍軸。無阻力時這件事是精確的，不需要近似。

### 5.2 預瞄解

在**射手座標系**求解。設相對位置 `P = 目標位置 − 射手位置`、相對速度 `V = 目標速度 − 射手速度`、初速 `s`：

```
|P + V·t| = s·t
(V·V − s²)·t² + 2(P·V)·t + P·P = 0
```

記 `a = V·V − s²`、`b = 2(P·V)`、`c = P·P`（`c > 0` 恆成立，除非目標與射手重疊）。取**最小正根**，預瞄方向 = `normalize(P + V·t)`。閉式解，不迭代。

分支必須逐一寫對——「目標比彈快就無解」是**錯的**，迎頭接近時仍然有解：

| 情形 | 處理 |
|---|---|
| `a < 0`（彈比目標快） | **恆有唯一正根**，取它 |
| `a > 0` 且 `b ≥ 0`（目標比彈快**且在遠離**） | 無解，預瞄環不顯示 |
| `a > 0`、`b < 0`、判別式 < 0 | 無解 |
| `a > 0`、`b < 0`、判別式 ≥ 0 | 兩根皆正，取小的 |
| `\|a\| < ε`（退化成一次式） | `t = −c/b`，且僅在 `b < 0` 時有效。不可直接除以 `a` |

L1 測試必須逐格覆蓋這五種——這是整個 M2 最容易寫錯又最不容易被發現的地方。

### 5.3 武器資料

| | P-51D | Bf 109 G-6 |
|---|---|---|
| 武裝 | 6× M2 Browning .50 cal（翼） | 1× MG 151/20（軸心，穿槳轂）+ 2× MG 131（機首） |
| 初速 | 887 m/s | 705 m/s（20 mm）／750 m/s（13 mm） |
| 射速 | 800 rpm ×6 | 700 rpm ×1 ／ 900 rpm ×2 |
| 匯聚 | **300 m** 固定（僅橫向，見 §5.3.1） | 軸心武裝，**無匯聚問題** |

109 的武裝在中軸線上，任何距離都不必修正匯聚。這個史實優勢從資料自然落出來，不需要另外設計。P-51 則是「300 m 附近最密、太近太遠都散」——這是它要學的東西。

> **後續變更（M10 驗收）**：P-51 的匯聚點由 300 m 改為 **1,000 m**，109 維持 300 m。本節其餘內容（僅橫向匯聚、109 無匯聚問題）不變。理由與量測見 `2026-08-04-m10-main-menu-design.md` §16.8。

槍口位置取自 M1 量出來的機翼與機首資料（見 §7.1 的同一條原則）。

### 5.3.1 為什麼匯聚只做橫向

**實作偏離本節字面規定，理由如下。**

沒有重力，所以縱向也匯聚的話彈道會在匯聚點之後**爬到瞄準線上方**：翼槍槍口在 y = −0.5，飛到 980 m 時已高出瞄準線 1.13 m，而機身命中盒頂只到 y = 0.80。實測 750 m 尾追、目標 250 m/s 的組合，三軸匯聚時整串子彈從目標上方飛過去，**命中 0 發**；改為僅橫向匯聚後命中 180 發。

真機的射擊校正本來就是「橫向匯聚、縱向設定重力下墜補償」。本模型沒有重力，正確的縱向設定就是平行。

實作：`mountDirection` 的方向為 `normalize(−p.x, 0, −convergence − p.z)`，y 分量恆為 0。

## 6. 命中與損傷

### 6.1 命中判定

彈丸每步走一段線段。判定是**線段 vs 六個 AABB，取最近命中**。

AABB 定義在**機體座標**，判定前把線段轉進機體座標——等價於世界座標的 OBB，飛機滾轉不失真。機翼是薄板，用盒子貼合遠好於球體。

**倍率取「命中的盒中最高的」，`t` 才取最近。**（實作偏離「取最近命中」的字面規定。）命中盒是巢狀的——座艙盒整個包在機身盒裡面，從正面來的彈丸一定先進機身盒再進座艙盒。倍率若也取最近的那一個，座艙的 ×2.5 **永遠選不到，整條是死碼**（與 M1 那次「黑視起點等於過載限制器上限、`overG` 恆為 0」是同一類缺陷）。`t` 決定「打到哪一架、打在哪裡」，仍取最近。

**粗篩**：判定前先比對線段到機體重心的距離與命中盒的包圍球半徑。實測滿載 4,000 發時它擋掉 99.89% 的（彈丸, 飛機）配對，`World.step` 由 1,895 µs 降到 175 µs。半徑必須是嚴格上界，否則會靜靜漏掉命中。

#### 6.3.1 ×3 的實測後果（2026-08-09）

全套跑完，**新增五條紅**。前兩條的成因是機械的、已就地處置；後三條是 20v20 的
行為改變，**留紅等專案負責人裁定**（護欄重新定值不是實作者的決定）。

**已處置 —— 尺的單位被換掉，不是行為退化**

| 護欄 | 基線 | ×3 之後 | 處置 |
|---|---|---|---|
| `weapons.test.ts` DPS 表 | 480 / 626.67 | 1440 / 1880 | 釘住的值換新，精度未放寬 |
| `hitbox.test.ts` TTK 表 | 2.08 / 1.60 s | 0.694 / 0.532 s | 同上，精度由 1 位收到 2 位 |
| `ai-defence.test.ts` `blueDamage` | 40.2 / 68.4 / 0 / 108.0 | 120.6 / 205.2 / 0 / 324.0 | 門檻改寫成 DPS 的秒數 |

`ai-defence` 那一組是**精確的三倍**，而且四種幾何的 `defendShare`、反應秒數、
`huntedShare` 逐位元相同 —— 1 藍 2 紅、30 s，沒有人死，行為一格未變。門檻因此
由寫死的 150 HP 改成 `0.3125 s × 紅方 DPS`（舊值 0.3125×480 = 150，新值
0.3125×1440 = 450，嚴格度不變），從此與傷害數值脫鉤。以 100/480 突變驗證過
它仍然是承重的。

**待裁定 —— 20v20 的行為真的變了**

| 護欄 | 基線 | ×3 之後 |
|---|---|---|
| `ai-command-channel` 命令期間編隊收攏 | 875.8 → 705.4 m（收攏 19.5%） | 670.0 → 677.1 m（**鬆 1.1%**），n = 2 |
| `ai-command-tactics` 集火讓被指名那一架掉血更快 | 通過（需 > ×1.5） | focused 2.4975 vs others 2.3571，**比值 1.060** |
| `ai-withdraw-anchor` `leavingShare` 落在 5%~25% | 7.20% | **4.31%** |

三條的共同上游是**致命度上升**：`ai-withdraw-anchor` 同一場的存活由 16v17 變成
15v9、紅方吃的傷害由 4,618 變成 12,163，rally 命令由 6 張掉到 2 張、同時最多
並行 3 張掉到 1 張。仗打得更短、死得更快，於是「有多少比例的時間在離場」與
「集火相對於自由開火的優勢」這兩把尺量到的東西都變小了。編隊收攏那條的 n 只有
2，本來就是小樣本。

**這三條要問的是同一個問題**：在新的致命度下，5% 的下界、×1.5 的集火倍率、
以及「平均誤差必須收攏」這三個判準，還是不是原本想守的東西？重新定值、改寫成
別的量、或判定為真的退化，都要專案負責人決定。

**彈藥無限的平衡後果（已知且接受）**：原本的三角是「109 打得快但機砲 13 秒見底」。拿掉彈藥限制後，109 在 DPS 與命中精度（中軸線）上**兩項全贏**。

這在史實上站得住：109 G-6 的單位時間殺傷力確實更高；P-51 的優勢在速度、高空、滾轉率、航程——**那些 M1 已經做進飛行模型並由 L3 的 17 條斷言守著**。整體平衡靠飛行模型撐，火力這一塊就是 109 佔優。

L3 要守的是**相對關係**，不是絕對值（數值可調）：

1. MG 151/20 的單發傷害顯著高於 .50 BMG
2. Bf 109 的總 DPS 高於 P-51
3. P-51 的彈著散佈在 300 m 處最密，太近與太遠都變差

## 7. 命中盒的來源

### 7.1 原則

命中盒的數字**取自 M1 量出來的機身資料**，不是手打的：座艙盒用 `CANOPY` 的站位、翼盒用 `WING` 的弦長與翼展、機首盒用首環。

### 7.2 一致性測試

這是 M1 那條「四分之一弦線必須壓在原點」測試的同一個模式——外型改了而命中盒沒跟上，測試會紅。沒有這條，兩份資料會靜靜地分岔，而且只會在玩家抱怨「明明打中了卻沒扣血」時才被發現。

**判準是「聯集覆蓋」而不是「每個盒包住對應 mesh」。**（本節已依實作修訂。）機身是**一個** mesh，從機首一路到機尾——座艙、引擎、尾翼都是它的一段，沒有「對應的 mesh」可以逐一比對。改成三條合起來等價、而且不會循環論證的斷言：

1. 每個頂點都落在至少一個盒內（不能有打不到的地方）
2. 每個盒都至少含一個頂點（不能有空盒）
3. 六個盒的體積總和 < 整機包圍盒體積（不能拿六個巨盒交差）

螺旋槳排除在外（`userData.spinning`）：槳葉與模糊圓盤掃出的是一個半徑 1.7 m 的圓面，把它包起來要一個 3.4 × 3.4 m 的盒子擋在機首前方——那不是命中面，是動畫。

另有兩條同類的跨模組斷言：每個槍口都落在自己的命中盒內；槍口射線走 12 m 不會進入自己的機身／座艙／尾翼盒。

實測：P-51 六盒體積合計 58.2 m³（整機包圍盒 331.4 m³ 的 18%）、Bf 109 為 35.4 / 166.1 m³（21%），兩台皆 0 個未覆蓋頂點。

## 8. HUD 增補

沿用 M1 的 Canvas 2D overlay 與 `widgets/` 結構。

| 元件 | 說明 |
|---|---|
| 預瞄環 | **每架敵機各一個**。顯示條件：§5.2 有解**且** `t ≤ 彈丸壽命`——也就是「真的打得到」（見 §5.1.1）。不是距離門檻 |
| 命中回饋 | 命中時機首十字周圍出現 `X` |
| 目標框 | 敵紅我藍，隨距離縮放。**畫全部**，無距離門檻 |
| 畫面外指示 | 螢幕邊緣的相對方位箭頭。**畫全部** |
| 小地圖符號 | **高於我 = 三角、同層 = 方、低於我 = 倒三角**；敵紅我藍 |

**沒有「當前目標」這個概念，也不顯示血量。**

血量在二戰題材上說不通——你看不出對方的結構完整度。命中回饋就是 `X` 標記，那是這個世界裡真的存在的東西。而拿掉血量顯示之後，「要顯示誰的血」這個問題消失，整套目標選取狀態（選中誰、目標死了怎麼換、被遮擋怎麼辦）也就不必存在。

其餘元件本來就不需要選取：目標框、畫面外指示、小地圖符號都是**畫全部**；`X` 打中誰都一樣閃；預瞄環改成射程內每架各一個。M4 有 40 架時，能同時看到兩三個威脅的提前量反而比鎖定單一目標好用。

自機血量在 M2 也不做——沒有任何東西打得到玩家，永遠 100% 的數字是雜訊。留到 M4。

**開火鍵**：滑鼠左鍵。左鍵目前的用途是取得指標鎖——已鎖定時左鍵即為開火，未鎖定時左鍵請求鎖定（`bindings.ts` 已有 `document.pointerLockElement` 判斷，沿用即可）。

命中 `X` 標記顯示 **0.15 s**，期間再命中則重新計時。

不做彈藥餘量（§2 裁決）。

## 9. 測試策略

沿用 M1 的分層。

### 9.1 L1 純函數

`lead.ts` 的解與四種退化情形、`hit.ts` 的線段 vs AABB（含正好擦邊、線段完全在盒內、線段起點在盒內）、彈丸推進與回收。

### 9.2 L2 史實值

各武器的初速與射速對得上史料。與 M1 的 `specs.test.ts` 同一個模式：資料表本身就是被測物。

### 9.3 L3 平衡

§6.3 的三條相對斷言，加上 300 m 匯聚點的幾何驗證。

### 9.4 L4 命中矩陣

**M2 的重頭戲**，對應 M1 的指揮儀 120 案例矩陣。

```
距離     {100, 300, 500, 750} m      ← 全部在 1.2 s 壽命內到得了
相對角度 {尾追, 側方 45°, 正交 90°, 迎頭}
目標速度 {150, 250} m/s
目標機動 {等速直線, 定盤旋}
```

共 64 個組合。射手固定 200 m/s，靶機為 P-51D 的命中盒。

這一條的價值在於它把預瞄解、彈丸推進、命中判定三個模組**綁在一起**驗證。任何一個算錯——預瞄公式、彈丸繼承速度、機體座標轉換、匯聚幾何——都會在這裡露出來，而且看得出是哪一類組合失敗。

**判準分兩段**（實作偏離「全部必須命中」的字面規定）：

- **等速直線 32 案例：全部必須命中。** 實測全數通過，最差脫靶量 2.26 m。
- **定盤旋 32 案例**：`ω · t ≤ 5°`（彈丸飛行期間目標轉不到 5°）→ 必須命中；其餘 → 斷言脫靶量 `≤ 1.5 × R(1 − cos ωt) + 1 m`，其中 `R = v / ω` 是盤旋半徑。

第二條**比「必須命中」更嚴格**：預瞄解假設等速直線，目標在彈丸飛行的 t 秒內轉了 ω·t，於是偏離預測位置 R(1 − cos ωt)。這個誤差是**模型本身的**，不是缺陷；而預瞄公式或彈丸積分只要算錯，脫靶量會是 v·t 的量級（數十到數百公尺），一定超標。

實測的三個 0 命中案例都落在第二條裡：500 m 尾追 250 m/s（脫靶 6.2 m，曲率界 7.8 m）、750 m 尾追 250 m/s（14.1 / 17.5）、750 m 斜追 45° 250 m/s（8.9 / 15.4）。**打不到是對的**——1944 年的實戰有效射程本來就在 400 m 以內。

靶機用運動學積分而非完整 `Aircraft`：這一條測的是武器數學，「10°/s」要精確是 10°/s，曲率界才是可驗證的閉式量。靶機與玩家同物理由 `controllers.test.ts` 守。
