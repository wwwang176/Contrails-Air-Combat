# boom and zoom 收斂成三條規則

**狀態**：已實作，三個定值待掃描，待人工試飛。

**取代**：`2026-09-07-turn-disadvantage-doctrine-design.md` 的第 4 節（變更 C～F）
與 `2026-08-22-energy-tactics-design.md` 的整個相位機。那一份的第 2 節
（現況診斷）與變更 A、B 仍然成立，見 §6。

**範圍**：刪掉 `src/ai/tactics.ts` 的相位機；`rules.ts` 新增一條脫離理由。
**不動**：空層鎖、`strikeRun`／`bombRun`／`torpedoRun`、指揮層、機種 spec。

---

## 1. 負責人指定的三條

> 1. 離敵方距離很遠，則平飛或拉高保持高度
> 2. 距離即將接近，則進入自由開火（放給 AI 自己打，它本身就會壓低機鼻）
> 3. 敵方在身後或我轉不過去，則脫離

以及後續的兩次修正：

> 如果敵人正在我後方追擊我，是不是我永遠都會觸發脫離？

> boom and zoom 的轟炸、拋雷脫離的行為是不是必須要有一個時間鎖？
> 戰鬥機是不是也要有，只是時間比較短？

---

## 2. 規則 1 與 2 已經存在 —— 是空層鎖

`steer.ts` 的 `bandHold`：

```js
wide = smoothstep(bandAspectEnter, bandAspectFull, aspectAngle)  // 離軸越大越鎖
far  = sweetYield(interceptTime)                                  // 攔截時間越長越鎖
hold = max(wide, far) × gate
```

- 目標**遠**（攔截時間長）→ 鎖住高度帶平飛接近 = **規則 1**
- 目標**近**（攔截時間短、機首對上）→ `hold` 趨近 0，鎖放開，回到純追擊 = **規則 2**

而 `stepBand` 的 `state.altitude = min(anchor, chaseAlt)` 讓空層在敵人低於
自己時**貼著他那層走**，於是機頭自然壓向他 —— 那正是規則 2 括號裡那句
「它本身就會壓低機鼻」。

**這兩條不需要任何新程式碼。**

### 2.1 相位機是同一件事的第二套實作，而且會蓋掉第一套

`build` 與 `perch` 走 `tacticalCommand`，而 `band` 只餵給 `steerCommand`
（`AiController` 的分流）。所以相位機作用時空層鎖**完全不參與**。

實測（單機軌跡，f4f4 vs a6m5 20v20）：

```
   t  意圖      相位    距離  機首偏離目標
 21.5 approach  perch   4195    0.2°
 24.0 approach  perch   3580   11.4°
 27.0 approach  perch   2882   50.5°
 30.0 approach  perch   2361   78.4°
```

意圖顯示「接近」，實際操舵是 `stationKeeping` 的繞行 —— 機頭從正對敵人
一路轉到偏 78°。人工回報的原話：「approach 的時候還會轉反方向遠離敵人」。

## 3. 規則 3：脫離

### 3.1 「敵人在身後」不能當觸發條件

他在我後面追我這件事會持續幾十秒，用它當脫離條件就是**永久脫離** ——
與 `extendTurnLatch` 那個缺陷同一個形狀（那一份 spec 的 §2.1）。

而且那個情境已經有專門的行為：敵人在後方**而且正在威脅我** = `defend`，
既有意圖、優先權最高、自己的操舵。敵人在後方但**不構成威脅**時，正確的
動作是轉過去打，不是脫離。

**所以規則 3 只剩「我轉不過去」。**

### 3.2 「轉不過去」用 `timeToBear`

```
t = 機首偏離角 ÷ (我的最大角速度 − 視線角速度)
```

分母是**淨追趕率**：我轉得動的，扣掉他跑掉的。分母 ≤ 0 就是 `Infinity`
—— 「轉不過去」因此不需要另外定義，它是這個式子的自然結果。

**不能只用 `trackRatio`。** 那個既有欄位是 `視線角速度 ÷ 我的角速度`，
出貨值 `trackEnter: 0` 把它關掉了，而註解記著理由：

> 開著時護送關的谷底由 −368 m 惡化到 −921 m。**它只用角速度、把角度丟掉了**
> —— 敵人在機體仰角 +86 度而它說「追得上」。

**不能只用角度。** 只看偏離角會漏掉橫越的目標：等我轉過那 10°，他已經在
40° 外。

新式子把兩者收在一起 —— 整理之後就是

```
t = (偏離角 ÷ 我的角速度) ÷ (1 − trackRatio)
```

左半是角度，右半是那個被關掉的量當修正係數。不是二選一，是後者被吸收。

### 3.2.1 它是量級估計，已知的偏差

實測（自機 F4F-4 / B-17G，目標距離 1500 m）：

```
情境                        F4F-4      B-17G
① 正上方（相對靜止）          3.4 s      5.9 s
② 右舷正橫（相對靜止）        3.4 s      5.9 s
③ 右舷橫越 150 m/s           3.2 s      6.4 s
③b 右舷橫越 250 m/s          3.7 s      8.8 s
④ 正前方                     0.0 s      0.0 s
```

方向全對：轟炸機比戰鬥機久、橫越比靜止久、速度越快差越多、正前方是 0。

**兩個已知缺口：**

**一、①與②相同。** 上下不對稱沒有算 —— 往上轉要對抗重力，比往側面貴。
兩者的偏離角都是 90°，式子分不出來。要補得接 `turnPlanePitch`（它用前向
積分比較三個轉彎平面的成本），本版**不做** —— 先確認基本盤有效。

**二、戰鬥機與轟炸機只差 1.7 倍。** `instantaneousTurnRate` 是
`g·√(n²−1) ÷ 速度`，**速度在分母**，所以慢的飛機反而被補償。它算的是
「拉到結構極限能轉多快」，而轟炸機根本不會去拉那個過載。這個式子表達不出
「轟炸機幾乎轉不過去」。

後果由 §3.2.2 的機種閘門擋掉，但**這個量在慢速機上偏樂觀**，日後拿它做
別的判斷要記得。

### 3.2.2 只給戰鬥機

轟炸機轉不贏攔截機是常態，`extendTurnLatch` 對它永遠成立；而 B-17 的
`timeToBear` 實測 5.9～8.8 s，`bearMax` 是 8 —— 高速橫越那一格已經跨過去。

少了這個閘門，整隊轟炸機會離開航線。實測過一次：`turrets.test.ts` 的
「P-51 也打下了東西」由正數變成 **0**。那條測試講的是砲塔平衡，被一個 AI
打法的改動弄紅時成因完全看不出來 —— 所以護欄另立一條「轟炸機不走規則 3」
直接釘住。

### 3.3 脫離要有承諾

沒有承諾會這樣：

```
跟不上 → 脫離 → 飛開 → 敵人變遠、角速度變小 → 跟得上 → 回頭
→ 一接近又跟不上 → 脫離 → …
```

每隔幾秒抖一次。這是「永不解除」的鏡像缺陷。

三個機制各司其職：

| | 作用 | 值 |
|---|---|---|
| **觸發** | `timeToBear` 超過這麼多秒就算轉不到 | `bearMax` **待定值**（起始 8 s） |
| **最小承諾** | 一旦脫離，至少飛這麼久不准反悔 | `trackCommit` **待定值**（起始 4 s） |
| **距離出場** | 拉開到 `extendRange` 就結束 | 1500 m（既有） |
| **時間上限** | 拉不到距離時的保底，避免永久脫離 | `trackMax` **待定值**（起始 12 s） |

**為什麼距離優先**：脫離真正要的是「拉開到足以重置幾何」，時間只是它的
代理。但距離單獨用有一個失效模式 —— 他比我快時永遠拉不到，於是永久脫離。
兩個一起才有界。

### 3.4 轟炸與拋雷不走這一條

`strikeRun.ts` 已經有完整的攻擊航路狀態機：

```
進場 ──對正了──▶ 直飛 ──投完／飛過頭／逾時──▶ 脫離 ──補滿且夠遠──▶ 進場
```

再進場的條件是 `range > egressRange`（距離），不是碼表。而且轟炸機不被
徵召（`role === 'fighter'`），兩邊完全分開。**這一塊不動。**

## 4. 要刪的東西

`src/ai/tactics.ts` 的相位機整個移除。連帶消失的旋鈕與狀態：

```
旋鈕  perchEnter perchExit buildMax perchMax passSeconds diveMax
      zoomMin zoomMax cooldownSeconds longCooldownSeconds
      cycleLossMax dryRounds perchRange enterRange exitRange quota

狀態  phase dwell perchLatch farLatch settled commit closed passing
      cooldown cycleBase cycleValid cycleShot dryRounds
      lastCooldownRatio orbitSide lastTarget

函數  stepTactics tacticalCommand stationKeeping hasSlot teamIndexOf
```

**十六個旋鈕換成三個**（`bearMax`、`trackCommit`、`trackMax`）。

`AiController` 連帶移除：`tacticalInput`、`tacticalConfig`、`slotHas`/
`slotSeed`/`slotQuota` 快取、相位對意圖的覆寫、`tacticalCommand` 的分流。

## 5. 為什麼這樣會比較好，而不只是比較少

今天在相位機上修掉的每一個缺陷，都是**兩套實作互相打架**的產物：

| 修過的缺陷 | 根源 |
|---|---|
| `perch` 繞圈時機頭轉開 78° | `stationKeeping` 蓋掉空層鎖 |
| 蓄能撞期限就放棄整輪 | 能量門檻與時間預算差五倍（`settled`） |
| 俯衝 2.4 秒就結束、87% 沒射擊解 | 通過判定看接近率符號 |
| 俯衝被能量帳提早收手 | 止損懲罰俯衝存在的目的 |
| 徵召到轟炸機 | 相位機沒有機種概念 |
| 中斷讓冷卻失效 | 相位與計時分屬兩個生命週期 |

刪掉相位機之後，這六個缺陷連同它們的修補一起消失。剩下的三條規則各自
只有一個職責，而且兩條已經在跑。

## 8. 驗收

判準是**單機軌跡**，不是隊伍平均。今天的教訓：隊伍平均把「逐台 39～61%
的脫離」報成 36.5%，也把「有一台 230 秒沒開過一槍」完全藏起來。

護欄（`test/integration/turn-disadvantage.test.ts`）全部是單機：

| 護欄 | 它擋什麼 |
|---|---|
| 規則 3 的最長連續脫離 < `trackMax` + 1 | 永久脫離（原始缺陷） |
| **規則 3 的脫離佔時 > 0** | **機制沒接上** —— 少了它上面那條永遠是綠的 |
| 機首在 15° 錐內的佔時 > 5% | 「從頭到尾沒有瞄準」 |
| 轟炸機的規則 3 佔時 = 0 | 轟炸機離開航線 |
| 同機種的規則 3 佔時 = 0 | 改動漏到不該碰的機種對 |

第二條是今天最重要的一條：第一版用 `trackRatio` 時它直接紅了，因為那個
閂鎖出貨是關的。**沒有它，「脫離不超過上限」會永遠是綠的（根本沒有脫離），
我會回報「修好了」而實際上什麼都沒發生。**

改動前的單機基準：

| 量 | 現況（f4f4 vs a6m5、座位 0/5/10/15） |
|---|---|
| 機首在目標 15° 錐內的佔時 | 30.4 / 3.1 / 1.7 / 6.4% |
| 射擊解佔時 | 12.3 / 1.9 / 1.4 / 2.8% |
| 最長無射擊 | 53 / 87 / 93 / 67 s |

人工試飛看的四件事見上一份 spec §7.2。
