## 1. 負責人指定的三條

> 1. 離敵方距離很遠，則平飛或拉高保持高度
> 2. 距離即將接近，則進入自由開火（放給 AI 自己打，它本身就會壓低機鼻）
> 3. 敵方在身後或我轉不過去，則脫離

以及後續的兩次修正：

> 如果敵人正在我後方追擊我，是不是我永遠都會觸發脫離？

> boom and zoom 的轟炸、拋雷脫離的行為是不是必須要有一個時間鎖？
> 戰鬥機是不是也要有，只是時間比較短？

## 2. 規則 1 與 2 已經存在 —— 是空層鎖

`steer.ts` 的 `bandHold`：

```js
wide = smoothstep(bandAspectEnter, bandAspectFull, aspectAngle)  // 離軸越大越鎖
far  = sweetYield(interceptTime)                                  // 攔截時間越長越鎖
hold = max(wide, far) × gate
```

- 目標**遠**（攔截時間長）→ 鎖住高度帶平飛接近 = **規則 1**
- 目標**近**（攔截時間短、機首對上）→ `hold` 趨近 0，鎖放開，回到純追擊 = **規則 2**

而 `stepBand` 的 `state.altitude = min(anchor, chaseAlt)` 讓空層在敵人低於
自己時**貼著他那層走**，於是機頭自然壓向他 —— 那正是規則 2 括號裡那句
「它本身就會壓低機鼻」。

**這兩條不需要任何新程式碼。**

### 2.1 相位機是同一件事的第二套實作，而且會蓋掉第一套

`build` 與 `perch` 走 `tacticalCommand`，而 `band` 只餵給 `steerCommand`
（`AiController` 的分流）。所以相位機作用時空層鎖**完全不參與**。

實測（單機軌跡，f4f4 vs a6m5 20v20）：

```
   t  意圖      相位    距離  機首偏離目標
 21.5 approach  perch   4195    0.2°
 24.0 approach  perch   3580   11.4°
 27.0 approach  perch   2882   50.5°
 30.0 approach  perch   2361   78.4°
```

意圖顯示「接近」，實際操舵是 `stationKeeping` 的繞行 —— 機頭從正對敵人
一路轉到偏 78°。人工回報的原話：「approach 的時候還會轉反方向遠離敵人」。

## 3. 規則 3：脫離

### 3.1 「敵人在身後」不能當觸發條件

他在我後面追我這件事會持續幾十秒，用它當脫離條件就是**永久脫離** ——
與 `extendTurnLatch` 那個缺陷同一個形狀（那一份 spec 的 §2.1）。

而且那個情境已經有專門的行為：敵人在後方**而且正在威脅我** = `defend`，
既有意圖、優先權最高、自己的操舵。敵人在後方但**不構成威脅**時，正確的
動作是轉過去打，不是脫離。

**所以規則 3 只剩「我轉不過去」。**

### 3.2 「轉不過去」用 `trackRatio`，不用機體比較

`assess.ts` 既有的欄位，註解逐字寫著：

> 視線角速度 ÷ 我此刻的**瞬時**轉彎率上限。無因次。
> **> 1 = 即使拉到極限過載，機頭也追不上預瞄點。**

三個性質正好是這一條需要的：

| 性質 | 為什麼要 |
|---|---|
| **態勢量，不是規格常數** | `airframeTurnAdvantage` 對一組機種對幾乎是常數，貼上就撕不掉（今天的原始缺陷）。`trackRatio` 隨幾何變，敵人遠、橫越慢時自己就解除 |
| **無因次** | 分母是自己的能力，所以轟炸機的「錐角」自然窄、戰鬥機自然寬。不必為機種、高度、關卡各訂一個角度 |
| **已有閂鎖** | `stepTrack` 每步維護，`AiController` 已在呼叫。訊號本身只有 1.7 秒，讀瞬時值機首會每兩秒抖一次 |

### 3.3 脫離要有承諾

沒有承諾會這樣：

```
跟不上 → 脫離 → 飛開 → 敵人變遠、角速度變小 → 跟得上 → 回頭
→ 一接近又跟不上 → 脫離 → …
```

每隔幾秒抖一次。這是「永不解除」的鏡像缺陷。

三個機制各司其職：

| | 作用 | 值 |
|---|---|---|
| **最小承諾** | 一旦脫離，至少飛這麼久不准反悔 | **待負責人定值**（新增） |
| **距離出場** | 拉開到 `extendRange` 就結束 | 1500 m（既有） |
| **時間上限** | 拉不到距離時的保底，避免永久脫離 | **待負責人定值**（新增） |

**為什麼距離優先**：脫離真正要的是「拉開到足以重置幾何」，時間只是它的
代理。但距離單獨用有一個失效模式 —— 他比我快時永遠拉不到，於是永久脫離。
兩個一起才有界。

### 3.4 轟炸與拋雷不走這一條

`strikeRun.ts` 已經有完整的攻擊航路狀態機：

```
進場 ──對正了──▶ 直飛 ──投完／飛過頭／逾時──▶ 脫離 ──補滿且夠遠──▶ 進場
```

再進場的條件是 `range > egressRange`（距離），不是碼表。而且轟炸機不被
徵召（`role === 'fighter'`），兩邊完全分開。**這一塊不動。**

## 4. 要刪的東西

`src/ai/tactics.ts` 的相位機整個移除。連帶消失的旋鈕與狀態：

```
旋鈕  perchEnter perchExit buildMax perchMax passSeconds diveMax
      zoomMin zoomMax cooldownSeconds longCooldownSeconds
      cycleLossMax dryRounds perchRange enterRange exitRange quota

狀態  phase dwell perchLatch farLatch settled commit closed passing
      cooldown cycleBase cycleValid cycleShot dryRounds
      lastCooldownRatio orbitSide lastTarget

函數  stepTactics tacticalCommand stationKeeping hasSlot teamIndexOf
```

**十六個旋鈕換成兩個**（最小承諾、時間上限）。

`AiController` 連帶移除：`tacticalInput`、`tacticalConfig`、`slotHas`/
`slotSeed`/`slotQuota` 快取、相位對意圖的覆寫、`tacticalCommand` 的分流。

## 5. 為什麼這樣會比較好，而不只是比較少

今天在相位機上修掉的每一個缺陷，都是**兩套實作互相打架**的產物：

| 修過的缺陷 | 根源 |
|---|---|
| `perch` 繞圈時機頭轉開 78° | `stationKeeping` 蓋掉空層鎖 |
| 蓄能撞期限就放棄整輪 | 能量門檻與時間預算差五倍（`settled`） |
| 俯衝 2.4 秒就結束、87% 沒射擊解 | 通過判定看接近率符號 |
| 俯衝被能量帳提早收手 | 止損懲罰俯衝存在的目的 |
| 徵召到轟炸機 | 相位機沒有機種概念 |
| 中斷讓冷卻失效 | 相位與計時分屬兩個生命週期 |

刪掉相位機之後，這六個缺陷連同它們的修補一起消失。剩下的三條規則各自
只有一個職責，而且兩條已經在跑。
