# 島的起伏與海岸浪花

2026-08-28

## 一、問題

### 1.1 每一座島都是同一顆圓錐

`src/world/archipelago.ts` 的 `bake` 裡，一座島的全部形狀就是這兩行：

```ts
const s = smoothstep(1, 0, d / isl.radius / wobble)
const h = isl.peak * s + SEA_FLOOR * (1 - s)
```

高度只是**離島心的距離**的函數。`wobble`（3θ 與 5θ 兩道正弦）推歪的是輪廓，
不是剖面。所以 48 座島是同一顆饅頭的 48 種縮放：

- 沒有稜線、沒有鞍部、沒有次峰
- 最陡處恆為 `1.5 × peak / radius`（錨島 44°），而且**每一個方位都一樣陡**
- 峰恆在島心，海岸線是一個平滑的團塊

改動前的截圖（`scratchpad/before-anchor-a.png`、`before-small.png`）把這件事
擺得很清楚 —— 遠處那一排小島是彼此的複製品。

### 1.2 海面完全不知道陸地在哪

`render/ocean.ts` 沒有任何地形的輸入。碎光的機率只吃三件事：半角向量對齊
（`align`）、浪高偏置（`crest`）、距離淡出（`fade`）。所以靠岸的海與外海長得
一模一樣 —— 沒有碎浪、沒有淺灘的訊號。

## 二、要做什麼

### 2.1 島 = 好幾瓣的聯集

一座島不再是一顆圓錐，而是**主瓣加上 2～4 顆偏心的小瓣取 max**。每一瓣都是
現在那條 smoothstep 剖面，參數全部由現成的 LCG 抽。

```
h = max over lobes:  peak_i × s_i + SEA_FLOOR × (1 − s_i)
    s_i = smoothstep(1, 0, d_i / r_i / wobble_i)
```

【為什麼不用 fBm 噪聲】`archipelago.ts` 的檔頭本來就寫著「島形是解析的，
不用 noise 函式庫」——「決定性天然成立、沒有第三方相依」。多瓣做到同一件事
而且不違背它：兩瓣相交處 `max` 留下的摺線就是稜線，這正是 low-poly 平面著色
最吃得到的訊號。

**三個既有契約變成建構時就成立的不變式，一個都不必重新定值：**

```
  outerRadius   每一瓣：偏移 + 瓣半徑 × WOBBLE_MAX ≤ outerRadius
                → 地形延伸範圍不變，AI 的圓盤、mesh 的裁切、視錐包圍球全部照舊
  PEAK_MAX      主瓣 = peak，其餘瓣的高度恆 < peak
                → peak 仍然是實際的最高點，而且仍在島心
  WOBBLE_MAX    每瓣自己一組相位，振幅沿用 WOBBLE_A / WOBBLE_B
                → 常數不動
```

【偏移由「還放得下多少」反推，不是抽完再夾】`off = u × (outerRadius −
r × WOBBLE_MAX)`，`u ∈ [0.45, 1]`。不變式因此是恆等式，不是一個要驗的條件。

【抽瓣的 `rand()` 必須排在挑位置的迴圈之前】與現有的相位同一個理由：
rejection sampling 會讓序列漂。

【瓣太小就不留】一瓣至少 `LOBE_MIN_RADIUS = 60 m`（1.5 格）才畫得出形狀。
**但參數照抽不誤** —— 抽的組數固定，序列才穩。

### 2.2 浪花 = 不挑角度的碎光

烘完高度場之後多做一張同尺寸的**膨脹圖**：陸地（`h ≥ 0`）是 1，往外
`SHORE_BAND = 200 m`（5 格）由 1 平滑降到 0。上傳成 1024² 的單通道貼圖。

片段著色器把它加成一項**不看太陽方向**的機率：

```glsl
float crestGain = max(1.0 + uCrestBias * crest, 0.0);
float p = (align * uDensity + shore * uShoreDensity) * fade * crestGain;
```

【浪花與碎光共用一切】同一批三角面、同一套閃爍、同一套浪峰偏置。差別只在
第一項挑角度、第二項不挑。**沒有第二個「白色從哪裡來」的真相**，也沒有粒子。

【`shore` 要在面的重心取樣，不是在片段】與 `faceH` 完全同一個理由：
`vOceanWorld.xz` 在面內是內插的，逐片段取樣會把一個三角形切成半白半不白。

【距離場由高度場推得，不是由島的參數另外算】2.1 會大改海岸線的形狀。
膨脹圖吃的是烘好的 `field.data`，所以海岸線怎麼變，浪花自動跟著走。

## 三、不做什麼

- **不碰 `SEA_FLOOR` / `DRAW_FLOOR` / `PEAK_MAX` / `WOBBLE_MAX`**。見 2.1。
- **不做淺灘變色**。專案負責人 2026-08-28 未裁定；配色照舊。
- **不加沙灘台地**。現在沙灘（0～12 m）在錨島上是 46 m 寬，約一格多一點；
  多瓣之後海岸線本身會變化很多，先看那樣夠不夠。
- **不碰碰撞**。`collisionHeightAt` 讀的還是同一份高度場。

## 四、風險

| 風險 | 為什麼 | 怎麼處置 |
|---|---|---|
| 46 座隨機島的位置全變 | 多抽了 `rand()`，序列往後推 | 錨島寫死不吃 `rand()`，交會區不受影響；`terrain-in-play` 三條要重量 |
| 局部坡度變陡 → AI 撞山變多 | 瓣的交界是摺線 | 重量 `terrain-in-play`。**紅了回報，不自己放寬護欄** |
| 三角形數變動 | 海岸線外擴到 `outerRadius` 附近 | 現在陸地約 126k，量改後的值 |
| 貼圖上傳的對齊 | R8 的 1024 列可被 4 整除，但 1×1 的退化貼圖不行 | `unpackAlignment = 1` |

`replay-determinism` / `order-of-battle-replay` / `tactics-off` **不吃地形**
（查過，三個檔完全沒有引用），所以 digest 護欄不受影響。

## 五、驗收

1. 單元：多瓣的三個不變式（`outerRadius` 外恰好是 `SEA_FLOOR`、島心恰好是
   `peak`、每一瓣都放得下）。
2. 單元：**起伏真的存在** —— 沿一條半徑走出去不再單調遞減（現在保證單調）。
   那是「有鞍部」可測的代理。
3. 單元：膨脹圖（岸上 255、帶外 0、帶內單調、與高度場同一套索引）。
4. 單元：兩個海面材質都取樣 `uShoreMap`，而且取樣點是 `faceCen`；
   `shore = 0` 時機率式與改動前逐字等價。
5. 整合：`terrain-in-play` 重量。
6. 截圖：`island-shot.e2e.ts` 的五個凍結姿態，before / after 對比。
