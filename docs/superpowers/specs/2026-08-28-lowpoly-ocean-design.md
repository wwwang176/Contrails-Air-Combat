# 低多邊形的海（2026-08-28）

## 1. 要做什麼

專案負責人的原話：

> 我想改回 lowpoly 風格。海跟山一樣都是多邊形組成，但是海的邊長比山大 1.5。
> 然後一樣是兩片海（近海、遠海）重疊，近海就是有浪遠海平面就好。
> 白點一樣要有，不然海會太平，白點一樣波峰比較容易生成，波谷低機率。
> 顏色照目前的配色，近深遠淺，可以對三角面獨立上色嗎？

以及後續的一條裁定：

> CPU 那邊你搞複雜了，其實海面碰撞體就平面就好，海浪只是視覺高低而已。

### 1.1 現況與目標的差距只有一個字：真的

海面**已經**是 `flatShading: true`（`ocean.ts:1920`），而且片段著色器裡已經有一整套
Voronoi 在**假造**低多邊形的面 —— 那一段自己的註解就寫著「每塊自己的法線傾斜 ——
low-poly 的『面』」。看不出稜角只是因為格子是 **2.5 m**，在畫面上遠小於一個像素。

所以這一輪不是「加上低多邊形」，是**把假的換成真的**：

```
  現在                              這一輪
  ────────────────────────────────────────────────────────
  幾何 2.5 m 格，稜角進次像素        幾何 60 m 格，稜角就是外觀
  片段用 Voronoi 假造面              刪掉，面是真的
  片段每像素跑波坡度迴圈算法線        刪掉，面法線由 flatShading 免費給
  碎光靠 Voronoi 選塊                碎光逐面
  碰撞讀完整波高                     碰撞是平面
```

### 1.2 為什麼順便是效能的一刀

2026-08-28 量到（Intel Iris Xe，1707×960 @ DPR 1.5，解鎖 vsync，代飛 20v20，
交錯配對三輪取中位，`test/e2e/ocean-cost.e2e.ts`）：

```
  情境                        基準              關掉海面省
  ───────────────────────────────────────────────────────
  座艙 · 中空 4,000 m     18.40 ms  54 FPS   10.65 ms  57.9%
  座艙 · 甲板   600 m     18.80 ms  53 FPS    8.40 ms  44.7%
  上帝視角高空            24.50 ms  41 FPS   13.50 ms  55.1%
  座艙 · 中空 · DPR 0.5    8.45 ms 118 FPS    4.15 ms  49.1%
```

**海面佔幀時間的 45~58%**，是這個場景最大的一筆（島是 6.35 ms / 25.1%）。
同一場景像素砍成 1/9 之後海的成本只掉 2.6 倍（不是 9 倍），解出來是

```
  跟著像素走     ~7.3 ms   69%   片段著色
  跟像素無關     ~3.3 ms   31%   頂點與繪製
```

這一輪兩邊都打得到：三角形由 253,952 降到 106,496（頂點那 31%），
片段著色器刪掉兩套 Voronoi、波坡度迴圈、微波迴圈（片段那 69%）。

**但效能不是驗收條件，外觀才是。** 護欄只擋「不得比現況差」。

### 1.3 做完之後量到的（2026-08-28）

`test/e2e/ocean-ab.e2e.ts`，同一個機器狀態**背對背**跑兩次（改動前用
`git checkout main -- src/render/ocean.ts …` 換進來），上帝視角高空、鏡頭不動：

```
                三角形      有海        無海        海面成本      佔比
  main         520,452    40.00 ms   21.60 ms    18.25 ms     45.6%
  低多邊形      380,018    30.80 ms   22.00 ms     8.90 ms     28.9%
```

**海面成本對半。** 扣掉海的基準線兩邊相同（21.6 / 22.0），所以這個比較是公平的
—— 差的就是海。整幀 40.0 → 30.8 ms，也就是 25 → 32.5 FPS。

【為什麼不是用 `ocean-cost.e2e.ts` 的數字】那一支量的是「海面佔這一輪的幾成」，
同一輪之內可信（交錯配對），但**兩輪之間的絕對值不可比** —— 改動後那一輪接在
400 秒全套測試之後跑，基準線整片被抬高了 6 ms。

【為什麼鏡頭要不動】代飛的鏡頭一直在動，而海面佔畫面多少正是要量的自變數：
實測 6 秒窗的散布是 12~23 ms，蓋過要量的東西。上帝視角爬到高空之後鏡頭不動，
量到的散布是 30.6~30.9。

【為什麼不能凍結畫面】暫停時主迴圈只呼叫 `render()`，JS 一路跑在 GPU 前面 ——
凍結時量到「有海 8.0 / 無海 7.8 ms」，而同一個場景活著跑差三成。
**在回呼裡加 `gl.finish()` 也沒有用。**

## 2. 幾何

### 2.1 格子 60 m，clipmap 保留

`world/archipelago.ts` 的 `FIELD_CELL = 40`，×1.5 = **60**。

clipmap 的結構不動，只改三個常數：

```
                      現在        這一輪
  OCEAN_BASE_CELL     2.5 m       60 m
  OCEAN_RING_SEGMENTS 128         128（不動）
  OCEAN_LEVELS        10          4

  L0  實心  60 m 格   ±3,840 m     32,768 三角形
  L1  方環 120 m 格   ±7,680 m     24,576
  L2  方環 240 m 格  ±15,360 m     24,576
  L3  方環 480 m 格  ±30,720 m     24,576
                                  ───────
                                  106,496（現在 253,952）
```

**為什麼不是均勻 60 m 鋪到 30 km**：那是 `(61440/60)² × 2 = 2,097,152` 個三角形。
均勻格的成本是半徑的平方，clipmap 是對數。

**為什麼外圈粗沒關係**：頂點位移按「離中心多遠 → 這裡的格子多大」淡出（§3.2），
所以格子變粗與浪變平是同一件事的兩面 —— 遠處是大而平的面，近處是小而有起伏的
面，中間沒有接縫。

**為什麼層數由 10 降到 4**：現行的十層是為了讓遠海接縫的 5 m 落差進次像素
（82 km 處 0.08 px）。30.7 km 處是 0.21 px，仍在一個像素以內。

### 2.2 網格必須吸附格點 —— 這是反轉一條既有的決定

`ocean.ts` 現在明文寫著「十層共用同一個中心，而且**不做**格點對齊」，
理由是頻帶限制讓取樣永遠在 Nyquist 之內、滑動只剩內插誤差。

**60 m 之後那個理由不成立。** 頂點在波場裡連續滑動，代表每一幀每個面的三個角
都落在波的不同相位上 —— 面的形狀逐幀改變，畫面上是整片海在蠕動、稜線在爬。
2.5 m 時看不出來是因為那個誤差遠小於一個像素；60 m 時它**就是**外觀。

做法：`update` 把中心吸附到 **480 m**（最外層的格距）的整數倍。
480 能被 60 / 120 / 240 整除，所以四層同時落在各自的格點上，
**`uOrigin` 仍然只有一個** —— 不對齊換來的那個好處保住了。

代價：L0 的中心最多偏離相機 240 m，而 L0 的半寬是 3,840 m。無感。

### 2.3 遠海不動

`FAR_SEA_SIZE`（6,000 km）、128×128 的細分、`renderOrder = 1`（排在近海之後
畫，讓 early-Z 收掉被蓋住的部分）全部維持。只有兩件事跟著動：

- 深度比較改成 `LessDepth`，見 §3.3。`FAR_SEA_Y` 因此**維持 −5.0 不動**。
- 逐面色與逐面白點不套在它身上，見 §4.3。
- 其餘材質參數跟著近海走（同 `SEA_COLOR` / `SEA_ROUGHNESS` 的既有紀律：
  兩份會漂開，症狀是 5 km 處一條色帶）。

## 3. 浪

### 3.1 五道剩三道，而且要重新編寫

現行 `WAVES` 的波長是 140 / 105 / 78 / 55 / 31 m。60 m 的格子，Nyquist 的
下限是 **120 m** —— 五道裡四道畫不出來，而 `RIPPLE_WAVES`（更短）全滅。

起始值（**這是起始值，不是結論** —— 外觀由截圖裁定）：

```
  波長 380 m   振幅 2.0   方向   0°
  波長 250 m   振幅 1.5   方向  55°
  波長 165 m   振幅 1.0   方向 115°
                 ────
  振幅和 4.5 m（現行是 4.673，量級不變）
```

三道都在 120 m 之上。陡度 `2πA/λ` 分別是 0.033 / 0.038 / 0.038，遠低於
Gerstner 打摺的 0.4。相鄰面的高差最大約 6.6 m / 60 m，法線差約 12° ——
比島（相鄰面差幾十度）柔，但看得出來。

座標扭曲（`WAVE_WARP_*` 2113 / 3271 m、`WAVE_WARP2_*` 419 / 577 m）**全部保留**。
它們打散的是「正弦的和是格柵」那個問題，與格子多大無關。

`RIPPLE_WAVES` 與它整套（`RIPPLE_RESOLVED`、`RIPPLE_GLSL`、`SHADE_SLOPE_RMS`
的預算分配）**全部刪掉**。

### 3.2 頂點淡出的窗要放寬 —— 這一輪要的正是折角

`OCEAN_VERT_FADE_LO / HI = 0.2 / 0.4` 的立意是「正弦波用直線接起來，要五個點
以上才看不出折角」。**這一輪的目標就是那個折角。** 改成 **0.35 / 0.5**：
`0.5` 正好是 Nyquist（格子 = 半波長），是物理上的硬上限，不是美學選擇。

**淡出是徑向連續的，不是逐層常數。** 頂點著色器算的是

```glsl
float vCell = max(uBaseCell, length(transformed.xz) * uInvHalfSeg);  // = 距離 / 64
```

也就是「這裡的格子多大」由**離中心的距離**推得，而不是查這個頂點屬於第幾層。
兩層交界上同一點兩層算出同一個 `vCell`，淡出量因此逐位元一致 —— 那是它沒有
接縫的原因，**不能換成逐層常數**。

於是每一道波有一個「消失半徑」`0.5 × λ × 64`：

```
  波長 380 m   撐到 12,160 m
  波長 250 m   撐到  8,000 m
  波長 165 m   撐到  5,280 m
```

浪不是在 L0 的邊緣結束，是一路淡到 12 km；而格子隨半徑變粗，兩者同時發生 ——
遠處是大而平的面，近處是小而有起伏的面。**接到平的遠海是既有機制自動做到的**，
不必新增邊界處理。

### 3.3 遠海的深度測試必須改判準

`ocean.test.ts` 有一條「浪存在的距離上，遠海與細浪面的深度分得開」：
浪的到達半徑 `0.5 × 最長波長 × 64`，深度量化階 `z²/2²⁴`，要求 `3 × 階 < −FAR_SEA_Y`。

新的最長波撐到 12,160 m，量化階是 **8.81 m** —— 三倍是 26.4 m，而 `FAR_SEA_Y`
只有 −5。**那條會紅，而且它是對的**：遠海排在後面畫、`LessEqualDepth` 在平手時
讓後畫的勝出，於是遠海會蓋掉近海的逐面色。

**不靠把遠海壓到幾十公尺以下解決** —— 那個落差自己會變成一條看得見的線。
改成讓遠海用 **`depthFunc: LessDepth`**：

遠海恆在近海之下、而且在 clipmap 的覆蓋範圍內恆在近海之後（同一條視線上更遠），
所以真實深度恆為 `far ≥ near`。量化是單調的，量化後仍然 `far ≥ near`。
`LessDepth` 拒絕相等 —— **近海在平手時勝出，而平手是唯一的失效模式**。
這比一個數值餘裕更強：它與距離、波長、振幅全都無關。

原測試改成守 `depthFunc === LessDepth` 與 `renderOrder` 的先後。

## 4. 一面一色

### 4.1 答案是可以，而且在這個尺度上它是主角

海太平了。相鄰面的法線只差約 12°（島是幾十度），**光靠法線做不出低多邊形感**。
低多邊形的訊號要由**每個面自己的色調**帶。

順帶更正一件事：`island.ts` 現在**不是**「每個三角形一個顏色」——
它是 indexed 幾何、逐頂點上色，顏色在面上是內插的；稜角來自 `flatShading`
給的逐面法線。海這一輪要的比島更進一步。

### 4.2 做法：從格座標反推面，不加任何幾何

不能用逐頂點屬性：clipmap 是 indexed 幾何，一個頂點被周圍六個三角形共用，
**沒有辦法給每個 primitive 一個唯一值**。要用就得 non-indexed，頂點數 ×3，
那會把 §2.1 省下的頂點又吐回去。

（`three@0.180` 的內建材質會轉成 `#version 300 es`，所以 `flat` 其實可用 ——
但共用頂點那個理由與 GLSL 版本無關，重建仍然是對的做法。）

改用重建：網格是規則格、而且吸附格點（§2.2），所以片段可以從**未位移**的
格座標直接算出自己屬於哪一個面。`vOceanWorld` 已經是它 —— 頂點只位移 `.y`，
所以 `vOceanWorld.xz` 就是未位移的世界 XZ，**不必新增 varying**：

```glsl
// 【格距要按層算，不是一律 60】四層共用同一顆材質，格距是 60/120/240/480。
// 一律除以 60 的話，L1/L2/L3 的每一個真實三角形會被切成 4/16/64 個假色塊。
// 環是**方**的，所以用 Chebyshev 半徑，不是 length()
vec2  local = vOceanWorld.xz - uOrigin;
float r     = max(abs(local.x), abs(local.z));
float cell  = uBaseCell * exp2(ceil(log2(max(1.0, r / (uBaseCell * uHalfSeg)))));

vec2  q    = vOceanWorld.xz / cell;
vec2  cel  = floor(q);
vec2  t    = q - cel;
float tri  = step(1.0, t.x + t.y);   // 與 clipmapLevelGeometry 的對角線同一條
float id   = oceanHash(cel + tri * 0.5);
```

**零額外幾何、零額外屬性、零額外 varying。**

【對角線必須與幾何一致】`clipmapLevelGeometry` 的索引是 `a,c,b` 與 `b,c,d`，
對角線落在 `tx + tz = 1` —— 與上面的 `step` 同一條（已核對）。寫反的話色塊會與
稜線錯開半格，看起來像兩層網格在打架，而那**不會讓任何測試變紅**：唯一守得住
它的是截圖。

【`exp2(ceil(log2(...)))` 怎麼對上幾何】第 L 層是半寬 `32c` 到 `64c` 的方環
（`c = 60 × 2^L`）。`r ≤ 3840` → L0、`r ∈ (3840, 7680]` → L1，依此類推 ——
`r / 3840` 取 `log2` 再 `ceil` 正好是層號。

### 4.3 遠海不套這一段

遠海是 128×128 的 `PlaneGeometry`，一格約 **46.9 km**。套 60 m 的格座標會讓它
長出一整片**假的**色塊；按它自己的真實面上色則是一個面幾十公里。

`applySparkle(m, displace, cacheKey)` 已經有一個 `displace` 旗標在區分兩者，
逐面色與逐面白點**都掛在同一個旗標下**。遠海只保留基色、天空反射、horizon mix。

【遠海因此沒有白點了】現行的碎光鋪到 250 km，遠海是有白點的。拿掉之後
30.7 km 之外會不會變成一塊死板 —— **那是截圖要回答的問題**。退路：給遠海一個
不冒充真實面的便宜噪聲（世界座標 → LOD 格 → hash），而不是把 Voronoi 撿回來。

### 4.4 顏色怎麼組

```
  基底      SEA_COLOR（0x18344c，不動）
  逐面擾動  id → ±ΔL 的明度微擾（起始值 ±6%）
  波峰偏亮  面中心高度 → 亮度偏置，與碎光共用同一條偏置函數（§5）
  近深遠淺  菲涅耳天空反射（見下），外加最終色 mix 向 uHorizonColor
```

**「近深遠淺」的來源要說清楚，因為它不是我原本以為的那一個。**
`SEA_AERIAL_STRENGTH` 現在是 **0** —— 大氣透視那一段是關掉的。現況由近到遠的
明暗變化幾乎全部來自**菲涅耳天空反射**：掠射角（遠）反射率趨近 1、看到的是天空；
俯視（近）F0 = 0.02、看到的是海自己的深色。

而任務 3 正要換掉那一段吃的法線來源（`oceanNormal`）。**改錯就會靜靜地把
「近深遠淺」弄掉**，而沒有任何測試守得住。天空反射那一段列為不可刪，
三個凍結視角的截圖列為驗收。

## 5. 白點

規則不變，**`SPARKLE_CREST_BIAS = 0.8` 那一套整組留著**（`ocean.test.ts` 有四條
在守它：偏置落在 [0,1]、對高度是奇函數所以總量不變只是搬家、過渡半寬等於波高
RMS 的一半、高度吃與坡度同一個淡出權重）。

變的是算在哪裡：

```
  現在   逐像素。兩套 Voronoi（各九次 hash22）選塊、塊內傾斜、波坡度迴圈
  這一輪 逐面。面 id → 擲一次；面**重心**高度 → 偏置機率
```

【為什麼一定要重心，不能用 `vOceanWorld.y`】那個值在面內是內插的，所以機率 `p`
在面內會變 —— `roll < p` 就會把一個三角形切成半白半不白，那不是「整面變白」。
重心在格內的局部座標是固定的（下三角 `(1/3, 1/3)`、上三角 `(2/3, 2/3)`），
在那一點重算一次波高（三道波 + 扭曲 + 包絡，約九次 `sin`）。

九次 `sin` 聽起來不少，但刪掉的是九次 `cos`、五次 `sin`、兩次 `exp`、
**二十次 `hash22`**。

**白點的形狀：整個三角面變白。** 那是低多邊形的標準做法，也是最便宜的，
而且與 §4 的一面一色是同一個機制的延伸。若截圖看起來像馬賽克而不是碎光，
退路是在面內用 `id` 決定一個小點的位置 —— 但先做整面，因為它更符合
「海跟山一樣都是多邊形組成」。

淡出（`SPARKLE_FADE_START / END`）與閃爍（`SPARKLE_TWINKLE`）保留。
`SPARKLE_CELL` / `SPARKLE_CELL_REF` / `SPARKLE_DRIFT` / `SPARKLE_TILT_SHARE` /
`SPARKLE_EDGE` / `SPARKLE_JITTER` / `SPARKLE_DARK_*` 隨 Voronoi 一起刪掉。

## 6. 碰撞：平面

### 6.1 裁定與它為什麼站得住

`crash.ts` 現在的註解寫的**正好相反**：

> 用平面 y=0 判定會出現「明明穿過浪峰卻沒事」與「離水面還有一段就爆」兩種
> 相反的錯覺。

那句話是在振幅和 4.673 m 的前提下寫的。而 `CRASH_CLEARANCE = 2` m 是一個
自承的估計值（「機體幾何尚未存在，故先以一個保守的半機身高度代替」）。
浪的量級與那個猜出來的餘裕同級 —— 用波高判定只是在一個 2 m 的估計上疊
精確度。**這段註解要改寫成新的理由，不是在後面補一行沿革。**

### 6.2 只有一個呼叫點要動，零測試變更

```
  World.crashPolicy 的預設就是 SEA_LEVEL（平面 y ≤ 0）
  全部 headless 測試與探針走的是預設，或自己的地形 predicate
  唯一讀波高的是 main.ts:521 —— 遊戲那一條線
```

也就是說**護欄早就都是平面的**，改過去是把遊戲對齊到測試。

`aircraft.test.ts` 那兩條吃 `gerstnerHeight` 的測試不會紅 —— 它們測的是
`isCrashed` 這個函式（波高場是注入的），不是遊戲的接線。

**山還是要撞得到**，所以不是換成 `SEA_LEVEL`，是把判定用的高度改成
`max(field.sample(x, z), 0)`。

### 6.3 視覺放置仍然吃波高

`heightAt` 有四個消費者，只有一個是判定：

```
  main.ts:521   crashPolicy      → 改平面
  main.ts:841   splashes.emit    → 照舊
  main.ts:994   wrecks.step      → 照舊
  main.ts:995   debris.step      → 照舊
```

`wrecks.ts:237` 自己寫著「浪高在最低角點的水平位置取樣 —— 海面振幅在機身尺度
上是有差別的」。殘骸會在水面停留一段時間；把它釘在 y=0 會一下半沉、一下浮在
空中。水柱與碎片是瞬間的，看不出來，但**沒有理由為它們特地改**。

視覺那一份用**連續的 `gerstnerHeight`**，不需要跟 mesh 的面對齊到公分 ——
差一公尺放一根水柱、擺一具殘骸看不出來。**所以不做三角形內插。**

## 7. 明確不做

- **不做遠海的浪**。遠海是平的，那是負責人指定的。
- **不做均勻 60 m 鋪滿**。見 §2.1。
- **不改 `CRASH_CLEARANCE`**。它要等機體幾何。
- **不動 `island.ts`**。山的外觀是既有的、已驗收的。
- **不改 `SEA_COLOR` / `uHorizonColor`**。負責人指定「顏色照目前的配色」。
- **不做面內小白點**。先做整面白，看過截圖再說（§5）。
- **不追效能數字**。效能是這一刀的副產品，護欄只擋迴歸。

## 8. 護欄

### 8.1 會作廢或重寫的

`ocean.test.ts`（35 條）裡驗現行片段著色器性質的那些全部作廢：微波階的坡度
RMS、Voronoi 塊的地板、塊傾斜只餵給碎光、微波的細座標扭曲互質、
「著色沒有比幾何更細的結構」。

留得下來的：`gerstnerHeight` 的四條（純函數、隨時間變、振幅範圍、波參數非空）、
碎光浪峰偏置的四條、遠海的三條、clipmap 尺寸恆等式、`dispose`。

### 8.2 要新增的

```
  格子邊長      OCEAN_BASE_CELL === FIELD_CELL × 1.5，而且 1.5 是寫在測試裡的
                意圖 —— 山變了海要跟著變
  格點吸附      update 之後，中心必然是 480 的整數倍；連續移動相機一段距離，
                每個頂點的世界 XZ 都落在 60 的整數倍上
  對角線一致    §4.2 的 tri 判準與 clipmapLevelGeometry 的索引順序同一條
                （用幾何的索引反算對角線，不是抄一個常數）
  Nyquist       每一道 WAVES 的波長 > 2 × OCEAN_BASE_CELL
  淡出的窗      L2 與 L3 對三道波的權重全部是 0（平的），L0 全部 > 0
  面色的決定性  同一個 (cell, tri) 恆得同一個 id；相鄰面的 id 不相等
  遠海高度      FAR_SEA_Y < −(振幅和)，與 WAVES 綁在一起算，不是寫死
```

### 8.3 不受影響、但要實跑確認

`perf-gate`、三支 replayDigest 護欄（`replay-determinism`、
`order-of-battle-replay`、`tactics-off`）——  headless 的 `crashPolicy` 走預設
的平海面，不碰 `ocean`。**用推的不算，開工前後各跑一次。**

### 8.4 視覺

`test/e2e/ocean-cost.e2e.ts` 改動前後各跑一次，確認海面佔比沒有變差。
`battlefield-visuals.e2e.ts`、`god-view.e2e.ts` 要重看。

## 9. 驗收

1. 截圖：座艙貼海、座艙中空、上帝視角高空三張，看得出是多邊形的海。
2. 白點在，而且偏在波峰。
3. 近深遠淺與現況同一個調子。
4. 全套測試綠。
5. `ocean-cost.e2e.ts` 的海面佔比不比現況差。
6. 飛機撞不到看不見的浪（因為根本沒有浪參與判定），山照樣撞得到。
