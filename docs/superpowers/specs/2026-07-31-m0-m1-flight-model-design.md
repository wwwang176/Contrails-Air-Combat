# M0 + M1 設計文件：可飛行的單機與飛行模型

日期：2026-07-31
狀態：已核准
範圍：M0（專案骨架）+ M1（飛行模型與操控）

---

## 1. 概述

本專案是一個網頁 3D 空戰遊戲，主題是二戰活塞戰鬥機的**能量戰**。完整遊戲規劃橫跨 8 個里程碑（M0–M8），本文件只涵蓋 **M0 + M1**。M2 之後每個里程碑各自撰寫獨立的 spec 與實作計畫。

M1 的核心命題：**做出一個物理上可信、且能讓玩家親身感受到「速度與高度就是戰鬥力」的飛行模型。** 如果 M1 失敗，後續所有里程碑都沒有意義。

## 4. 架構

### 4.1 模組

```
core/                 固定步長迴圈、時間、數學、暫存物件池
physics/atmosphere    ISA 大氣            ── 純函數
physics/aero          氣動力與力矩         ── 純函數
physics/propulsion    引擎功率 + 螺旋槳推力 ── 純函數
physics/dynamics      6DOF 剛體積分        ── 唯一持有狀態的物理模組
specs/        機種資料             ── 純資料
aircraft/     Aircraft 實體（組合上述）
control/      FlightDirector + G/迎角限制器 + PID
input/        鍵鼠 → 抽象輸入狀態
camera/       第三人稱 / 機首視角 / 右鍵自由視角
render/       場景、海面、天空、參照物、程序化機體幾何
hud/          Canvas 2D overlay
tools/        調參面板、Telemetry、EM 圖產生器
```

### 4.2 關鍵邊界：純函數三兄弟

`atmosphere` / `aero` / `propulsion` 一律為純函數：輸入飛行狀態與機種參數，輸出數值；不持有狀態、不引用 `Aircraft`、不引用 three.js 場景物件。

三個理由，缺一不可：

1. 可直接單元測試，不需建構完整飛機
2. EM 圖產生器需掃描上萬個 (速度 × 高度 × 迎角) 網格點；若氣動計算與 `Aircraft` 耦合則無法離線批次執行
3. M4 的 AI 需即時查詢「當前該用多少速度轉彎」，會重複使用同一組函數

`dynamics` 是唯一持有狀態的物理模組。

### 4.3 物理引擎選型

飛行力學完全自寫，不使用剛體物理引擎。理由：空氣動力（升力、誘導阻力、失速、配平）不是碰撞求解器能表達的，套上剛體引擎只會增加一層難以除錯的間接層，且無法達成能量戰所需的力/力矩精確控制。

碰撞在 M1 僅有「飛機 vs 海面」，用高度場比較即可。cannon-es 延後至 M7 有地面載具與爆炸碎片需求時再引入。

## 6. 飛行模型規格

### 6.1 大氣（純函數）

```
對流層 (0–11 km)
  T = 288.15 − 0.0065·h                [K]
  p = 101325 · (T/288.15)^5.2559       [Pa]
  ρ = p / (287.05·T)                   [kg/m³]
  a = √(1.4·287.05·T)                  音速 [m/s]

平流層 (11–20 km)
  T 固定 216.65 K，p 依指數律衰減
  （P-51 升限 12.8 km 會進入此段，不可只實作對流層）
```

### 6.2 氣動力

```
迎角   α = atan2(−v_body.y, −v_body.z)
側滑   β = asin(v_body.x / |V|)
動壓   q = ½ρV²

升力   CL = CL_α · α                          線性段
       α > α_crit 後平滑崩塌至 ~0.6·CL_max
       更大迎角採平板模型 CL = 2·sin α·cos α    （深失速仍具物理意義）
       負迎角對稱處理

阻力   CD = CD0 + CL²/(π·e·AR) + CD_β·β²
       M > M_crit 後 CD0 依馬赫數上升（壓縮性）

側力   CY = CY_β · β
```

**誘導阻力項 `CL²/(π·e·AR)` 是能量戰的物理來源**：拉大迎角 → CL 上升 → 阻力隨 CL 平方暴增 → 速度流失 → 能量流失。此項寫對，能量戰體感自然成立，不需任何額外規則。

**Bf 109 前緣自動縫翼必須建模**：低速時展開，`α_crit` +3.5°、`CL_max` +0.15、失速崩塌斜率變緩。這是 109 低速盤旋優勢的物理來源，而非憑空給予的加成。

### 6.3 力矩與阻尼

```
俯仰   Cm = Cm_0 + Cm_α·α + Cm_q·(q·c/2V) + Cm_δe·δe
滾轉   Cl = Cl_β·β + Cl_p·(p·b/2V) + Cl_δa·δa
偏航   Cn = Cn_β·β + Cn_r·(r·b/2V) + Cn_δr·δr
```

`Cl_p`（滾轉阻尼）決定最大滾轉率；`Cm_q` / `Cn_r` 提供俯仰與偏航的自然阻尼。

**高速舵面變重**（Bf 109 的關鍵弱點，必須建模）：

```
δ_effective = δ_command · min(1, (q_ref / q)^k)
```

P-51 的 `k` 小、Bf 109 的 `k` 大。目標行為：109 在 400 km/h 滾轉率約 80°/s，至 650 km/h 降至約 30°/s；P-51 在 480 km/h 有約 100°/s 且高速衰減平緩。此項做出來，Boom & Zoom 對抗盤旋戰的戰術差異才會成立。

### 6.4 推進

**引擎功率**依增壓器檔位建模：

```
臨界高度以下   P 隨高度線性微升至 P_crit（增壓器維持進氣壓）
臨界高度以上   Gagg-Farrar：P = P_crit · (σ/σ_crit − 0.117) / 0.883
               其中 σ = ρ/ρ₀

P-51D  V-1650-7（兩級兩速）
  低檔   P_sl 1,490 hp    h_crit 1,900 m    P_crit 1,720 hp
  高檔                     h_crit 5,900 m    P_crit 1,370 hp
  取兩條曲線的上包絡，自動換檔

Bf 109 G-6  DB 605A（單級無段變速）
  P_sl 1,475 PS    h_crit 5,700 m    P_crit 1,355 PS
```

P-51 的雙峰功率曲線是其高空優勢來源；Bf 109 在 7,000 m 以上明顯吃力。此差異構成能量戰的高度層次感。

油門範圍 0–100%，100% 以上為 WEP（緊急戰鬥功率）。保留時間限制欄位，M1 不啟用。

**螺旋槳推力**：

```
T = min( η(V) · P / max(V, 1) ,  T_static )
T_static = (2·ρ·A_disk·P²)^(1/3)      動量理論上限，防止 V→0 時推力發散
η(V) = η_max · (1 − exp(−V / V_ref))  低速時效率低
```

螺旋槳扭矩效應與 P-factor 列為選配參數，預設關閉。

### 6.5 積分器

```
狀態   position(vec3, 世界)   velocity(vec3, 世界)
       quaternion             angularVelocity(vec3, 機體)

固定步長 dt = 1/240 s，半隱式 Euler，渲染端對 position / quaternion 內插

每步流程
  1. 世界速度 → 機體速度
  2. 計算 α, β, V, q
  3. aero → 機體座標的力 F_aero 與力矩 M_aero
  4. propulsion → 推力 F_thrust（沿 −Z）
  5. 重力（世界 → 機體）
  6. a_body = (F_aero + F_thrust + F_gravity) / m
  7. 角加速度 = I⁻¹ · (M − ω × I·ω)
  8. 半隱式 Euler：先更新速度，再更新位置
  9. 四元數積分後正規化
```

**選擇 240 Hz 的理由**：氣動力矩剛性高、滾轉率可達 100°/s 以上，100 Hz 在大 G 機動時積分誤差會肉眼可見。M1 僅一架飛機，成本可忽略（約 0.12% CPU）。M5 有 40 架時可降至 120 Hz 或加入子步進。

**240 Hz 是物理步長，與畫面更新率、瀏覽器、螢幕支援無關。** 採用固定步長累加器：

```
每次 requestAnimationFrame：
    accumulator += 實際經過時間（夾在 0.25 s 以內）
    步數 = 0
    while (accumulator >= dt && 步數 < MAX_SUBSTEPS) {
        physicsStep(dt)
        accumulator -= dt
        步數++
    }
    若因步數上限而中止，丟棄剩餘 accumulator
    alpha = accumulator / dt，渲染時內插
```

三項必要保護：

1. **子步上限**（預設 8）：超過即丟棄剩餘時間，遊戲變慢動作但不會卡死（避免 spiral of death）
2. **dt 上限 0.25 s**：切換分頁再切回時 rAF 會給出巨大 dt
3. **步長可設定** 240 / 120 / 60，預設 240；提供「自動降頻」選項（連續 60 幀超出預算則降至 120）

### 6.6 過載

```
n = 機體 Y 軸方向的比力 / g

黑視   持續 > 6G  → 畫面周邊漸暗，> 8G 全黑
紅視   < −3G      → 畫面泛紅，−5G 飽和（起點由 spec 規定，飽和點為實作決定）
結構   P-51 +8 / −4      Bf 109 +7.5 / −3.5
       M1 僅記錄警告，不做結構破壞（無損傷系統）
```

**【M1 實作陷阱】** 黑視起點必須用這裡的 **6G**，不可以沿用 `PILOT_G_POSITIVE = 6.5`——那個常數同時是指揮儀俯仰限制器的過載上限（`control/limiters.ts`），拿它當起點會讓 overG 恆為 0，整套黑視是死碼。以 6G 為起點時，限制器夾住的 6.5G 持續轉彎落在 25% 強度：看得到，還能打。

### 6.7 時間縮放

全域係數 λ 作用於模擬時間（`dt *= λ`）。**預設 1.0（完全史實）**，做成調參面板滑桿。

此為唯一數學上乾淨的節奏縮放方式：所有速度、轉彎率、爬升率、彈道同步變化，機種間的相對關係與能量戰特性零破壞。M1 先以 1.0 實際試飛，之後再決定是否調整。

另有**飛機模型視覺放大係數**（1.0–2.0），純視覺、不影響物理，用於解決真實尺寸飛機在遠距離只有數個像素的可讀性問題。與 λ 各自獨立。

## 8. 操控與飛行指揮儀

### 8.1 輸入層

滑鼠使用 **Pointer Lock API**（準星不能被視窗邊界限制），自行累積 delta 維護準星位置。

```
抽象輸入狀態
  aimWorld   Vector3       瞄準點，世界座標的單位方向
  throttle   0 ~ 1.1       W / S 調整，1.1 = WEP
  lookActive bool          右鍵按住
  lookYaw/lookPitch        自由視角偏移，rad
  viewMode   third | first V 鍵切換
```

**【M1 實作：瞄準點改為世界固定，且不設任何夾制】**（專案負責人兩次裁決）

原規格是「螢幕固定準星 + 半徑 35% 的圓形夾制」。機體固定的螢幕準星在數學上不收斂：純橫向偏移會讓 rollCommand 恆為 ±90°，飛機永遠滾轉而誤差角一步都不減（實測 143°/s 滾轉、8 秒航向只變 3°）。改為**世界固定的方向向量**後會收斂，代價是「維持轉彎必須持續移動滑鼠」。

夾制隨後也全部移除（機首圓錐、畫面矩形、單幀位移上限三道）。三道都是「準星不能離開畫面」的產物，而相機改為跟隨瞄準方向後（§9），準星恆在畫面正中央，該前提不再成立。移除後瞄準點可以指到機身後方，指揮儀因此可能收到接近 180° 的誤差角——那個奇點由指揮儀自己的滾轉遲滯處理（§8.2），本來就在它的規格內。

**代價要記著**：夾制年代「把滑鼠推到底不放」會被夾在圓錐邊界，等於自動維持最大轉彎率。現在沒有那個機制，維持轉彎要把滑鼠推在飛機真的轉得動的速率上（P-51D 250 m/s 拉滿 G 約 26°/s）；推太快瞄準點會直接繞到機身後面。

### 8.2 指揮儀演算法

```
1. 螢幕準星反投影 → 世界空間目標方向 aimDir（單位向量）
2. 機首方向 noseDir = 機體 −Z 轉世界
3. 誤差旋轉 = noseDir → aimDir 的最短弧（軸角），轉入機體座標
4. 決定目標滾轉角
     φ_target = atan2(誤差橫向分量, 誤差垂直分量)
     真實飛機採 Bank-To-Turn：滾轉後拉升降舵，因為升降舵權限遠大於方向舵。
     方向舵僅用於消除側滑（協調轉彎）。
5. 串級 PID
     外環：角度誤差 → 期望角速度
     內環：角速度誤差 → 舵面偏角
     （單層 PID 在高動壓下會震盪，串級才穩定）
6. 限制器作用於「期望角速度」，不作用於舵面
7. 輸出 {aileron, elevator, rudder} ∈ [−1, 1] 送入 dynamics
```

**兩個必要的特例處理**：

- 誤差 < 3° 時停止滾轉修正，改為維持當前滾轉角。否則飛機正對目標時會持續左右滾轉
- 誤差接近 180°（目標在正後方）時滾轉方向數學上不定，加入遲滯鎖定一側

### 8.3 限制器

```
G 限制器
  n_aero    = ½ρV²·S·CL_max / (m·g)       當前速度可產生的最大過載
  n_limit   = min(n_aero, n_structural, n_pilot)
  q_max     = (n_limit · g) / V            期望俯仰率上限

迎角限制器
  α_command ≤ α_crit × 0.95

兩者取更嚴格者
```

**設計意圖（此段定義了能量戰能否成立）**：限制器只防止「玩家把飛機拉到失速」，**不阻止玩家把能量拉光**。

- 低速時 `n_aero` 很小 → `q_max` 很低 → 飛機轉不動 → 玩家親身感受能量不足
- 高速大 G 時限制器完全不介入 → 玩家可盡情拉 G，然後看著速度暴跌
- 滑鼠準星與飛機準星的分離距離，即「飛機跟不上意圖」的視覺化

指揮儀只負責「不要求飛機做做不到的事」，從不硬掰姿態。物理層永遠是唯一的真相。

### 8.4 歸因面板

M1 同時開發物理模型與指揮儀，兩者都未調校，手感不對時需要能歸因。即時數值加滾動曲線，兩排並列：

```
指揮儀側   誤差角 · 目標滾轉角 · 期望 p/q/r · 舵面指令
物理側     實際 p/q/r · α · β · n · V · Ps
限制器     當前作用者（G / α / 無）· 可用最大 G
```

判讀規則：期望角速度與實際角速度差距大 → 氣動或舵面權限問題；期望值本身震盪 → PID 問題。

## 9. 相機

| 模式 | 說明 |
|---|---|
| 第三人稱（預設） | 後上方 12 m / 3 m，**彈簧阻尼跟隨而非剛性綁定**，轉向時相機略微落後。相機看的是**滑鼠瞄準方向**（見下），準星因此釘在畫面正中央 |
| 機首視角（V 切換） | M1 僅顯示機首輪廓與準星。低多邊形機體從內部觀看會穿幫，完整座艙延後至後續里程碑 |
| 自由視角（右鍵按住） | yaw ±160° / pitch ±80°，放開後 0.25 s slerp 回原位，期間飛機指令維持不變 |

FOV 預設 65°，可調 65–90°。

**速度感**是純史實速度下最主要的體感問題。三個手段：相機彈簧阻尼、FOV 隨速度微幅變化（+0–8°，可關閉）、場景參照物（§11）。

### 【M1 實作偏離】

**相機跟隨的是瞄準方向，不是機首方向**（專案負責人裁決）。準星釘在畫面正中央，會漂的變成飛機——指揮儀正在追的誤差角於是直接看得見。原規格的「朝向飛機前方的瞄準點」在機首跟隨模式下只讓準星穩定於中央「區」；改為跟隨瞄準方向後它就在中央「點」。

**相機不隨機體側滾。** 滑鼠位移的旋轉軸取自相機。相機若跟著機體滾，「螢幕右」會跟著坡度轉——持續右移滑鼠 → 加坡度 → 螢幕右軸再轉 → 正回饋成螺旋。坡度靠機體模型與姿態儀呈現。

**相機自己持有上方向量**，逐幀對視線正交化後再以 0.25 s 的時間常數靠回世界上方；接近垂直時凍結目標，只靠正交化把上一幀帶過去。直接拿世界上方去 `lookAt` 在垂直爬升／俯衝會退化——實測單幀翻轉 178.5°，而筋斗每圈經過兩次。

**三個時間常數必須分開**：
- 自由視角**拖曳中** 0.04 s（玩家正在下指令，慢就是延遲）
- 自由視角**放開回正** 0.25 s（相機自己在動，慢一點才順）
- 上方向量回正 0.25 s

自由視角另外**不經過機動彈簧**：彈簧的落後量單獨保留，轉頭的部分瞬間生效。

**彈簧作用在「相對飛機的偏移」而不是世界座標。** 世界座標彈簧對移動目標有穩態誤差 `2ζv/√k`，正比於速度——巡航 160 m/s 下實測相機被拖到 83 m 外（設定值 32），飛機縮成一個點。

**`thirdHeight` 與 `thirdDistance` 必須一起調**：機身在畫面上的下沉量 ≈ `atan(h/d)`。太低垂尾會擋住畫面正中央的準星，太高機身掉出下緣。

**失速抖振已移除**（專案負責人裁決）。§10 的 STALL 字樣、準星轉紅、迎角條滿格已經足夠明顯，相機抖振只是干擾。

**【M1 實作偏離：速度帶／高度帶改為圓形機械儀表】**（專案負責人裁決）
垂直帶是現代噴射機的 HUD 語彙，與二戰座艙對不上。改為指針式圓表並排於姿態儀兩側：空速表 0~800 km/h、指針掃 300°；高度表雙針（長針一圈 1000 m、短針一圈 10000 m）。TAS／馬赫／升降率沒有指針，以文字掛在表名下方。航向帶保留在頂部——真機的羅盤刻度盤本來就是水平展開的帶子。

**【M1 實作偏離：小地圖改為機首朝上】**（專案負責人裁決）
自機符號固定指向畫面上方，轉的是地圖。空戰時腦裡的方位是相對自己的（「他在我兩點鐘」）。補一個沿地圖框邊移動的 `N` 標記維持絕對方位，網格跟著世界座標捲動。

`Ps`（比超量功率，m/s）與 `Es`（比能量，m = h + V²/2g）不是除錯資訊，是**能量戰教學元件**。Ps 正值代表能量累積、負值代表能量流失；大 G 轉彎時會跳至 −40 m/s 等大負值。玩家看得到能量狀態，才學得會能量戰。

**失速警告（無音效，全視覺）**：

- α 接近臨界 → 準星轉警示色 / 紅色 + 迎角條進入紅區
- 進入失速 → `STALL` 警告文字（相機抖振已移除，見 §9）

### 12.3 EM 圖產生器

```

  瞬間轉彎率上限
      n = min( ½ρV²·S·CL_max/(m·g),  n_structural )
      ω = g·√(n²−1) / V

      以二分搜尋求解

  Ps 等高線族   +50 / 0 / −50 / −100 m/s
```

## 13. 測試策略

框架：**Vitest**（Vite 原生整合）。四層測試全部不啟動渲染，可於 node / CI 環境執行。

開發順序遵循 TDD：`L1 → 實作純函數 → L2 → 調參至通過 → L3 → L4 → 實作指揮儀`。

### 13.1 L1 純函數單元測試

```
大氣   ρ(0) = 1.225 · ρ(5000) ≈ 0.7364 · T(11000) = 216.65
氣動   CL(0) = 0 · CL 在 α_crit 達 CL_max · 失速後遞減
引擎   P(0) = P_sl · P(h_crit) = P_crit · P(12000) 大幅衰減
數學   四元數積分、座標轉換往返一致性
```

### 13.2 L2 史實性能測試（誤差 ±5%）

```
極速      定高全油門，跑至加速度 < 0.01 m/s² 時取值
爬升率    全油門，以最佳爬升角配平
失速速度  緩慢減速直至 CL 達 CL_max
升限      持續爬升直至爬升率 < 0.5 m/s
```

驗證目標見 §7.2。此組測試證明氣動、引擎、大氣模型沒有寫錯。

### 13.3 L3 平衡關係測試（相對斷言）

```
P51.Vmax > BF109.Vmax
BF109.climbRate(0m) > P51.climbRate(0m)
P51.Vmax(7600m) − BF109.Vmax(7600m) > 60 km/h
BF109.sustainedTurnRate(300km/h, 0m) > P51.sustainedTurnRate(300km/h, 0m)
P51.rollRate(600km/h) > BF109.rollRate(600km/h) × 1.5
```

此組測試證明兩台飛機的性格沒有跑掉，與絕對數值無關。

### 13.4 L4 指揮儀矩陣測試

```
起始滾轉 {0, 45, 90, 135, 180}° × 目標方位 8 向 × 速度 {200, 400, 600} km/h
= 120 個案例

每案例跑 N 秒後斷言：
  誤差收斂至 < 2° 且不震盪（末 2 秒誤差標準差 < 0.5°）
  全程 α 未超過 α_crit
  全程 |n| 未超過結構極限
  誤差 ≈ 0 時滾轉指令不抖動
```

此組測試能自動抓出「特定角度組合下指揮儀震盪」這類手動試飛極難發現的缺陷。

```
  M0 的微基準會抓到違規（GC 造成的耗時尖峰）

渲染紀律
  flat shading · 共用材質 · 參照物使用 InstancedMesh · M1 無陰影

效能覆蓋層（F3 切換）
  FPS · frame time · 物理步耗時 · draw call · 三角形數
```

此紀律從第一天開始執行，是 M5（40 架飛機）能否達標的前提。

## 17. 後續里程碑的已定案決策

以下決策已在討論中確認，但實作屬於 M2 之後的里程碑。記錄於此以免遺失，各自的 spec 會再展開。

| 項目 | 決策 |
|---|---|
| 音效 | 整個專案暫不做 |
| 損傷模型 | 飛機有總 HP；部位化命中判定，各部位有不同扣血倍率；**不做性能減損**（兼顧遊戲性）。資料結構預留 `effects` 欄位供未來啟用 |
| P-51 翼槍匯聚 | 固定 300 m，不提供玩家調整 |
| 著彈效果 | three.js 粒子，沿命中面法線方向噴射 |
| 難度 1–5 星 | **僅調整敵我數量比**。`DifficultyProfile` 保留完整欄位（反應延遲、瞄準誤差、態勢感知半徑等），全部給王牌等級預設值，供未來調整 |
| 任務類型 | 攔截 / 對地攻擊 / 護送 / 撤離全部延後，待空對空穩定後才開始 |
| 遭遇戰模式 | 先於戰役模式實作 |
| 物理引擎 | cannon-es（非停止維護的 cannon.js），延後至 M7 有地面載具與碎片需求時引入 |
| 編隊單位 | 4 機 Schwarm，由兩個 2 機 Rotte 組成。指揮 AI 對 4 機分隊下令，分隊長可自主拆隊 |
| AI 安全層 | 對地/對海碰撞迴避為可否決上層一切決策的獨立層級，M4 就要建立，為未來地形做準備 |
