## 實作後的偏離與殘留（2026-09-04 收尾時記）

- **commit 拆法**：T1–T3 單獨 commit 時 `menu.ts` 編譯不過（它讀舊的 `playerAt`），拆開會留下
  一個不能編譯的 commit。改成**一筆 commit 收 T1–T9**，T10 的清理另一筆。
- **`onCampaign` hook 沒做**：spec §1 寫「先 `onCampaign(c)` 再 `onEvent('mission')`」，但 `main.ts`
  沒有任何地方需要知道陣營 —— 簡報頁自己記著、`battle.toMission` 回同一條線也是它自己記。
  加一個沒有人讀的 hook 是多的；陣營狀態留在 `menu.ts`。
- **戰報的完整路徑沒有 e2e**：`afterAction()` 要一場打完才跑到。headless 下 `maxSubsteps: 8`
  讓模擬只跑到牆鐘的四成，20 架 P-51 對一架 He 111 跑 300 秒牆鐘都沒結束。
  純函數（`tallyOf`／`playerOf`／`formatDuration`）有單元測試，按住 TAB 的即時看板（`extra = null`）
  在 e2e 裡跑過沒有錯誤；**帶戰報的那一支要靠試飛第一次打完看**。
- **`mission-config-baseline` 重抓**：那份快照沒有上一輪加進 `VETERAN` 的 `fireDelay: 0.1`
  （a69977c 之後沒跑過全套）。用 `mission-config-baseline.probe.ts` 重抓，diff 只有那兩行。
- **效能閘門在負載下假紅**：全套跑時 Playwright 與 vite 都在跑，20v20 與砲塔兩條紅；單獨跑全綠。
  與 `docs/backlog.md` §1.1 的既有紀錄一致。
- **`god-view.e2e.ts` 要用 `vite-node` 跑**（檔頭本來就這樣寫）：用 `tsx` 跑會在 `page.evaluate`
  裡 `__name is not defined`，那是 esbuild 的 keepNames 助手沒被序列化進瀏覽器。不是遊戲的問題。
- **圖片已轉 JPEG**（2026-09-04 追加）：`public/ui/` 五張 PNG 共 6.3 MB → JPEG 0.77 MB，
  PSNR 36.2–46.3 dB。PNG 不留（提示詞在 `docs/ui/PROMPTS.md`，重生一張 40 秒）。**2× 仍是另案。**
- **`backdrop-filter` 沒上**：照 spec §4 先不做；量了再說。
- **`escort-live.e2e.ts` 改指名 `germany-m1`**：它原本量護航 AI，現在量攔截方；檔頭已改。

## 試玩之後的第二輪（2026-09-04，負責人五點）

1. **圖轉 JPEG** —— 見上。
2. **戰報的底變薄**：`#board` 的紗 .70 → .46、`.aar` 改用新的 `--panel-thin`（.74）。
   【為什麼另開一個 token 而不是把 `--panel` 調薄】`--panel` 也是選單面板的底，
   那些面板背後是主選單的天空、不是剛打完的那一幕，兩者要的厚度不一樣。
3. **完整名單置中、而且不預設收合**：`#tables` 加 `justify-content: center`；
   `render()` 每次都把 `<details>` 打開。折疊是給看完的人收起來用的。
4. **`#aar-tally` 改橫的**：三列 a|k|b 的網格 → 一列三組 `.item`，省下約 55 px 高。
5. **戰報不再每幀重建**：結算板一場只畫一次（`aarDrawn`），按住 TAB 的即時看板
   節流到 4 Hz（`BOARD_PERIOD = 0.25`）。順帶修掉一個真的錯：`afterAction()` 的
   用時本來讀當下的 `elapsed`，**分出勝負之後還會繼續往上跳** —— 現在記
   `battleEndedAt` 凍住。
   【headless 量不出來】無 GPU 時戰鬥迴圈只有 2.5 fps（選單迴圈 49 fps），
   節流與不節流在那裡是同一個數字；這一條靠讀碼與試飛。
