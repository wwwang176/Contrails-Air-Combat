# 手感地圖

**這份文件回答一個問題：「想調手感的話，旋鈕在哪裡？」**

寫它的直接原因是 2026-08-20 一次誤判 —— 有人（我）被問到「可以設計飛行手感
了嗎」，憑印象回答「輸入塑形、速度相依舵效、失速預警、G 回饋這四層都沒有」，
**四條全錯，四層都在**。找不到它們不是因為不存在，是因為它們散在六個目錄裡，
而且沒有任何一份文件把它們列在一起。

規則與 `backlog.md` 相同：**每一條都要有出處**（`檔案:行號` 或常數名），否則
下一個人無從判斷它還成不成立。

最後更新：2026-08-20

甲已經調過一輪並裁定過（2026-08-07），乙是**逐項長出來的**、沒有整體設計。

## 1. 包絡：`src/specs/feel.ts`

```
GAME_FEEL   = { roll 1.2, oswald 2, power 1.572, lift 1.3, cd0 1.636, mass 0.8 }
BOMBER_FEEL = { 同上，但 power 與 cd0 同乘 0.70 → 1.100 / 1.145 }
```

**史實值原封不動留在 `specs/*.ts`，遊戲執行時套一層倍率**（`applyFeel`，
`battle/setup.ts` 呼叫，輪廓由 `feelFor(spec)` 依 `spec.role` 挑）。`historical.test.ts` 跑的是**未包裝**的 spec，
所以那層 L2 斷言（極速／失速／升限 ±5%）照樣守著真飛機。

出貨的 P-51D 爬升率是史實的 **2.2 倍**、持續迴旋 **1.9 倍**。
**2026-08-07 專案負責人裁定**：「這個遊戲對於能量太過於寫實了，導致遊戲性
很差」。這是取捨，不是失誤。

**轟炸機為什麼另一組**（2026-08-20）：那六個倍率是 2026-08-07 照兩台戰鬥機
調的，當時專案裡沒有轟炸機。同一組套下去，轟炸機的爬升率變成史實的 2.71×
與 2.94×，比戰鬥機的 1.89× **還多** —— 那是副作用不是設計。只動 `power` 與
`cd0` 而且同乘一個因子，是因為 `V_max³ ∝ power/cd0`：**極速不動，動到的只有
多出來的功率**，也就是爬升與持續迴旋。

```
                爬升倍數      極速 km/h    持續迴旋 °/s（3,000 m）
  He 111      2.71 → 1.81   384 → 383      22.2 → 19.4
  B-17G       2.94 → 2.00   400 → 398      23.3 → 22.5
```

怎麼重新調（耦合順序、以及調完要回頭看什麼）**已經寫在該檔的檔頭**，不重複。

## 2. 玩家怎麼下指令：**不是推桿，是指瞄準點**

`src/input/aim.ts` — 滑鼠位移旋轉一個**世界固定**的瞄準單位向量；
`src/control/FlightDirector.ts` — 指揮儀用 PID 把機首追過去。

**所以「死區／指數曲線／單幀位移上限」這一類推桿塑形在這個模型裡沒有位置。**
三道夾制（機首圓錐、畫面矩形、單幀上限）曾經存在，相機改成跟著瞄準點走之後
**全部移除**（`aim.ts` 檔頭記著理由與裁定）。

延遲與平滑因此落在別的地方：

| 來源 | 值 | 出處 |
|---|---|---|
| 舵面作動速率 | 副翼 5 /s、升降舵 6 /s、方向舵 4 /s | `control/actuator.ts` `DEFAULT_ACTUATOR_RATES` |
| 指揮儀內外環 PID + 遲滯 | 見該檔 | `control/FlightDirector.ts` |
| 油門行程 | 0.6 /s，放手彈簧回中到 0.7 | `input/throttle.ts` `THROTTLE_RATE`／`CRUISE_THROTTLE` |

作動速率的依據：P-51D 飛行員報告「中立到滿副翼約 0.2 秒」。實測沒有它的話，
滑鼠一甩副翼在**單一物理步（4.2 ms）內**由 0 跳到 1.000，等效 240 /s。

## 3. 高速重舵：`spec.controlStiffening`

同樣的舵面偏轉在高速時產生的力矩較小 —— 氣動負載那一側（與第 2 節的作動
速率是**不同的物理成因**，不是重複計算）。

```
             qRef   aileronK  elevatorK  rudderK
  P-51D     10884     0.35      0.25      0.25
  Bf109G6    7560     1.50      0.60      0.40
  He111      4250     1.80      0.90      0.60
  B-17G      4250     2.40      1.10      0.80
```

消費者三處：`physics/aero.ts:243`、`control/FlightDirector.ts:740`、
`analysis/envelope.ts:436`。

**這是機種個性最大的一個旋鈕** —— P-51D 的 0.35 對 B-17G 的 2.4 差了七倍。

## 4. 極限：過載、迎角、前緣縫翼

| 項目 | 值 | 出處 |
|---|---|---|
| 飛行員負 G | −3 | `control/limiters.ts` `PILOT_G_NEGATIVE` |
| 飛行員正 G | 6.5（**已不再硬夾**，見下） | 同上 `PILOT_G_POSITIVE` |
| 迎角餘裕 | 0.95 × `alphaCrit` | 同上 `ALPHA_MARGIN` |
| 俯仰率上限 | `pitchRateLimit(spec, aero, slats, gLoad)` | 同上 |
| 前緣縫翼 | 遲滯開合（`slatDeployAlpha`／`slatRetractAlpha`），開了加 `slatAlphaBonus` | `physics/aero.ts:81` |

**2026-08-11 把正 G 的硬夾拿掉了**，上限改由結構極限決定（P-51D 8 G、
Bf109 7.5 G）。這件事直接牽動第 5 節的黑視門檻。

## 5. 生理回饋：`src/hud/widgets/gEffect.ts`

```
  黑視   7.5 G 起漸暗 → 9.5 G 全黑
  紅視   −3 G 起     → −5 G 飽和
  時間   累積 1.6 s、恢復 2.4 s
```

門檻的定法是**錨在「極限持續轉彎落在 25% 強度」這個意圖上**，不是絕對值：
原始 spec 寫 6/8 是配 6.5 G 的硬夾；硬夾拿掉之後兩個門檻同時 +1.5，於是
8 G 的極限轉彎重新落在 (8−7.5)/(9.5−7.5) = 25%。Bf109 的 7.5 G 落在 0%。

**兩件待裁定的事**（該檔檔頭已記）：

1. 這一組是**起手值**，黑視該不該更兇是專案負責人的裁定。
2. **不對稱** —— 黑視只作用在玩家（它是 HUD widget），AI 拉 8 G 沒有任何
   生理代價。

## 6. 失速預警

| 形式 | 判準 | 出處 |
|---|---|---|
| 準星轉色 | `|alpha| / alphaCrit` > 0.85 警示、> 0.95 危險 | `hud/widgets/reticle.ts:33` |
| 速度讀數轉紅 | 舵面效力低於 `1/1.44`（＝速度掉到 1 G 失速速度） | `hud/widgets/energy.ts` `LOW_SPEED_DANGER` |
| 能量教學讀數 | G／AoA／Ps／Es 四行常駐 | `hud/widgets/energy.ts` |

**沒有的是抖動（buffet）** —— 沒有任何震動、聲音或畫面上的機械式預警，
只有顏色。要不要補是一個開放問題（見 `backlog.md`）。

## 7. 相機：`src/camera/CameraRig.ts`

```
  thirdDistance 12    thirdHeight 3.0
  springStiffness 120  springDamping 1.0
  fovBase 65  fovSpeedGain 8  fovSpeedRef 200     ← FOV 隨速度開
  lookReturnTime 0.25  lookFollowTime 0.04  levelTime 0.25
  aimPointDistance 400
```

**相機不隨機體側滾** —— 瞄準點是世界固定的，相機若跟著滾，「螢幕右」會跟著
坡度轉，持續右移滑鼠就正回饋成螺旋。坡度靠機體模型與姿態儀呈現。

拖曳（0.04 s）與回正（0.25 s）**刻意不同**：回正是相機自己在動，慢一點才順；
拖曳是玩家正在下指令，慢一點就只是延遲。

**沒有的是 G 或撞擊造成的鏡頭抖動。**

## 想調的話，最短路徑

| 想改什麼 | 動哪裡 |
|---|---|
| 轉得太鈍／太靈 | `feel.ts` 的 `lift`（角落速度）與 `roll` |
| 高速像在水裡 | `spec.controlStiffening` 的 `aileronK` |
| 輸入到反應之間有延遲感 | `actuator.ts` 的三個速率 |
| 極限轉彎看不見 | `gEffect.ts` 的兩個門檻 |
| 不知道自己快失速 | 第 6 節 —— 目前只有顏色 |
| 爬升／俯衝的取捨 | `feel.ts` 的 `oswald` ↔ `power` 那一個自由度 |

**每一項都要回頭看 `feel.ts` 檔頭「調完之後必須一起回頭看的東西」那一節**
—— AI 的能量判準寫的是比值，分母是飛機自己的氣動性能，倍率一動它們跟著走；
但「這一次沒壞」不等於「這一層不受影響」。
