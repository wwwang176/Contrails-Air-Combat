# 機種平衡參考紀錄

**這份文件回答兩個問題：「這兩台現在誰強在哪？」與「要加一台新飛機，數字該
往哪裡放？」**

寫它的原因是 2026-08-27 為了回答「兩台的性能對比」而重新量了一次全部包絡 ——
那些數字本來就都在程式裡算得出來，只是沒有人把它們擺在一起看過。

> **2026-08-30 起，下方「量級」與「裁決」兩節已更新，但所有**逐項包絡數字**
> （極速表、爬升表、優勢表）仍是 P-51D 修正前、F6F-5 加入前產生的。要用的話
> 先照下一節重跑一次。

---

## 這份文件**不是**規範

**這裡沒有一個數字是門檻。** 硬性規範只有兩個地方：

| 守什麼 | 在哪裡 |
|---|---|
| 兩台仍然是真飛機（極速／爬升／升限／失速 ±5%） | `test/performance/historical.test.ts` |
| 調參旋鈕不得離開物理界限 | `test/unit/specs.test.ts` |

這份文件的用途是**省下重新量的功夫**，以及讓下一台新飛機有個量級可以對照。
它與程式不一致時，**以程式為準** —— 見下一節。

node node_modules/vite-node/vite-node.mjs test/tools/aircraft-compare.probe.ts

分家，而分家時錯的一定是這份文件。

### 一、兩層要分開看

`specs/*.ts` 是史實層，`specs/feel.ts` 的 `GAME_FEEL` 套上去之後才是玩家飛的
那一台。倍率是 `{roll 1.2, oswald 2, power 1.572, lift 1.3, cd0 1.636, mass 0.8}`，
**對兩台一視同仁**。

因此有一個結構性的事實值得記住：

> **三十幾個項目裡，史實層與遊戲層的勝負欄位沒有一項換手。**
> `GAME_FEEL` 放大絕對值，不扭曲對局。

唯一被壓縮的是**持續迴旋**：史實層 K-4 領先 0.54~0.75°/s，遊戲層只剩約
0.25°/s。成因是 `oswald ×2` 對翼展大的 P-51 幫助較多。

## 判讀 —— 這一段不會過期

數字會變，下面這幾條結構關係是設計出來的，改動它們應該是有意識的裁決。

### K-4 贏的是「進場」

爬升 1.4 倍、低速 Ps 1.4 倍、火力 2.5 倍。**它決定什麼時候打、從哪裡打。**
而且 MK 108 的 DPS 讓它「咬中一次」就足以結束戰鬥。

### P-51D 贏的是「脫離」與「高速」

- **600 km/h 以上 Ps 反超**；700 km/h 時 K-4 的 Ps 是**負的**（撐不住那個速度）
- 650 km/h 滾轉快 **2.25 倍** —— 109 全系列的重副翼弱點，K-4 沒有改善
  （`specs/bf109k4.ts` 的 `aileronK: 1.5`）
- VNE 高 60 km/h
- 8,000 m 以上快 9~26 km/h

### 所以這一版的對局是

> **109 逼你打它要的仗（低速、垂直、纏鬥）；P-51 的活路是不接受 ——
> 把速度拉起來、往高處帶。**

P-51D 唯一的長期優勢（高空速度、高速滾轉）都要求它**先有能量**，而它爬升差
40%。這是刻意的不對稱，不是失衡。

### 一個容易被忽略的乘數

P-51D 的命中盒比 K-4 **大 64%**，而 K-4 的 DPS 是它的 **2.5 倍**。
也就是說「被咬到」對 P-51D 的代價遠高於反過來 —— 兩個效應同向相乘。

### 二、硬界限（`test/unit/specs.test.ts` 會擋）

| 參數 | 允許範圍 |
|---|---|
| 展弦比 AR | > 4 |
| `drag.cd0` | 0.014 ~ 0.035 |
| `wing.oswald` | 0.70 ~ 0.88 |
| `prop.etaMax` | 0.70 ~ 0.90 |
| `prop.figureOfMerit` | 0.50 ~ 0.80 |
| `engine.ramEfficiency` | 0 ~ 1 |
| `prop.vRef` | > 0 |
| 增壓檔的 `altCritical` | 必須遞增 |

另有一條跨機種斷言：`P51D.drag.cd0 < BF109K4.drag.cd0 × 0.8`（層流翼）。

### 三、校準流程 —— 順序很重要

1. **先確認史實表自己對得起來，再開始調係數。**
   把史實表的兩三項各自反解成「這需要多重／多少 `cd0`」，看它們指不指向
   同一個點。工具：`test/tools/reconcile.probe.ts`。
2. **反解要有對照組。** 對另一台已經校準好的飛機做同一次反解。只有新的那台
   聚在一起 → 是它的表混了掛載狀態；兩台都散 → 是模型的通病，別拿減重去補。
3. **失速速度是最有力的一項，因為它完全不吃出力** —— 只有升力除以重量。
   爬升與升限都可能被「模型推力不足」解釋，失速不行。
4. 再依 `specs/feel.ts` 檔頭「怎麼重新調」的順序定手感：極速 → 失速／角速 →
   持續迴旋 → 滾轉。

### 四、加了新機種之後要回頭看的東西

- `test/performance/historical.test.ts` 的 `CASES` —— 新機種守哪幾項？
  對不上的要逐條寫進 `PENDING`，**不要放寬門檻**。
- `test/unit/envelope.test.ts` 的兩機轉彎關係 —— 那些斷言寫死了 P-51 對 K-4。
- `src/ai/rules.ts:349` 的 `turnEnter: -0.02`（rad/s）—— 迴旋劣勢超過這個值
  才會判定不要纏鬥。現行兩台的持續迴旋差最大只有 −0.074，全部在門檻之內，
  所以那條規則對它們等於休眠。新機種可能把它叫醒。
- `test/fixtures/*.ts` 的校驗和 —— 只要動到參與那些場景的機種就會連坐。
  重錄前**雙跑確認逐字相同**。
- `src/specs/feel.ts` 的 `feelFor()` —— 轟炸機走 `BOMBER_FEEL`，靠 `role`
  欄位分流。新機種的 `role` 填錯會靜靜地套到錯的倍率。
