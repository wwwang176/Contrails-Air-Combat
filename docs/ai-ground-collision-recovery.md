# AI 墜地感知、Worker 改出與對地掃射

> 本文件由第二版模型研究報告整理入版控。第 1～8 節記錄模型研發階段，
> 第 9 節記錄玩家試飛後的正式遊戲定案；若階段性描述互相衝突，以第 9 節為準。

## 1. 交付範圍與結論

本輪只修改／新增量測工具與模型，沒有修改 `src/ai/`、`src/control/`、
`src/physics/`、`src/specs/`、`src/analysis/` 或既有測試，也沒有執行 `git add`
或 commit。

第二版已把改出拆成減速、過載／滾轉建立、定速拉平三段，並把正負 G 配額、
縫翼、舵效、俯仰慣量、阻力、怠速推力及滾轉率全部由機種規格與既有函式導出。
全機種共用且唯一擬合的係數為：

- 跟隨係數 `eta = 0.840992`。
- 建立時間倍率 `c1 = 1.14964`。

中央誤差已接近零，但近鉛直／倒飛尾端仍明顯低估，尤其轟炸機；因此本輪數據
不支持直接把模型接進正式安全層。固定餘裕 30／100 m 仍不足以涵蓋全部試驗格。

## 2. 探針修正與資料方法

每個網格包含地面海拔 1000／4000 m、四個速度、八個俯衝角、五個初始坡度、
兩個初始滾轉率，共 640 格／機種。

舊探測機固定放在離地 5000 m，動壓不屬於真正起點，而且尚未步進的
`diag.loadFactor = 0` 會讓 `worstGamma` 虛構更陡的前瞻。現在的處理如下：

1. `setupAircraft` 以場景宣告的初始過載（本量尺為 1 G）初始化
   `diag.loadFactor`，並以真正絕對高度初始化 TAS、動壓與 Mach。初始姿態的
   速度與機首一致，所以 `alpha = beta = 0`。
2. 起點從離地 20 m 開始固定點迭代四次；每次都在「地面海拔＋候選離地高度」
   建機並重算模型線，最後再加 0.3 s 下沉量（至少 5 m）。因此算線和實際起飛
   使用同一高度的大氣。
3. 閉迴路只記錄第一次接管至第一次 `velocity.y >= 0`；觸發時保存完整
   `RecoveryFeatures`、模型預測掉高及實際掉高。離線擬合只反覆呼叫同一支
   `predictFromFeatures`，沒有複製公式。
4. 現行安全層從第二版共同起點與自身觸發線的較高者進場，避免起點改變對地
   瞄準落點而把對照變成不同場景。

少數格在 30 s 內未接管，原因是高預測線令上層指令先自行改出；這些右設限格
不納入分位數或撞地計數。各機種有效／無效格數已列於誤差表。

## 3. 第二版完整公式

以下 `g = 9.80665 m/s²`，下沉角 `theta = -gamma_w >= 0`。

### 3.1 航跡角前瞻

`worstGamma` 與 `applySafety` 相同：

```text
gamma_dot = g [ n_diag (L_hat · c_hat) - cos(gamma) ] / V
gamma_pred = max(-pi/2, gamma + gamma_dot * DEFAULT_SAFETY.lookahead), gamma < 0
gamma_w = min(gamma, gamma_pred)
```

其中 `c_hat` 是世界正上方在速度法平面內的單位向量；來源為
`flightPathRate`，前瞻時間來源為 `DEFAULT_SAFETY.lookahead = 0.25 s`。

### 3.2 角落速度與限制器配額

```text
V1 = min(V0, cornerSpeed(spec, altitude))
Vm = sqrt[(V0² + V1²) / 2]
qbar(V) = rho(altitude) V² / 2

alpha_m = 0.95 alpha_crit + (slats ? slatAlphaBonus : 0)
CL_m = liftCoefficient(spec, alpha_m, slats)
n_aero(V) = qbar(V) S CL_m / (m g)
n_plus(V) = min(n_aero(V), gPositive)
n_minus(V) = |max(-3, gNegative, -n_aero(V))|
n_turn = eta * (push ? n_minus(V1) : n_plus(V1))
```

`0.95` 來源為 `limiters.ALPHA_MARGIN`；`CL_m` 來源為 `liftCoefficient`。起始
正／負配額採當下 `diag.slatsDeployed`，拉平天花板則在機種有縫翼時採展開後
的迎角，因為高迎角段會展開縫翼。正 G 上限和 `pitchRateLimit` 一樣只夾
`limits.gPositive`；負 G 取 `limits.gNegative`、飛行員 −3 G 與氣動能力中最
嚴格者。Bf 109 因而在建立判準使用未展開配額，拉平使用展開後天花板。

### 3.3 推頭或翻轉與改出航向

先用 `DEFAULT_SAFETY.recoveryPitch`（20°）和撞地接管航向建立世界瞄準向量，
轉到機體座標 `(x, y, z)`：

```text
error = atan2(hypot(x, y), -z)
roll_pull = atan2(x, y)
roll_push = atan2(x, -y)

g_load = gLoadFromOrientation(orientation)
q_max = max[g(n_plus(V0) - g_load)/V0, QMAX_FLOOR]
q_min = min[g(-n_minus(V0) - g_load)/V0, -QMAX_FLOOR]
p_ss = maxRollRate(spec, altitude, V0)

t_pull_choice = (|roll_pull| - |roll_push|)/p_ss + error/q_max
t_push_choice = error/|q_min|
push = (y < 0) and t_push_choice <= 0.85 t_pull_choice
```

時間比較與 `FlightDirector.rollOrPush` 相同；`0.85 = 1 - pushHysteresis` 是從
非推頭狀態進入推頭狀態的同一遲滯邊界。選拉／翻時支付
`t_roll = |roll_pull|/p_ss`；選推時 `t_roll = 0`，並以負 G 配額計算後續曲率。
`p_ss` 與 `steadyRollRate` 使用相同的副翼舵效、紅線舵效、`clDa/clP`、TAS
與翼展算法（工具層呼叫等價的 `maxRollRate`）。

`roll_pull` 的參考瞄準向量來自撞地接管實際航向，不是世界正上方，所以近
鉛直時仍與指揮儀看到的目標一致。

### 3.4 過載建立時間

中段升降舵有效率與物理層一致：

```text
e_e = lowSpeedEffectiveness(spec, qbar_m)
    * redlinePitchEffectiveness(vne, qbar_m)
    * controlEffectiveness(elevatorK, qRef, qbar_m)

q_ddot_e = qbar_m S c |cmDe| e_e / I_pitch
```

本網格的 IAS／VNE 約 0.75–0.83 時，紅線項等於 1，真正降低舵效的是
`controlEffectiveness`；公式仍保留低速與紅線項，才能和正式物理在其他速度
一致。

`q_target = g(n_signed - g_load)/V1`，其中推頭時 `n_signed = -n_turn`。沿所選
方向尚缺的角速度為：

```text
Delta q = max(0, q_target - q_now)          （拉）
Delta q = max(0, q_now - q_target)          （推）
```

迎角行程 `Delta alpha` 從當下 `diag.aero.alpha` 到所選方向的
`alpha_m`；`q_turn` 是 V1 處相同正／負限制器公式給出的俯仰率配額。建立時間：

```text
t_build = c1 [ Delta alpha / max(|q_turn|, QMAX_FLOOR)
             + Delta q / q_ddot_e ]
t_ready = max(t_build, t_roll)
```

第一項是以限制器容許俯仰率走完迎角行程，第二項是以升降舵力矩建立該俯仰率。
這補上低速格中「角速度力矩很大，但 qMax 很小、仍要很久才到限制迎角」的實測
缺口。過載從觸發瞬間的 `diag.loadFactor` 及其垂直投影線性建立到 `n_turn`，
不是從 1 G 假設起跑。

### 3.5 減速段

僅在 `V0 > V1` 時存在。以 `Vm` 的動壓、Mach 與怠速推力計算：

```text
D_0+brake = qbar_m S * dragCoefficient(spec, 0, 0, Mach_m, brake=1)
k_i = inducedDragFactor(spec)
D_i = k_i (m g)² <n²> / (qbar_m S)
T_floor = thrustAt(spec, altitude, Vm, THROTTLE_FLOOR)

a = (D_0+brake + D_i - T_floor)/m - g sin(theta)
t_decel = (V0 - V1) / max(a, 0.1)
```

`dragCoefficient` 提供零升／壓縮阻力及 `BRAKE_CD = 0.45`，誘導阻力係數由
`inducedDragFactor` 提供，推力由 `thrustAt` 以 `THROTTLE_FLOOR = 0.2` 計算。
`<n²>` 是實際起始過載至有號 `n_turn` 的線性建立過程均方值；先以完整建立
均方值估一次 `t_decel`，再以該時間涵蓋的實際建立比例重算一次。重力沿俯衝
方向抵銷減速，因此是減去 `g sin(theta)`。低於角落速度時 `t_decel = 0`。

減速、迎角建立與滾轉同時進行，沒有把三段時間直接相加。每段採平均垂直過載
`n_v_bar`，用與 `flightPathRate` 相同的關係更新航跡角：

```text
omega_gamma = g (n_v_bar - cos(gamma)) / V_bar
gamma_1 = gamma_0 + omega_gamma Delta t
Delta h = V_bar [cos(gamma_1) - cos(gamma_0)] / omega_gamma
```

`omega_gamma` 接近零時取極限 `Delta h = -V_bar sin(gamma) Delta t`。航跡角向下
到 −90° 後，剩餘時間按垂直下落計；到 0° 後不再增加掉高。先積分減速時間，
若 `t_ready > t_decel`，再以 V1 積分尚未被減速覆蓋的建立時間。

### 3.6 拉平段與總高度

建立完成後速度為 V1、有效過載為 `n_turn`，剩餘掉高直接使用正式安全層的
閉式解：

```text
h_arc = recoveryAltitude(V1, gamma_after_build, n_turn)
h_required = h_decel_and_build + h_arc
```

`recoveryAltitude` 在能力足夠時使用單段定過載圓弧；能力不足時先以能量換速度
至解析最佳過載 `n*` 再拉平。第二版不含固定餘裕；呼叫端另加戰鬥機 30 m、
轟炸機 100 m。

## 6. 近鉛直升力方向變體

變體只在速度水平分量小於 TAS 的 25%（約 `|gamma| > 75.5°`）時，以升力方向
的水平投影取代速度水平投影；其他姿態沿用現行航向。25% 是試驗定義，用來把
變更限制在水平航向開始病態的近鉛直區，不是機種係數。模型和實際改出指令都
使用同一方向；沒有修改 `src/ai/safety.ts`。

## 7. 仍然對不上的地方與原因

1. **近鉛直／倒飛是主要低估尾端。** B-17G 最低誤差 −252.6 m 位於
   4000 m、115 m/s、−89°、倒飛；He 111 與 G4M 最低也在 −89°／−75°、
   135°／180°坡度。交辦書的逐格追蹤已直接量到 B-17 最差格接管後 3.5 s
   尚未開始拉。模型只用接管瞬間的 `rollOrPush` 時間比較和穩態滾轉率，沒有
   表示指揮儀的反轉死區、PID 狀態與拉／滾同時進行時的瞬態耦合；這與尾端
   集中位置一致。
2. **建立模型修正了天花板，但尚未完整描述低速瞬態。** 新增
   `Delta alpha/q_turn` 後，P-51D 訂參數資料有效格由先前試算的 637 增至 639，
   擬合 `c1` 也由直接力矩模型需要的約 130 降到 1.15，證明漏掉迎角行程是
   真的物理缺項。最終戰鬥機 5% 誤差仍為 −30.8 至 −53.7 m，表示單一線性
   建立段仍不能重現作動器、PID、氣動阻尼與速度向量轉動的完整二階響應。
3. **Bf 109 的縫翼處理方向正確但尾端未消失。** 模型在選擇／建立時使用
   當下未展開配額，在拉平天花板使用展開後 `CL_m`；其中位誤差 −4.3 m，
   但 5% 仍為 −53.7 m。證據支持「天花板正確、建立瞬態仍缺」而不是替
   Bf 109 改 `eta`。
4. **轟炸機同時存在很大的正負尾端。** B-17G 5% 為 −191.5 m、95% 為
   +419.2 m；He 111 為 −125.3／+214.3 m；G4M 為 −113.8／+304.2 m。
   這不是把一個共用係數上下移即可修正。**推測：** 線性垂直過載建立與單點
   中段阻力近似在長達數秒的轟炸機改出中太粗，尤其當航跡角、動壓、推／拉
   模式在段內切換時；需要逐時段的狀態模型或再找可解析的瞬態物理量驗證。
5. **30 s 未觸發格是右設限資料。** 最終無效格為 P-51 2、A6M5 2、F4F-4 4、
   F6F-5 4、Ki-84 2、B-17 13、He 111 11、G4M 6，Bf 109 為 0。其共同機制
   是初始預測線較高時，上層對地瞄準在接管前已把飛機帶離下降狀態；不能把
   「未接管」當成模型誤差 0，也不能當成撞地。

## 9. 後續正式接入、玩家試飛與定案（2026-09-14）

本節記錄交付第 1～8 節後，依玩家逐輪試飛回饋完成的正式遊戲接入；若與前文
「只做工具、尚未接入」的階段性敘述衝突，以本節為準。更完整的逐輪量測與決策
紀錄另見同目錄的 `recovery-rollout-report.md`。

### 9.1 正式架構

- 正式 AI 以**單一 Web Worker** 依序服務所有飛機；每架最多 4 Hz 派送一次預演，
  Worker 內以正式飛行物理做 60 Hz 子步，戰鬥機／轟炸機最長前瞻分別為 11／17 秒。
- Worker 回傳「若現在立刻改出，還會掉多少高度」；戰鬥機加 30 m、轟炸機加
  100 m 的角色餘裕。前瞻時間只是搜尋碰地與完成改出的範圍，不代表看到 11／17 秒後
  可能碰地就立刻拉起。
- 遊戲不再以主執行緒的簡化模型取代 Worker。Worker 建立或執行失敗時阻擋遊戲並顯示
  錯誤，避免在玩家不知情時失去防墜能力。
- `tools/recovery.html` 已換成同一套正式 rollout 引擎；展示工具與遊戲不再各自維護
  不同的預測公式。

### 9.2 定案的飛行邏輯

- 移除舊的固定 500 m 空戰高度限制，也移除會持續抬高瞄準線的「柔性高度」偏置。
  AI 在有射擊解時可持續俯衝；只有跨過 Worker 算出的立即改出線才由硬防墜接管。
- 對地掃射的硬改出完成後，不立即把俯衝權交回攻擊 AI。系統先以淺 6° 補高或水平
  捕獲穩住航跡，再把原本想執行的向下命令送入 Worker 做 0.5 秒影子試飛；連續安全
  0.5 秒才解除接管。這個釋放閘門只作用於對地掃射，不污染空戰、反艦或轟炸路徑。
- 飛越地面目標後採動態離場／再進場距離：依本機速度、轉彎能力、目標相對位置與
  攻擊幾何估算需要的航程，先拉開再轉回，而非近距原地繞圈。此幾何邏輯是各機種與
  各地面目標共用；機種差異來自物理能力。
- 德國第三個可玩任務（資料 id `germany-m4`）額外指定停放／滑行中的 P-51 為優先
  地面目標。關卡只提供目標資料，AI 核心仍走共用對地掃射行為；遭到直接空中威脅時
  仍可先自衛。
- HUD 意圖把主要階段與防墜覆寫分開呈現，例如「對地進場（防墜驗證）」、
  「對地射擊」、「對地離場（防墜補高）」，避免把戰術目的與安全接管混成同一狀態。

### 9.3 測試方式與結果

測試分層以快速、可決定的最小契約作合併門檻：`npm test` 只跑 unit／control／balance；
跨模組案例由 `npm run test:integration` 依修改範圍選跑。真瀏覽器只保留 Worker 必需能力
與阻擋畫面的短 E2E。20 對 20 效能與 75 秒任務試飛分別保留為
`test/tools/recovery-worker-perf.probe.ts`、`test/tools/recovery-risk-smoke.probe.ts`，只作人工
量測與設計證據，不納入自動合併門檻。

- Worker 元件單元測試直接呼叫 `RecoveryWorkerEngine`；整合測試使用同步測試 port
  呼叫同一引擎，不建立假的瀏覽器執行緒，也沒有繞過正式算法。
- 相關核心測試 289／289 通過；AI 機動測試 7 通過、1 個既有 skip。六個場景的硬安全
  接管率依序為 1.25%、0%、1.67%、0.92%、0%、0.67%，全部低於 5% 護欄。
- 全部 integration 首輪為 698 通過、10 skip、2 失敗；兩個失敗都是測試環境沒有
  Worker。接上同步引擎 test port 後，兩項針對性重跑均通過。
- 全部 unit／control／balance／performance（排除凍結回放）首輪為 4323 通過、
  8 skip、3 失敗；其中兩項為微基準單次雜訊，隔離重跑 7／7 通過（20v20 為
  514 us，門檻 900 us），另一項地形測試在配合 30 m 新餘裕修正起始高度後 12／12
  通過。沒有降低門檻或新增 skip。
- `npx vite build` 通過（277 modules，包含 Worker bundle 與
  `dist/tools/recovery.html`）。`npx tsc --noEmit --pretty false` 前後都是 24 個既有錯誤，
  沒有新增本次修改檔案的錯誤。
- 真瀏覽器 20 對 20、Worker 開啟：平均 62.1 FPS、1% low 35.6、p99 25.0 ms、
  最長幀 31.7 ms、long task 0；完成 79／79、失敗 0、結尾無排隊，因此維持每架 4 Hz。
- 德 M3 最終有效的 75 秒試飛：玩家 Bf 109 存活，最低高度 28.3 m；Worker 完成
  443 次、失敗 0、過期 1，並觀察到完成改出後成功釋放、重新下壓進場。之後只修改
  測試介面及把釋放狀態限縮到對地掃射；最近一次無頭瀏覽器因 rAF 嚴重節流，180 秒
  牆鐘只前進 10.2 秒物理時間，期間無頁面錯誤，故不把該次逾時冒充完整驗收。
