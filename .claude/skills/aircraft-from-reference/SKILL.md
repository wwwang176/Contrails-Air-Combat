# 依參考模型建立飛機外型

**核心原則：能量的就不要用眼睛判斷。** 這套流程是在 Bf 109 E-4、P-51D、
He 111 H-6 上一路踩坑試出來的；每一條「坑」後面的數字都是實測值，不是推測。

## 為什麼需要這套流程

在導入參考模型之前，外型是靠「看照片 → 調數字 → 截圖 → 再調」的循環做的。
那個循環有一個致命盲點：**它只會收斂到你在看的那個視圖**。

實際發生的事：兩台飛機的側視剖面都調到與參考模型差 ±0.03 m，看起來完美，
但機身**寬度**同時錯了 13–18%（Bf 109 尾錐錯 41%）。因為十幾輪都在看側視圖，
沒有人量過俯視圖。

> 只要你還在用眼睛比對，你只會修正你正在看的那一個維度。

He 111 補上了同一句話的另一半。它的量測全部做對了，卻在機腹連錯六次——
因為那一塊的**前提**（「整塊凸起都是玻璃」）是從照片讀來的，從來沒有進過
任何一張量測表。

> 沒有進過量測表的假設，不會被任何一輪修正檢查到。

## 流程

### 第 0 步：把參考模型放進 `ref/`

`ref/` 已列入 `.gitignore`。參考模型**只當量尺**，不進版控、不進打包。

### 第 1 步：對齊（最容易錯，錯了後面全錯）

對齊參數寫在 `src/tools/hangar.ts` 的 `REFS` 表，一機一筆：

```ts
const REFS: Record<string, RefSpec> = {
  p51d:    { url: '/ref/p51d.glb',      yaw: 180, pitch: -14.0 },
  bf109g6: { url: '/ref/bf109e4.glb',   yaw: 180, pitch: 0 },
  he111:   { url: '/ref/he_111-h6.glb', yaw: -90, pitch: 2.4 },
}
```

| 欄位 | 用途 |
| --- | --- |
| `url` | GLB 路徑 |
| `yaw` | 繞 Y 轉正的角度（度）。180 = 機首朝 +Z 要轉半圈；±90 = 長度軸原本在 X |
| `pitch` | 繞世界 X 軸轉正的角度（度），求法見坑 2 |

**`yaw` 的正負要實證，不要憑算的。** He 111 那台的長度在 X、機首朝 −X，
憑推理寫成 +90，套下去機首朝 +Z。轉正後的驗收有三條，三條都要對：
機首在 −Z、翼展落在 X 且幅度等於真機翼展、水平尾翼落在機身尾端那一段 Z。

機庫面板上勾「參考模型」才會下載（兩個檔加起來 50 MB），切換機種會自動換
對應的那一份。「實體」按鈕切換不透明材質——疊圖用的平塗只保留輪廓，要判讀
**輪廓以內**的特徵（例如玻璃的分界線在哪）就得先看得見它本來的樣子。

外部工具（Playwright）用 `__hangarRef(on, solid)` 開啟；它回傳是否已就緒，
可以輪詢而不是硬等下載。

**這三個值是量出來的定值，不要做成每次輸入的旋鈕。** 打錯很難發現——實測
P-51D 用 −9.5° 時剪影上看起來已經差不多平了，正確值卻是 −14.0°。

**縮放基準是翼展，不是全長。** 這是本流程最重要的一條（見坑 1）。

### 第 2 步：三軸切片量測

`src/tools/sliceRef.ts`，機庫的 `__hangarSlice`。一組切面只描述得了一種零件，
所以三根軸都要切：

**一次量完所有零件，不要分批。** 機身、機翼、尾翼、座艙、進氣口全部在同一
個對齊座標系裡量出來，最後才整體平移一次。分批量的代價見坑 16——每個零件
自己都對，彼此的關係錯 0.85 m，而且側視疊圖看不出來。

```js
// 機身橫剖：由軸心往外射線，取最外側交點
window.__hangarSlice('radial', 'z',
  { from: -2.3, to: 6.16, count: 44, angles: 72, axisV: 0.24, maxRadius: 0.95 })

// 機翼縱剖：z 幅度是弦長、y 幅度是厚度
window.__hangarSlice('extent', 'x', { from: 0.2, to: 5.2, count: 26 })

// 平面形：x 幅度是翼展、每個 x 的 z 幅度是弦長
window.__hangarSlice('extent', 'y', { from: -0.6, to: 0.4, count: 11 })

// 水平尾翼：uWindow 限住 z，才不會跟主翼混在一起
window.__hangarSlice('extent', 'x', { from: 0.1, to: 2.4, count: 24, uWindow: [2.5, 6.2] })

// 垂尾／背鰭：極大 maxRadius，只讀正上方那一條射線 → 側視上緣線
window.__hangarSlice('radial', 'z',
  { from: 2.6, to: 6.0, count: 35, angles: 72, axisV: 0.05, maxRadius: 3.2 })

// 座艙罩：把射線原點放進罩子裡，機身就干擾不到
window.__hangarSlice('radial', 'z',
  { from: -1.3, to: 2.3, count: 37, angles: 72, axisV: 0.72, maxRadius: 0.55 })
```

座艙罩那一招是這輪才試出來的：**換一個射線原點，就能把被擋住的東西單獨
量出來**。從機身軸心往上射只會量到罩頂一個數字，把原點抬進罩子內部，側剖
面一起有了——P-51D 的 `roundness 2.0` 是這樣量出來的，不是調出來的。

垂尾那一招則是反過來：`maxRadius` 開到 3.2 之後，正上方那一條射線掃出來
就是整條**側視上緣線**，背鰭起點、垂尾前緣轉折、頂端高度、方向舵後緣一次
到位，不必分別去猜每個零件的邊界。

配套的開發用出口：

| Hook | 用途 |
| --- | --- |
| `__hangarSlice(kind, axis, opt, 'mine')` | 第四個參數切自家模型，量測與驗收共用同一支切片器 |
| `__hangarSlice(k, a, opt, target, only)` | 第五個參數是 mesh 名稱的 RegExp——**分別打蒙皮與玻璃**就能量出哪裡是窗（見第 5b 步） |
| `__hangarRef(on, solid)` | 開關參考模型，回傳是否已載入完成（可輪詢） |
| `__hangarSpec(id)` | 切換機種，免得腳本去點 DOM |
| `__hangarRefPitch(deg\|null)` | 暫時覆寫俯仰角，掃描專用；null 回到 REFS 定值 |
| `__hangarInfo()` | metrics、三角形數，以及**正交相機的像素換算** |
| `__hangarShow(mine, ref)` | 分別開關兩個模型，抽純剪影用 |
| `__hangarOrtho(view)` / `__hangarCam(x,y,z)` | 視角 |

`__hangarInfo().ortho` 給的是 `{ mPerPx, center, right, up }`，像素換世界座標
直接套：

```
world = center + right·(px − W/2)·mPerPx + up·(H/2 − py)·mPerPx
```

**不要再自己手推這個換算。** 先前在腳本裡推過至少四次，錯過一次——第一版的
百分比表整個左右顛倒，機首機尾對調。相機自己知道答案。

### 第 3 步：擬合與清洗

把每一刀的 `r(θ)` 擬合成超橢圓**五參數** `(a, cy, bUp, bDn, n)`——半寬、
**最寬處的高度**、上下半高、指數：

```
|x / a|^n + |(y − cy) / b|^n = 1        b = bUp（y > cy）或 bDn
殘差 = |P − 中心| − r_model(該點的極角)
```

`cy` 是第五個參數而不是固定在射線原點上：機尾剖面的最寬處明顯偏低（P-51D
實測 −0.19～−0.22），四參數版本會硬把它撐回原點高度，`a` 因此偏小、上下
半高偏大。

用**單邊修剪**反覆擬合：污染一律讓半徑偏大，所以每輪丟掉「量到的比模型大
超過門檻」的點。收斂後殘差 RMS 應在 0.010–0.023 m；明顯更大就是該站位不可信。

**只有 `a`、`cy`、`n` 用擬合值。背線與腹線要取正上方／正下方那一條射線**
——單一指數的超橢圓配不上「上圓下平」的真機剖面，擬合會把頂點往下拉，實測
Bf 109 因此整段低 0.05–0.10 m（見坑 20）。射線是直接量測，沒有這個問題。

### 第 4 步：烘焙成顯式頂點

輸出 `<機種>.hull.ts`，每站一圈半剖面（只存右半，左半鏡像）。
**站位要密**（見坑 7），並做兩輪 **z 不等距的拉普拉斯平滑**：把每一站往
「前後兩站在該 z 的連線」拉 λ = 0.5。

**不要用等權的 `[.25, .5, .25]`。** 站距不等距時等權濾波會把密集區壓扁；
Bf 109 的站距差到 4 倍（0.105～0.400）。兩輪就夠，位移約 11 mm——在擬合
自己的殘差之內，再多輪只增加位移、不再減少漣漪（見坑 19）。

另一種同樣有效的做法是**先把 `a(z)`、背線、腹線寫成錨點曲線再取樣**，讓
平滑發生在曲線上而不是烘好的頂點上。P-51D 是這樣做的，漣漪明顯比 109 少。

### 第 5 步：挖座艙、補內裝、蓋玻璃

`buildHull(rings, cut)` / `buildCockpitTub(...)` / `buildCanopy(...)`，
三者共用同一組環（先呼叫 `prepareRings` 把玻璃站位補進去）。

### 第 5b 步：透明件、凹槽與掛在外面的零件

He 111 是第一台**玻璃比蒙皮還多**的機種——全玻璃機首、機背罩、兩塊側窗、
機腹吊艙的前後兩片窗，外加兩具發動機艙的上下進氣口。P-51D 與 Bf 109 只有
一個座艙罩，整段碰不到；這一節整段是 He 111 教出來的。

**（1）先問「那裡到底是不是玻璃」，再問「暗色要怎麼補」**

按 **mesh 名稱**分別打同一組射線，就能逐站位、逐角度量出**最外側那一片是
蒙皮還是玻璃**。射線原點放進零件自己的剖面中心（與座艙罩那一招同源）：

```js
// 吊艙的剖面中心在 y = −0.75，maxRadius 收到剛好包住它
const o = { from: 2.4, to: 5.6, count: 17, angles: 72, axisV: -0.75, maxRadius: 1.0 }
await __hangarSlice('radial', 'z', o, undefined, 'hull')     // 蒙皮
await __hangarSlice('radial', 'z', o, undefined, 'windows')  // 玻璃
```

同一格兩者都打到就比誰在外面。實測 He 111 的機腹吊艙：

```
  機體Z      190°  215°  245°  270°  295°  325°  350°
 2.51…2.61    蒙    蒙    蒙    蒙    蒙    蒙    蒙
 2.71…3.21    蒙    玻    玻    玻    玻    玻    蒙    ← 前窗
 3.31…4.41    蒙    蒙    蒙    蒙    蒙    蒙    蒙    ← 中間是金屬
 4.51…5.51    玻    玻    玻    玻    玻    玻    玻    ← 後窗
```

**這張表照片讀不出來。** 照片上那一整塊凸起看起來就是一片玻璃罩，實際上是
金屬艙加前後兩片窗。走錯前提的代價見坑 22。

**（2）一個零件一串截面**

`buildFuselage` 是**整圈一起縮放**的。He 111 的發動機艙第一版把「圓錐 + 上
進氣罩 + 下進氣罩」壓進同一串截面，於是下緣該掉的那一步把上緣也憑空抬了
**0.045**——單獨看每一項都調得動，湊在一起怎麼調都不對。

**判準：兩個特徵在同一串截面上會不會互相牽動？** 會就拆。拆完各自量得到的
極值直接寫進註解，日後才知道那一串是照什麼配的。

**（3）凹槽有三個要件，缺一個就只是「一塊暗色的東西」**

| 要件 | 做法 |
| --- | --- |
| 有開口 | `caps: { front: false }`——封了就是一片平板塞子 |
| 壁朝內 | 從凹槽裡看得到，所以要嘛反纏繞、要嘛雙面材質 |
| 壁接到緣 | 內壁比罩口**大** 2%，不是小一號塞在裡面 |

四種錯法與各自的症狀見坑 23。**「凹陷」與「隆起」是同一組頂點加不同的正負
號，但視覺上是兩個東西**——第一版的機背襯裡是「玻璃那幾片往內縮 0.84」，
而機背玻璃是個隆起的罩子，襯裡於是也是個隆起。正確做法是取那一段補丁的
**弦**（`hull.ts` 的 `lidAt`）。

**（4）角度區間的殼**

`buildFuselage(sections, segments, roundness, caps, arc)` 的 `arc` 只吐該角度
範圍的側面，**給了角度就不封口**——開口的殼沒有端面可言。

兩個用途：

- **只畫看得到的那一面。** 內襯只需要朝外的那半圈，畫整圈是白花三角形，而且
  另外半圈會從縫裡露出來。
- **與玻璃互補的蒙皮。** 區間可以超過 360° 繞回去：玻璃 `216…324`，蒙皮寫成
  `324…576`，兩者逐格互補、既沒有縫也不會 z-fighting。

配 `bolaSeg(z0, z1, { scale, arc, caps })` 這種「從**同一組截面**切出子段」的
小工具，七個零件不會各自漂開。

**（5）分段數要讓量到的角度落在格線上**

`arc` 的兩端會被取整到頂點索引。吊艙原本 14 段（一格 25.7°），量到的
215°…325° 被吃成 231°…308°——窗子憑空縮了 40%。改 20 段（一格 18°）之後
216°…324° 剛好落在格線上。

這是坑 12「方正與否取決於分段數」的另一面：**分段數同時決定你切得出哪些
角度。** 先量，再挑一個能整除量測值的段數。

### 第 6 步：驗收

正交側視 + 俯視疊圖，**兩個都要看**。再跑一次數值比對表（半寬、背線、腹線
逐站對照）。眼睛看疊圖抓大方向，數字抓 0.02–0.05 這一級的偏差。

**數值比對要用 `__hangarSlice(..., 'mine')` 對切，不要在疊圖上量像素。**
實測過一次：疊圖上背鰭看起來浮出參考模型 0.23 m，用同一支切片器對切之後
逐站差只有 0.008–0.020——那 0.23 是**水平尾翼擋在前面**造成的錯覺。疊圖裡
離鏡頭近的零件會遮住參考模型，遮出來的邊界看起來就像自家模型的輪廓。

（自家模型平常在自動旋轉，切片用世界座標。`__hangarSlice` 已經在切之前
歸零並停轉——不歸零會量到一個斜著的機身，而且數字看起來完全正常。）

**形狀對了不等於算圖對了。** 疊圖與切片抓的是輪廓，抓不到「從機首看穿到
機尾」「支架從背面是透明的」「凹槽變成一張黑貼紙」這一類缺陷——它們在剪影
上完全不存在。**實體算圖要另外看一輪**，而且要看六個方向（正／側／俯／仰／
前下／後下），透明件與凹槽的缺陷幾乎都只在其中一兩個角度露出來。

He 111 的十五條缺陷裡有九條是這樣抓到的。用 `__hangarCam(x,y,z,tx,ty,tz)`
（它順手把自動旋轉關掉）寫一支 Playwright 截圖腳本，一次抽完六個角度。

## 坑

### 1. 縮放基準用全長 → 整台小 2–4%

全長被螺旋槳與姿態污染。實測依全長縮放後：

| | 縮放後翼展 | 真機 | 誤差 |
| --- | --- | --- | --- |
| Bf 109 E-4 | 9.481 | 9.87 | −4.0% |
| P-51D | 11.030 | 11.286 | −2.3% |

**改用翼展**：兩台都對上（9.865、11.246），P-51D 的全長也回到 9.841 對 9.83。
翼尖是乾淨的基準——±X 的極端點必然是翼尖，沒有起落架、螺旋槳、天線。

在這條修好之前做的所有疊圖比對，結論都帶著這個誤差。

### 2. 參考模型不保證是飛行姿態

P-51D 那個模型是**三點著陸姿態**、起落架放下，整台機首朝上 **14°**。
直接疊圖會讀成「機身前段太低、後段太高」——那 1.1 m 的落差全部來自姿態。

**先看一張側視再相信任何垂直方向的比對。** 用 `REFS[id].pitch` 轉正。

**不要用剪影目測估這個角度。** 第一次憑側視疊圖估成 −9.5°，實際是 −14.0°，
差了 4.5°——而剪影上看起來已經「差不多平了」。正確做法是**掃描**：

1. 取兩個**長基線**且**乾淨**的縱向基準：整流罩軸心（`|x|<0.14` 的上下中點，
   就是推力線）與機尾中心線（`|x|<0.12`，避開座艙罩、散熱器、尾輪的 z 區間）。
2. 對每個候選 pitch 量「參考值 − 本模型值」在這兩處的差，算殘餘俯仰角
   `atan((機首差 − 機尾差) / Δz)`。
3. 殘餘角過零的那個值就是答案。實測非常線性，四五個點就夠：

```
 pitch   機首差   機尾差   殘餘俯仰
  −8.0   +0.727   +0.033    +5.73°
 −11.0   +0.540   +0.205    +2.76°
 −14.0   +0.354   +0.378    −0.20°   ← 過零
 −17.0   +0.165   +0.535    −3.05°
 −20.0   −0.024   +0.697    −5.96°
```

**驗收：轉正之後機翼中線應該整段吻合。** 實測 P-51D 在 −14° 時，13 個翼展
站位的差全部在 ±0.015 m 內，上反角 4.78° 對 5.00°——這是「姿態對了」最強的
證據，因為機翼橫跨整個翼展，角度只要差一點就會在翼尖放大。

**轉正之後還剩下的常數差就不是姿態，是真的外型不同。**

### 2b. 垂直基準用機首尖端（推力線），不要用翼尖

同一個 0.37 m 落差，基準不同會落在不同零件上——**基準只決定你會怪誰**：

| 基準 | 機首軸心 | 機尾中心線 | 機翼 |
| --- | --- | --- | --- |
| 翼尖 | +0.354 | +0.378 | ±0.015 |
| **機首** | **+0.001** | **+0.025** | **−0.36** |

用機首當基準，機身從頭到尾吻合到 0.025 m——那是橫跨 7 m、幾十個獨立站位
的一致性，比「機翼是一條直線對上另一條直線」強得多。結論因此明確：機身是
對的，**機翼掛太高了 0.36 m**。

翼尖的平均高度取決於上反角、翼尖形狀、取樣視窗取多寬，三件事在兩個模型上
都不一樣；機首尖端是**一個點**，而且 Z 向本來就拿它對齊。

### 2c. 世界座標的快取會在模型一動之後過期

切片用的三角形是**世界座標**蒐集後快取的。只要參考模型的位置／旋轉／縮放
一動，快取就過期。實測掃描俯仰角時三個不同的 pitch 量到一模一樣的數字，
**而且完全看不出是錯的**——會直接把錯的角度當成答案。任何會動到參考模型的
路徑都要清掉快取（本專案在 `placeRef()` 開頭清）。

### 3. 軸向約定不保證一致，而且不要自動判斷

Bf 109 E-4 那個模型機首朝 +Z，第一版疊圖整台頭尾顛倒，還一度被讀成
「機身形狀差很多」。試過用「螺旋槳端的 X 延伸較大」自動判向，但該模型的
機尾也有寬達 ±1.31 的部件，判準直接失效。

**看一次算圖就知道方向，用參數指定比猜可靠。**

### 4. 只比對側視圖 → 寬度錯 13–18% 也看不出來

這是最貴的一個坑，見開頭。**每一輪都要看俯視圖。**

### 5. 想靠節點分類挑出「機身」→ 分類不可靠

第三方模型有兩百多個節點，蒙皮、內裝、發動機、起落架、螺旋槳混在一起。
實測某站位量到的半寬是 ±0.22，而被判為「機身」的節點包圍盒卻說 ±0.55。

**改用射線取最外側交點就完全不需要分類**：內裝、座椅、發動機一定在蒙皮之內。

### 6. `maxRadius` 訂太大 → 擬合悄悄失效

P-51D 第一次切片時 `maxRadius: 1.0`，結果 `bUp` 在連續六個站位剛好等於
上界 `1.000`——那不是量測值，是**擬合撞到參數上界**。

**檢查方法：任何參數等於邊界值就是垃圾資料。** 把 `maxRadius` 收到略大於
預期最大半徑（機身半深的 1.1 倍左右）再重跑。

### 7. 站位太疏 → 平滑的量測曲線被折成折線

第一版只從 44 站的擬合結果挑了 18 站烘焙。逐段斜率：

```
−1.91 → −1.51   +10.8°
−1.51 → −1.12    +2.1°   ← 8.7° 折角，側視看得見
 3.01 →  3.60   −13.5°
 3.60 →  4.39    −8.3°   ← 背線凹陷
```

**用 30–40 站再加平滑**，相鄰斜率變化壓到 4° 以內。站位不必等距——曲率大的
地方（機首、座艙）加密，機尾放疏。

### 8. lofting 的封閉管子做不出座艙凹口

想在管子上壓出凹口只能壓扁截面，但截面一壓扁**寬度也跟著縮**：實測艙緣
高度的半寬會由 0.401 掉到 0.314，機身在座艙處長出一個腰身，正視與俯視
都很明顯。

**烘焙成顯式頂點之後直接不輸出艙緣以上的面即可。**

### 9. 內裝的纏繞方向要跟機身相反

機身朝外的順序是 `(A_i, B_i, B_j)`；內裝要**朝內**（從開口往下看要看得到
內側），必須整個反過來。寫成同向的話正面被機身擋住、朝內的是背面又被剔除，
症狀是「暗色內裝完全看不到、從開口直接看穿」。

### 10. 開口前壁會被拉成長斜坡

開口的前壁是「最後一個完整的環」到「第一個被切開的環」之間那一段。若前面
最近的環在 0.295 m 之外，機背就會一路斜降到艙緣，側面看是機首後方塌下去
一塊——會被誤讀成「機鼻與玻璃罩沒接好」。

**在開口前後各補一個距離 0.01 m 的環**，前壁就等於一道垂直隔板。

### 11. 玻璃下緣要與開口邊緣算同一個交點

用 `prepareRings` 把玻璃站位補進機身環，玻璃的艙緣 x 再用**同一組環**求出。
兩邊各自逼近的話，站位之間會出現縫。

### 12. 座艙罩的**截面形狀**要量，不能假設

- Bf 109：梯形——窄平頂 + 平側玻璃 + 寬艙緣（`/‾\`）
- P-51D：真的圓的氣泡罩，用梯形做出來像雞籠

還有一個非直覺的：**方正與否取決於分段數，不只是圓潤度參數**。6 段的頂點
落在 60°/120°，中間形成平頂；8 或 10 段會在 90° 出現頂點做成尖屋脊，
圓潤度調再高也救不回來。

### 13. 機翼太厚 → 通常不是最大厚度訂錯

實測 Bf 109 的最大厚度 0.315 與真機 14.2% 弦長**完全一致**，看起來還是太厚。
原因是**整片等厚的平板**讓這個厚度從前緣一路撐到後緣。

**改成弦向厚度分佈**（最大厚度在三成弦長，前後緣幾乎收成一條線）。最大厚度
一個字不用改，看起來就薄得多。

另一件事：**厚弦比本身沿翼展就在變薄**（P-51D 15.1% → 11.4%、Bf 109
14.2% → 11.35%）。只按弦長縮等於把翼根的厚弦比帶到翼尖，翼尖會厚 27%。

### 14. 貼在機翼下的方盒要跟著上反角傾斜，而且不能太長

機翼有上反角、厚度又沿翼展收，下表面在一個 0.55 m 寬的散熱器內外兩端會差
0.074 m（實測 7.7°）。水平的方盒會內側陷進機翼、外側浮空。

而且機翼是翼型剖面之後，下表面只有在三成弦長處最低、往後抬起；**平頂的
方盒蓋不住這段起伏**——0.97 長的盒子後端會離開機翼 0.06 m 露出一條縫。
縮短到只涵蓋厚度變化小的那一段。

### 15. 有些東西量不到，要知道是哪些

| 量不到的 | 原因 | 怎麼辦 |
| --- | --- | --- |
| 座艙段背線 | 玻璃罩擋在射線上 | 由前後兩端內插（而且那段會被挖掉） |
| 艙緣線 | 參考模型該處最外側就是玻璃 | 人工定，這是唯一必須人工定的線 |
| 翼根腹線 | 量到的凹陷是翼根整流罩 | 用趨勢值，機翼是另一片，不能重複 |
| 機尾 90% 之後 | 垂直尾翼 | 手工收尾錐 |
| 機首 6% 之前 | 螺旋槳 | 配合整流罩尺寸 |
| 起落架放下的機腹 | 輪子與支柱 | 換一個乾淨的角度重量，或用趨勢值 |

**在文件裡把這幾處標出來**，日後才知道哪些數字有來源、哪些是判斷。

### 16. 機翼與機身各自訂位 → 縱向關係錯 0.85 m 也看不出來

**最貴的一個坑之二。** P-51D 的機身環量得很準（逐站吻合 0.025 m），機翼的
弦長、後掠、上反、厚度也都量過——但兩者**從來沒有放在同一個座標系裡量**。
機身是照參考模型烘的，機翼是手訂的，結果機翼掛得比真機後 **0.85 m**。

側視疊圖看不出來，因為機身自己是對的、機翼自己也是對的；錯的是它們之間
的關係，而疊圖時眼睛會自動去比「機身對不對」。

**做法：所有零件都由同一次切片、在同一個座標系量出來，最後整體平移一次**
（本專案是讓機翼四分之一弦線落在原點，因為原點是重心）。

**兩個免費的交叉驗證**，飛行模型的參數本來就在檔案裡：

| | 量測值 | `spec.wing` | 原本手訂 |
| --- | --- | --- | --- |
| MAC | 1.981 | 1.98 | 2.11 |
| 翼面積 | 21.4（+整流罩） | 21.83 | 22.8 |

量測值同時對上兩項、手訂值兩項都差 6%——**這比任何疊圖都有說服力**。
量完梯形一定要算一次 MAC 與面積跟 spec 對照。

還有一個一眼可辨的檢查：**風擋落在翼弦的百分之幾**。P-51D 量測值 36.5%，
手訂版本是 3.6%（等於風擋騎在機翼前緣上）——照片上一秒就看得出不對，
但只要沒把兩者放進同一張圖，就永遠不會去比。

### 17. 垂尾的 rootY 要低於**整段**機尾背線

垂尾用「前緣所在站位的背線」當虛擬翼根很直覺，但背線一路往後降：P-51D
在垂尾前緣是 0.55、到尾錐只剩 0.215。取 0.60 的結果是垂尾後半整個懸空，
側視看得到底下透出背景。

**取最後一個機身環的背線再低一點**，多出來的部分埋進機身反正看不到。
方向舵後緣本來就會伸出尾錐之外，那是對的。

### 18. 量到的輪廓已經含翼尖圓化，不要再套一次

`tipRound` 是**圓化前**的梯形參數。垂尾沿用機翼的 0.35 會把最頂端的弦長
收到 0.23，疊圖上垂尾頂端缺一塊——而實測頂端弦長 0.60，等於 0.8 出頭。
真機的垂尾頂、水平尾翼尖都只是小圓角，不是橢圓收尖；會急收的只有主翼，
而且是在最外側 4% 翼展之內。

### 19. 「不夠平順」多半是**曲率變號**，不是振幅

疑似機身線條不夠平順時，量錯東西很容易得到「兩台一樣」的結論。實測 Bf 109
與 P-51D：相鄰站位折角、環上轉折角、偏離前後兩站連線的量，三個指標**完全
一樣**（平均 1.8 vs 1.9 mm）。分得出來的只有一個：

| | 最寬線的曲率變號次數 |
| --- | --- |
| Bf 109（擬合值直接烘） | 14 / 34 站 |
| P-51D（先寫成錨點曲線再取樣） | 7 / 34 站 |

**每隔一站就凹凸互換**，就是擬合殘差沒被濾掉。振幅只有 ±2 mm，但平面著色
下每一條長條的法線跟著交替，邊界看起來就是波浪狀的。

解法是 **z 不等距的拉普拉斯平滑**（往「前後兩站在該 z 的連線」靠 λ=0.5），
不是等權的 `[.25,.5,.25]`——站距差到 4 倍時等權濾波會把密集區壓扁。兩輪
即可（變號 14 → 4），位移 11 mm，在擬合自己的殘差之內；再多輪只增加位移
不再減少變號。

### 20b. 翼根整流罩是獨立的一片，不是把翼根加長

主翼的翼根弦長是**氣動參考弦**，四分之一弦線必須壓在原點（重心）。整流罩
不算在氣動弦裡，加進主翼會讓那條跨模組測試失效。做成獨立的一片還有一個
好處：測試判斷「哪一片是主翼」的門檻是 80% 半翼展，整流罩只跨 27%，
自然被排除，不必動測試。

**量法**是逐站比「參考前緣 − 本模型前緣」。P-51D 實測：

```
 x     0.50  0.70  0.90  1.10  1.30  1.50  1.70
 前伸  0.319 0.239 0.175 0.118 0.065 0.025 0.006
 後伸  0.181 0.050 0.027 0.022 0.013 0.006  —
```

**不會 z-fighting 的訣竅：厚度取主翼同站位的 0.97 倍，弦長卻更長。**
同一個 z 上，整流罩在主翼前緣附近是 15% 弦長（厚）、主翼是 0% 弦長（薄），
所以整流罩露在外面；到 30–60% 弦長主翼比較厚，整流罩整片縮在裡面。兩者
永遠不共面——露出來的正好是要的那圈整流，中段自動藏起來。翼尖端的弦長與
前緣訂成**恰好等於**主翼在該站位的值，兩端就都沒有接縫。

**寧可少也不要多。** 真機的後緣整流是很集中的鼓包（0.5 有 0.18、0.7 只剩
0.05），線性收窄的梯形做不出來：對上翼根就會在 0.7～1.0 整段外伸 0.05。
少的地方看起來只是沒有整流罩，多的地方是憑空長出參考模型沒有的東西。

### 20. 背線要取「正上方那一條射線」，不能取擬合的 bUp

單一指數 n 的超橢圓配不上真機那種「上圓下平」的剖面，擬合會把頂點往下拉。
實測 Bf 109 的機背因此**整段低 0.05–0.10 m**，而同一批站位的半寬差 15 mm、
腹線差 20 mm——只有背線錯。最明顯的後果是座艙罩正後方一步掉 0.082 m，
側視是一個缺口。

抬升時以**最寬處為樞紐**等比拉高上半部：半寬與腹線完全不動，才不會把一條
線的修正變成整個剖面重做。

### 21. 量尺自己也要驗：同一台參考模型可能只有位置可信

Bf 109 那個參考模型：

| | 量測值 | 真機 | 差 |
| --- | --- | --- | --- |
| 主翼翼根弦 | 2.279 | 2.22 | +2.7% |
| 主翼厚弦比 | 16.9% | 14.2% | +19% |
| 水平尾翼半翼展 | 1.47 | 1.65 | **−11%** |
| 垂尾頂端高度 | 1.09 | ~1.45 | −25% |

**主翼偏大、尾翼偏小**——這不是量測誤差，是那台模型的比例本來就不準。
但它的機身逐站吻合到 3 mm、機翼前緣是一條每站 0.006 m 的完美直線：
**位置可信，尺寸不可信。**

所以每一個量到的數字都要先問一次「這一項有沒有史實值可以對」：

- 有史實值而且對得上 → 採用量測值（P-51D 的 MAC 1.981 對 spec 1.98）
- 有史實值但對不上 → **史實值優先**，量測值只拿來定位置
- 沒有史實值（機身剖面、座艙罩輪廓、整流罩） → 只能用量測值

判別「不準」而不是「我量錯了」的方法：**看同一台模型的其他零件是不是往
同一個方向偏**。全部偏大 → 縮放基準錯了；有的偏大有的偏小 → 模型本身
比例不準。

### 22. 一個錯的前提，可以讓六次修正每一次都合理、每一次都不對

**這是 He 111 最貴的一條，也是整份文件最貴的一條。**

機腹吊艙的暗色內襯前後改了六次都不對：縮小的實心殼（兩次）、平天花板、
上半圈的內面、下半圈的外面、把機身挖一個洞。每一次都是針對上一版的症狀
提出的合理修正，每一次算圖出來都還是錯的。

根因不在那六次裡的任何一次：**參考模型的吊艙是金屬的，只有前後兩片窗。**
而「機腹整塊凸起都是玻璃」這個前提，是前一天**從照片上讀來的，不是量的**——
它從來沒有進過任何一張量測表，所以也從來沒有被檢查過。

六次全部在問「暗色要怎麼補」，而正確的問題是「**那裡到底是不是玻璃**」。

**做法：同一個地方修第三次還是錯，就停手去量前提，不要再修。** 判別方法很
簡單——把這一輪依賴的每個假設列出來，逐一問「這個數字是量到的還是看到的」。
看到的那些就是嫌疑犯。

### 23. 「補一塊暗色的東西」不是「挖一個凹槽」

同一個需求做錯四次，四種症狀各不相同，但都會被誤讀成「顏色不對」或
「位置不對」：

| 做法 | 看起來像什麼 | 真正的問題 |
| --- | --- | --- |
| 縮一號的**封閉**管子塞在罩口前 | 一片平板塞子 | 側壁法線朝外，從凹槽裡看是背面被剔除；只剩封蓋看得到 |
| 同上，且比罩口小 0.10 | 塞子與罩口之間一圈是空的 | 壁沒有接到緣 |
| 整組環往內縮 0.88 的一層殼 | 罩子裡飄著一台小飛機 | 那是「機身的縮小版」，不是隔框 |
| 玻璃那幾片往內縮 0.84 | 跟著玻璃一起隆起的暗色包 | 罩子是凸的，縮小版也是凸的；要的是那一段的**弦** |

**凹槽 = 開口 + 朝內的壁 + 壁接到緣。** 三個都有才是凹槽。

### 24. 全玻璃的機首整條是通的

He 111 沒有階梯式風擋，整個機首是玻璃。第一版於是從機首一路看穿到機尾——
而這個缺陷**在側視疊圖上完全不存在**，只有實體算圖才看得到。

真機在玻璃段後端有一道**前隔框**。做法是在分界站位前 1 cm 放一片**整剖面**的
暗色板（`buildHull` 兩站相距 0.01，`caps: { back: false }`），不是往內縮一層殼。

**推廣：任何大面積透明件都要問一次「後面擋得住嗎」。**

### 25. 窄帶只有一個朝向 → 從背面看是透明的

玻璃罩的結構條是幾條窄的長條，法線只有朝外那一面。全玻璃機首看得到**對側**
骨架的背面，於是那幾條從背面看整個消失。

**專門開一個 `DoubleSide` 的材質給它們**（`assembly.ts` 的 `bothSides`），
不要去改 `frames()` 的纏繞——長條兩面都要，反過來只是換一面看不見。

### 26. 兩個沉深各訂各的 → 黑貼紙

`hull.ts` 有兩個往內沉的係數：玻璃 `GLASS_SINK` 0.94、碗底 `LID_SINK` 0.93。
機背（玻璃與蒙皮共面）沒問題，但**側窗是凹槽**、玻璃已經沉到 0.94——碗底
0.985 於是落在玻璃**外面**，整片黑板蓋住那扇窗，看起來是一張黑貼紙。

**相對的量要相乘，不要各自訂絕對值**：`LID_SINK * (patch.recess ? GLASS_SINK : 1)`。

### 27. API 的語意要親自驗一次

`propeller.noseZ` 是整流罩的**錐底**不是錐尖（`spinner.position.z =
noseZ − length/2`，錐尖朝 −Z）。照「機首尖端」填進去，整支整流罩往前跑了
0.55 m，而發動機艙又把同一個圓錐畫了第二次——症狀是「機首多一截」，
看起來完全像是尺寸訂錯。

**新接一個產生器時，先給一組已知的極端值算一次包圍盒**，確認語意再填真值。

### 28. 兩條量測路徑之間的差不一定是剛體位移

`__hangarProbe`（旁路，自己套一組對齊參數）與 `placeRef`（遊戲實際疊圖走的
那條）擺參考模型的方式不同。看起來像是固定的 +0.12 z／+0.105 y，於是在驗收
階段補償了一次——**逐站殘差中位數從 0.095 惡化到 0.269**，而且參考模型的
背線往上跑而不是往下。

**驗收一律走 `placeRef` 那一條**（要問的本來就是「遊戲裡疊出來的那一份對
不對」）。probe 那條只拿來量參考模型自己，不做兩邊對照。

### 29. 最便宜的判定法：把它改成純紅，重跑一次

懷疑「機背襯裡沒有蓋到」時，與其推理，不如把那個材質**暫時改成純紅**再算一
張圖。實測結果是罩內整片是紅的——**襯裡本來就在**，錯的是形狀不是有無。

這一招在三個地方省下了整輪的修改：判斷某個面是不是被剔除、判斷某個零件在不
在畫面上、判斷兩片是不是重疊。**零像素改變＝那個假設是錯的**，一次算圖就有
答案（坑 20b 的另一種用法：寧可先證明它存在，也不要憑空再補一份）。

### 30. 取樣間距要比特徵細

發動機艙第一版用 0.2 m 取樣，而參考模型上有三道間距 0.1 上下的階——量出來
是一條波浪，配出來自然也是波浪。**先用粗取樣找出特徵在哪，再對那一段加密
重量一次。**

## 剪影抽取（正交截圖比對用）

需要逐欄比對輪廓時：

- **正交相機是必須的。** 透視會讓靠近鏡頭的部件變大，機首與機尾的長度比例
  在畫面上就不是真的。
- 每一欄取**最長連續**的非背景像素段，不是頭尾——這樣會自動濾掉天線、
  起落架支柱那種細長離群物。
- **側視圖裡機首在畫面右邊**（相機看 −X，螢幕右是 −Z）。第一版的百分比表
  整個左右顛倒過。
- 兩張圖要共用同一顆相機：先 `__hangarShow(true, false)` 再
  `__hangarOrtho('side')` 框圖，之後只切換顯示、不要重新框。

## 不要為外型寫測試

專案負責人兩次裁決，而且有證據：

1. 對手寫的造型數字再斷言一次，本質上是同義反覆。
2. 「背線形狀」那條改過兩次，**兩次都是測試錯了、幾何是對的**——第一次容差
   訂 3 mm 而真機實測偏離 22 mm；第二次寫死線稿的絕對高度，被改採參考模型
   的裁決推翻。它沒擋下任何缺陷，只擋了自己人。
3. 實際發生過的外形缺陷（機翼沒畫完、垂尾顛倒、機腹浮空、機身太胖、座艙罩
   形狀）**全部是人眼先發現的**。

**該留的測試只有兩類**，兩類都與好不好看無關：

- **產生器的機制**：給定參數幾何是否照定義產生（後掠方向、翼尖收縮、法線
  朝外、開口確實挖掉、玻璃下緣等於開口邊緣）。
- **跨模組一致性**：包圍盒翼展要等於 `spec.wing.span`（飛行模型與視覺模型
  共用同一個數字）、機翼四分之一弦線要落在原點（原點是物理模型的重心）。

**新機種要記得加進硬編的機種清單。** `[P51D, BF109G6]` 這種寫死的陣列散在
十幾個檔案裡（`aero`／`envelope`／`geometry`／`hitbox`／`propulsion`／
`low-speed-authority`／`pitch-limiter-departure` 與幾支 probe）。**沒有加
進去的機種等於沒有任何測試在跑**——He 111 整段外型做完時這幾條一次都沒有
碰過它。

加之前先確認幾何撐得住那幾條：玻璃緣的內壁是**兩種纏繞都畫**的，「法線朝外
（帶符號體積為正）」那條護欄要先想清楚怎麼算。

## 檢查清單

新增一個機種時：

- [ ] GLB 放進 `ref/`（已 gitignore）
- [ ] 側視一張，確認機首朝向與**姿態**（起落架放下 ≈ 著陸姿態 ≈ 需要 pitch）
- [ ] 縮放基準用翼展；驗證縮放後翼展與全長都對得上真機
- [ ] 三軸切片，殘差 RMS < 0.025 m，且**沒有參數卡在邊界**
- [ ] **機身、機翼、尾翼、座艙、進氣口全部由同一次切片量出**，最後才整體平移
- [ ] 量完機翼算一次 MAC 與翼面積，跟 `spec.wing` 對照（見坑 16）
- [ ] **每個量測值先問有沒有史實值可以對**；對不上時史實優先（見坑 21）
- [ ] 標出量不到的區間，逐一決定怎麼處理並寫進註解
- [ ] 背線與腹線取射線值，不是擬合的 bUp／bDn（見坑 20）
- [ ] 烘焙 30–40 站 + z 不等距平滑，逐段斜率變化 < 5°、曲率變號 < 8/34 站
- [ ] 座艙：挖開、內裝反向纏繞、開口前後補環、玻璃接在開口邊緣
- [ ] **每一塊透明件先量「那裡到底是不是玻璃」**（按 mesh 名稱分別打射線，
      見第 5b 步），不要從照片讀
- [ ] 凹槽三件事：有開口、壁朝內、壁接到緣（見坑 23）
- [ ] 大面積透明件後面有沒有東西擋（隔框），窄帶結構條有沒有用雙面材質
- [ ] 掛在外面的零件（發動機艙、吊艙、散熱器）**一個零件一串截面**，不要
      壓成一串（見第 5b 步（2））
- [ ] 分段數挑一個能整除量到的角度的值（見第 5b 步（5））
- [ ] 機翼：弦向厚度分佈、翼尖厚度另外指定、翼根整流罩（見坑 20b）
- [ ] **側視與俯視都疊圖**，再用 `__hangarSlice(..., 'mine')` 對切跑逐站比對
- [ ] **實體算圖看六個方向**（正／側／俯／仰／前下／後下）——看穿、黑貼紙、
      透明支架這些缺陷剪影上不存在
- [ ] 把新機種加進硬編的 `[P51D, BF109G6]` 清單，跑一次全套回歸
- [ ] 回報三角形數，讓負責人決定要不要收
