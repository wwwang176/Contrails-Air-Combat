# 依參考模型建立飛機外型

**核心原則：能量的就不要用眼睛判斷。** 這套流程是在 Bf 109 E-4 與 P-51D
上一路踩坑試出來的；每一條「坑」後面的數字都是實測值，不是推測。

## 為什麼需要這套流程

在導入參考模型之前，外型是靠「看照片 → 調數字 → 截圖 → 再調」的循環做的。
那個循環有一個致命盲點：**它只會收斂到你在看的那個視圖**。

實際發生的事：兩台飛機的側視剖面都調到與參考模型差 ±0.03 m，看起來完美，
但機身**寬度**同時錯了 13–18%（Bf 109 尾錐錯 41%）。因為十幾輪都在看側視圖，
沒有人量過俯視圖。

> 只要你還在用眼睛比對，你只會修正你正在看的那一個維度。

## 流程

### 第 0 步：把參考模型放進 `ref/`

`ref/` 已列入 `.gitignore`。參考模型**只當量尺**，不進版控、不進打包。

### 第 1 步：對齊（最容易錯，錯了後面全錯）

對齊參數寫在 `src/tools/hangar.ts` 的 `REFS` 表，一機一筆：

```ts
const REFS: Record<string, RefSpec> = {
  p51d:    { url: '/ref/p51d.glb',   flip: true, pitch: -14.0 },
  bf109g6: { url: '/ref/bf109e4.glb', flip: true, pitch: 0 },
}
```

| 欄位 | 用途 |
| --- | --- |
| `url` | GLB 路徑 |
| `flip` | `true` = 機首朝 +Z，需要繞 Y 轉 180° |
| `pitch` | 繞世界 X 軸轉正的角度（度），求法見坑 2 |

機庫面板上勾「參考模型」才會下載（兩個檔加起來 50 MB），切換機種會自動換
對應的那一份。「實體」按鈕切換不透明材質——疊圖用的平塗只保留輪廓，要判讀
**輪廓以內**的特徵（例如玻璃的分界線在哪）就得先看得見它本來的樣子。

外部工具（Playwright）用 `__hangarRef(on, solid)` 開啟；它回傳是否已就緒，
可以輪詢而不是硬等下載。

**這三個值是量出來的定值，不要做成每次輸入的旋鈕。** 打錯很難發現——實測
P-51D 用 −9.5° 時剪影上看起來已經差不多平了，正確值卻是 −14.0°。

**縮放基準是翼展，不是全長。** 這是本流程最重要的一條（見坑 1）。

### 第 2 步：三軸切片量測

`src/tools/sliceRef.ts`，機庫的 `__hangarSlice`。一組切面只描述得了一種零件，
所以三根軸都要切：

```js
// 機身橫剖：由軸心往外射線，取最外側交點
window.__hangarSlice('radial', 'z',
  { from: -2.3, to: 6.16, count: 44, angles: 72, axisV: 0.24, maxRadius: 0.95 })

// 機翼縱剖：z 幅度是弦長、y 幅度是厚度
window.__hangarSlice('extent', 'x', { from: 0.2, to: 5.2, count: 26 })

// 平面形：x 幅度是翼展、每個 x 的 z 幅度是弦長
window.__hangarSlice('extent', 'y', { from: -0.6, to: 0.4, count: 11 })
```

配套的開發用出口：

| Hook | 用途 |
| --- | --- |
| `__hangarRef(on, solid)` | 開關參考模型，回傳是否已載入完成（可輪詢） |
| `__hangarSpec(id)` | 切換機種，免得腳本去點 DOM |
| `__hangarRefPitch(deg\|null)` | 暫時覆寫俯仰角，掃描專用；null 回到 REFS 定值 |
| `__hangarInfo()` | metrics、三角形數，以及**正交相機的像素換算** |
| `__hangarShow(mine, ref)` | 分別開關兩個模型，抽純剪影用 |
| `__hangarOrtho(view)` / `__hangarCam(x,y,z)` | 視角 |

`__hangarInfo().ortho` 給的是 `{ mPerPx, center, right, up }`，像素換世界座標
直接套：

```
world = center + right·(px − W/2)·mPerPx + up·(H/2 − py)·mPerPx
```

**不要再自己手推這個換算。** 先前在腳本裡推過至少四次，錯過一次——第一版的
百分比表整個左右顛倒，機首機尾對調。相機自己知道答案。

### 第 3 步：擬合與清洗

把每一刀的 `r(θ)` 擬合成「上下半高可不同的超橢圓」四參數
`(a, bUp, bDn, n)`：

```
|r·cosθ / a|^n + |r·sinθ / b|^n = 1     b = bUp（sinθ>0）或 bDn
→ r(θ) = (|cosθ/a|^n + |sinθ/b|^n)^(−1/n)
```

用**單邊修剪**反覆擬合：污染一律讓半徑偏大，所以每輪丟掉「量到的比模型大
超過門檻」的點。收斂後殘差 RMS 應在 0.010–0.023 m；明顯更大就是該站位不可信。

### 第 4 步：烘焙成顯式頂點

輸出 `<機種>.hull.ts`，每站一圈半剖面（只存右半，左半鏡像）。
**站位要密**（見坑 7），並在輸出格點上做三輪 `[.25, .5, .25]` 平滑。

### 第 5 步：挖座艙、補內裝、蓋玻璃

`buildHull(rings, cut)` / `buildCockpitTub(...)` / `buildCanopy(...)`，
三者共用同一組環（先呼叫 `prepareRings` 把玻璃站位補進去）。

### 第 6 步：驗收

正交側視 + 俯視疊圖，**兩個都要看**。再跑一次數值比對表（半寬、背線、腹線
逐站對照）。眼睛看疊圖抓大方向，數字抓 0.02–0.05 這一級的偏差。

## 坑

### 1. 縮放基準用全長 → 整台小 2–4%

全長被螺旋槳與姿態污染。實測依全長縮放後：

| | 縮放後翼展 | 真機 | 誤差 |
| --- | --- | --- | --- |
| Bf 109 E-4 | 9.481 | 9.87 | −4.0% |
| P-51D | 11.030 | 11.286 | −2.3% |

**改用翼展**：兩台都對上（9.865、11.246），P-51D 的全長也回到 9.841 對 9.83。
翼尖是乾淨的基準——±X 的極端點必然是翼尖，沒有起落架、螺旋槳、天線。

在這條修好之前做的所有疊圖比對，結論都帶著這個誤差。

### 2. 參考模型不保證是飛行姿態

P-51D 那個模型是**三點著陸姿態**、起落架放下，整台機首朝上 **14°**。
直接疊圖會讀成「機身前段太低、後段太高」——那 1.1 m 的落差全部來自姿態。

**先看一張側視再相信任何垂直方向的比對。** 用 `REFS[id].pitch` 轉正。

**不要用剪影目測估這個角度。** 第一次憑側視疊圖估成 −9.5°，實際是 −14.0°，
差了 4.5°——而剪影上看起來已經「差不多平了」。正確做法是**掃描**：

1. 取兩個**長基線**且**乾淨**的縱向基準：整流罩軸心（`|x|<0.14` 的上下中點，
   就是推力線）與機尾中心線（`|x|<0.12`，避開座艙罩、散熱器、尾輪的 z 區間）。
2. 對每個候選 pitch 量「參考值 − 本模型值」在這兩處的差，算殘餘俯仰角
   `atan((機首差 − 機尾差) / Δz)`。
3. 殘餘角過零的那個值就是答案。實測非常線性，四五個點就夠：

```
 pitch   機首差   機尾差   殘餘俯仰
  −8.0   +0.727   +0.033    +5.73°
 −11.0   +0.540   +0.205    +2.76°
 −14.0   +0.354   +0.378    −0.20°   ← 過零
 −17.0   +0.165   +0.535    −3.05°
 −20.0   −0.024   +0.697    −5.96°
```

**驗收：轉正之後機翼中線應該整段吻合。** 實測 P-51D 在 −14° 時，13 個翼展
站位的差全部在 ±0.015 m 內，上反角 4.78° 對 5.00°——這是「姿態對了」最強的
證據，因為機翼橫跨整個翼展，角度只要差一點就會在翼尖放大。

**轉正之後還剩下的常數差就不是姿態，是真的外型不同。**

### 2b. 垂直基準用機首尖端（推力線），不要用翼尖

同一個 0.37 m 落差，基準不同會落在不同零件上——**基準只決定你會怪誰**：

| 基準 | 機首軸心 | 機尾中心線 | 機翼 |
| --- | --- | --- | --- |
| 翼尖 | +0.354 | +0.378 | ±0.015 |
| **機首** | **+0.001** | **+0.025** | **−0.36** |

用機首當基準，機身從頭到尾吻合到 0.025 m——那是橫跨 7 m、幾十個獨立站位
的一致性，比「機翼是一條直線對上另一條直線」強得多。結論因此明確：機身是
對的，**機翼掛太高了 0.36 m**。

翼尖的平均高度取決於上反角、翼尖形狀、取樣視窗取多寬，三件事在兩個模型上
都不一樣；機首尖端是**一個點**，而且 Z 向本來就拿它對齊。

### 2c. 世界座標的快取會在模型一動之後過期

切片用的三角形是**世界座標**蒐集後快取的。只要參考模型的位置／旋轉／縮放
一動，快取就過期。實測掃描俯仰角時三個不同的 pitch 量到一模一樣的數字，
**而且完全看不出是錯的**——會直接把錯的角度當成答案。任何會動到參考模型的
路徑都要清掉快取（本專案在 `placeRef()` 開頭清）。

### 3. 軸向約定不保證一致，而且不要自動判斷

Bf 109 E-4 那個模型機首朝 +Z，第一版疊圖整台頭尾顛倒，還一度被讀成
「機身形狀差很多」。試過用「螺旋槳端的 X 延伸較大」自動判向，但該模型的
機尾也有寬達 ±1.31 的部件，判準直接失效。

**看一次算圖就知道方向，用參數指定比猜可靠。**

### 4. 只比對側視圖 → 寬度錯 13–18% 也看不出來

這是最貴的一個坑，見開頭。**每一輪都要看俯視圖。**

### 5. 想靠節點分類挑出「機身」→ 分類不可靠

第三方模型有兩百多個節點，蒙皮、內裝、發動機、起落架、螺旋槳混在一起。
實測某站位量到的半寬是 ±0.22，而被判為「機身」的節點包圍盒卻說 ±0.55。

**改用射線取最外側交點就完全不需要分類**：內裝、座椅、發動機一定在蒙皮之內。

### 6. `maxRadius` 訂太大 → 擬合悄悄失效

P-51D 第一次切片時 `maxRadius: 1.0`，結果 `bUp` 在連續六個站位剛好等於
上界 `1.000`——那不是量測值，是**擬合撞到參數上界**。

**檢查方法：任何參數等於邊界值就是垃圾資料。** 把 `maxRadius` 收到略大於
預期最大半徑（機身半深的 1.1 倍左右）再重跑。

### 7. 站位太疏 → 平滑的量測曲線被折成折線

第一版只從 44 站的擬合結果挑了 18 站烘焙。逐段斜率：

```
−1.91 → −1.51   +10.8°
−1.51 → −1.12    +2.1°   ← 8.7° 折角，側視看得見
 3.01 →  3.60   −13.5°
 3.60 →  4.39    −8.3°   ← 背線凹陷
```

**用 30–40 站再加平滑**，相鄰斜率變化壓到 4° 以內。站位不必等距——曲率大的
地方（機首、座艙）加密，機尾放疏。

### 8. lofting 的封閉管子做不出座艙凹口

想在管子上壓出凹口只能壓扁截面，但截面一壓扁**寬度也跟著縮**：實測艙緣
高度的半寬會由 0.401 掉到 0.314，機身在座艙處長出一個腰身，正視與俯視
都很明顯。

**烘焙成顯式頂點之後直接不輸出艙緣以上的面即可。**

### 9. 內裝的纏繞方向要跟機身相反

機身朝外的順序是 `(A_i, B_i, B_j)`；內裝要**朝內**（從開口往下看要看得到
內側），必須整個反過來。寫成同向的話正面被機身擋住、朝內的是背面又被剔除，
症狀是「暗色內裝完全看不到、從開口直接看穿」。

### 10. 開口前壁會被拉成長斜坡

開口的前壁是「最後一個完整的環」到「第一個被切開的環」之間那一段。若前面
最近的環在 0.295 m 之外，機背就會一路斜降到艙緣，側面看是機首後方塌下去
一塊——會被誤讀成「機鼻與玻璃罩沒接好」。

**在開口前後各補一個距離 0.01 m 的環**，前壁就等於一道垂直隔板。

### 11. 玻璃下緣要與開口邊緣算同一個交點

用 `prepareRings` 把玻璃站位補進機身環，玻璃的艙緣 x 再用**同一組環**求出。
兩邊各自逼近的話，站位之間會出現縫。

### 12. 座艙罩的**截面形狀**要量，不能假設

- Bf 109：梯形——窄平頂 + 平側玻璃 + 寬艙緣（`/‾\`）
- P-51D：真的圓的氣泡罩，用梯形做出來像雞籠

還有一個非直覺的：**方正與否取決於分段數，不只是圓潤度參數**。6 段的頂點
落在 60°/120°，中間形成平頂；8 或 10 段會在 90° 出現頂點做成尖屋脊，
圓潤度調再高也救不回來。

### 13. 機翼太厚 → 通常不是最大厚度訂錯

實測 Bf 109 的最大厚度 0.315 與真機 14.2% 弦長**完全一致**，看起來還是太厚。
原因是**整片等厚的平板**讓這個厚度從前緣一路撐到後緣。

**改成弦向厚度分佈**（最大厚度在三成弦長，前後緣幾乎收成一條線）。最大厚度
一個字不用改，看起來就薄得多。

另一件事：**厚弦比本身沿翼展就在變薄**（P-51D 15.1% → 11.4%、Bf 109
14.2% → 11.35%）。只按弦長縮等於把翼根的厚弦比帶到翼尖，翼尖會厚 27%。

### 14. 貼在機翼下的方盒要跟著上反角傾斜，而且不能太長

機翼有上反角、厚度又沿翼展收，下表面在一個 0.55 m 寬的散熱器內外兩端會差
0.074 m（實測 7.7°）。水平的方盒會內側陷進機翼、外側浮空。

而且機翼是翼型剖面之後，下表面只有在三成弦長處最低、往後抬起；**平頂的
方盒蓋不住這段起伏**——0.97 長的盒子後端會離開機翼 0.06 m 露出一條縫。
縮短到只涵蓋厚度變化小的那一段。

### 15. 有些東西量不到，要知道是哪些

| 量不到的 | 原因 | 怎麼辦 |
| --- | --- | --- |
| 座艙段背線 | 玻璃罩擋在射線上 | 由前後兩端內插（而且那段會被挖掉） |
| 艙緣線 | 參考模型該處最外側就是玻璃 | 人工定，這是唯一必須人工定的線 |
| 翼根腹線 | 量到的凹陷是翼根整流罩 | 用趨勢值，機翼是另一片，不能重複 |
| 機尾 90% 之後 | 垂直尾翼 | 手工收尾錐 |
| 機首 6% 之前 | 螺旋槳 | 配合整流罩尺寸 |
| 起落架放下的機腹 | 輪子與支柱 | 換一個乾淨的角度重量，或用趨勢值 |

**在文件裡把這幾處標出來**，日後才知道哪些數字有來源、哪些是判斷。

## 剪影抽取（正交截圖比對用）

需要逐欄比對輪廓時：

- **正交相機是必須的。** 透視會讓靠近鏡頭的部件變大，機首與機尾的長度比例
  在畫面上就不是真的。
- 每一欄取**最長連續**的非背景像素段，不是頭尾——這樣會自動濾掉天線、
  起落架支柱那種細長離群物。
- **側視圖裡機首在畫面右邊**（相機看 −X，螢幕右是 −Z）。第一版的百分比表
  整個左右顛倒過。
- 兩張圖要共用同一顆相機：先 `__hangarShow(true, false)` 再
  `__hangarOrtho('side')` 框圖，之後只切換顯示、不要重新框。

## 不要為外型寫測試

專案負責人兩次裁決，而且有證據：

1. 對手寫的造型數字再斷言一次，本質上是同義反覆。
2. 「背線形狀」那條改過兩次，**兩次都是測試錯了、幾何是對的**——第一次容差
   訂 3 mm 而真機實測偏離 22 mm；第二次寫死線稿的絕對高度，被改採參考模型
   的裁決推翻。它沒擋下任何缺陷，只擋了自己人。
3. 實際發生過的外形缺陷（機翼沒畫完、垂尾顛倒、機腹浮空、機身太胖、座艙罩
   形狀）**全部是人眼先發現的**。

**該留的測試只有兩類**，兩類都與好不好看無關：

- **產生器的機制**：給定參數幾何是否照定義產生（後掠方向、翼尖收縮、法線
  朝外、開口確實挖掉、玻璃下緣等於開口邊緣）。
- **跨模組一致性**：包圍盒翼展要等於 `spec.wing.span`（飛行模型與視覺模型
  共用同一個數字）、機翼四分之一弦線要落在原點（原點是物理模型的重心）。

## 檢查清單

新增一個機種時：
