# Grok Aircraft

網頁 3D 空戰遊戲。二戰活塞戰鬥機的能量戰模擬。

目前進度：**M0 + M1 + M2 + M4** —— 可駕駛的單機飛行模型，加上機槍機砲、彈道與命中判定，以及一架會經營能量的 1v1 敵機。

## 快速開始

```bash
npm install
npm run dev       # http://localhost:5173
```

| 指令 | 用途 |
|---|---|
| `npm run dev` | 開發伺服器 |
| `npm run build` | `tsc --noEmit` + 正式建置 |
| `npm test` | 全部測試（44 檔 / 1,248 條） |
| `npm run bench` | 物理步、彈丸步、AI 步的微基準 |

## 操作

| 鍵 | 動作 |
|---|---|
| 滑鼠 | 移動瞄準點。飛機自己飛過去 —— 沒有直接的舵面操作 |
| 左鍵 | **開火**。未取得指標鎖時為進入遊戲（第一次進入必按） |
| 右鍵拖曳 | 自由視角。**不影響飛行**，放開後回正 |
| `W` / `S` | 油門。**彈簧回中** —— 按住 `W` 推到 1.1（WEP）、按住 `S` 收到 0.2，放開自動回到 0.7 |
| `S`（同上） | 同時**減速**。俯衝進場前收速度以延長瞄準窗口、或減速過彎以提高轉彎率 |
| `V` | 第三人稱 ↔ 機首視角 |
| `C` | 切換 P-51D / Bf 109 |
| `R` | 重生 |
| `1` `2` `3` `4` | 靶機機動：等速直線／定盤旋／蛇行／爬升 |
| `5` | 靶機交給 AI 駕駛（`1`–`4` 切回預錄機動） |
| `I` | **自機**交給 AI 駕駛，用於觀測 AI 的行為。接管期間左鍵失效、右鍵自由視角照常，再按一次收回 |
| `F3` | 效能覆蓋層 |

**瞄準模型**：圓圈是你指的方向、十字是機砲指的方向，兩者重合才打得中。瞄準點是**世界固定**的，所以維持轉彎需要持續移動滑鼠 —— 停下滑鼠，飛機就會追上瞄準點並穩住。

相機跟著**瞄準方向**而不是機首，所以圓圈恆在畫面正中央，會漂的是飛機。兩個準星之間的虛線就是指揮儀正在追的誤差角。

**射擊**：目標身上有方框與距離讀數；打得到的時候旁邊會多一個圓圈，那是**預瞄環** —— 把機首十字壓上去再開火。預瞄環的顯示條件不是距離門檻，而是「這一發真的追得上」（有攔截解，且飛行時間在彈丸壽命 1.2 s 內），所以「看得到預瞄環」精確等於「打得到」。命中時十字四角會閃出向內收縮的 `X`。

沒有血量顯示，也沒有目標鎖定 —— 你看不出對方的結構完整度，那在二戰題材上說不通。

## 這個專案在做什麼

飛行模型是**史實性能驅動**的：極速、爬升率、失速速度、升限、持續轉彎率都對著史料調，誤差 ±5% 以內由測試守著。兩台飛機的**相對**強弱不是手感調出來的，是從各自的參數自然長出來的 ——

- Bf 109 在 250 km/h 的持續轉彎率優於 P-51（前緣縫翼）
- 400 km/h 時優勢反轉
- 海平面的交叉點落在 319 km/h
- P-51 在高速、高空、滾轉率、能量保持上領先

這些全部是 `test/balance/relative.test.ts` 的斷言，不是註解。

`Ps`（比超量功率）與 `Es`（比能量）顯示在 HUD 上不是為了除錯，是**能量戰的教學元件**：大 G 轉彎時 Ps 會掉到 −40 m/s 以下，玩家看得到能量在流失，才學得會不要亂拉。

## 架構

```
src/
  core/       固定步長迴圈、暫存物件池、數學
  physics/    ISA 大氣、氣動力、推進、6DOF 積分      ← 純函數
  specs/      機種參數（P-51D、Bf 109 G-6）
  analysis/   準靜態包絡求解器                       ← 純函數
  control/    飛行指揮儀、PID、限制器；Controller 介面與玩家／靶機實作
  aircraft/   Aircraft 組裝、撞海判定
  weapons/    武器資料表、射速時鐘、匯聚幾何
  world/      World（多機步進）、預瞄解、命中判定、彈丸池   ← 純函數為主
  ai/         態勢評估、意圖仲裁、轉向、開火紀律、安全層     ← 純函數（狀態全在 AiController）
  input/      指標鎖輸入、世界固定瞄準點
  camera/     CameraRig
  render/     場景、海面、天空、程序化機體幾何
  hud/        Canvas 2D overlay
  tools/      sliceRef、hangar                       ← 開發用，不進打包
```

**純函數三兄弟**（`physics/`、`analysis/`、部分 `control/`）不持有狀態、不碰 three.js 的場景圖，所以史實性能可以在 node 裡直接驗證，不必開瀏覽器。`ai/` 走同一條紀律 —— 遲滯閂鎖、最小停留、10 Hz 節流、跟蹤計時器全部住在 `AiController`，其餘五個模組是純函數，所以 288 組安全矩陣與對戰矩陣能在 node 裡跑完。

低速時舵面會失去效力（動壓低於 1 G 失速動壓的 1.44 倍時線性衰減），所以垂直懸掛不是免費的招式 —— 掛太久就拉不回來，機頭會被重力帶下去。實測滿舵能換到的俯仰率由入場的 195 °/s 掉到 26 °/s，AI 則在最壞情況（操縱權歸零、飛機完全停住）下仍能在 15.4 秒內救回、只掉 271 m。設計與實測見 `docs/superpowers/specs/2026-08-03-low-speed-control-authority-design.md`。

物理跑 240 Hz 固定步長，渲染用累加器內插 —— 滾轉率可達 100°/s 以上，100 Hz 在大 G 機動時積分誤差肉眼可見。單步實測 **1.0 μs**；彈丸池滿載 4,000 發時整個 `World.step` 是 **175 μs**（含命中判定），曳光彈維持 **1 個 draw call**。兩架 AI 纏鬥的完整 `World.step` 平均 **19 μs**，其中 10 Hz 的包絡查詢那一格 p99 為 **129 μs**。

## 機體幾何

兩台的外型是**量出來的**，不是手調的：機身剖面、座艙罩站位、翼面尺寸與各凸起位置全部量自參考模型。工具在 `src/tools/`（三軸切片器 + 機庫比對頁），完整流程與 21 條實測踩過的坑寫在 `.claude/skills/aircraft-from-reference/SKILL.md`。

參考模型放在 `ref/`，列在 `.gitignore` —— **只作為量尺**，不進版控也不進打包。
