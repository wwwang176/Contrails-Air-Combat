# Contrails Air: Combat

網頁 3D 空戰遊戲。二戰活塞戰鬥機的能量戰模擬。

目前進度：**M0 + M1 + M2 + M4 + M5 + M6 + M7** —— 可駕駛的單機飛行模型，加上機槍機砲、彈道與命中判定，一架會經營能量的敵機 AI，**20v20** 的多機戰場，**編隊與長僚協同**（每隊 5 個 4 機 Schwarm，玩家帶自己的分隊），以及**武器特效**（槍焰、沿命中面法線噴開的火花、入海水柱）。

## 快速開始

```bash
npm install
npm run dev       # http://localhost:5173
```

| 指令 | 用途 |
|---|---|
| `npm run dev` | 開發伺服器 |
| `npm run build` | `tsc --noEmit` + 正式建置 |
| `npm test` | 全部測試 |
| `npm run test:unit` | 純函數與單一機制那一層（unit、control、balance、performance），改一行跑一次用這個 |
| `npm run test:integration` | 跑整場戰鬥的那一層，提交前跑 |
| `npm run bench` | 物理步、彈丸步、AI 步的微基準 |

## 操作

| 鍵 | 動作 |
|---|---|
| 滑鼠 | 移動瞄準點。飛機自己飛過去 —— 沒有直接的舵面操作 |
| 左鍵 | **開火**。未取得指標鎖時為進入遊戲（第一次進入必按） |
| 右鍵拖曳 | 自由視角。**不影響飛行**，放開後回正 |
| `W` / `S` | 油門。**彈簧回中** —— 按住 `W` 推到 1.1（WEP）、按住 `S` 收到 0.2，放開自動回到 0.7 |
| `S`（同上） | 同時**減速**。俯衝進場前收速度以延長瞄準窗口、或減速過彎以提高轉彎率 |
| `V` | 第三人稱 ↔ 機首視角 |
| `C` | 切換 P-51D / Bf 109 |
| `R` | **重開整場**（不只是自機——20v20 裡「只有我復活、戰場停在半場」說不通） |
| `I` | **自機**交給 AI 駕駛，用於觀測 AI 的行為。接管期間左鍵失效、右鍵自由視角照常，再按一次收回 |
| `F3` | 效能覆蓋層 |

**瞄準模型**：圓圈是你指的方向、十字是機砲指的方向，兩者重合才打得中。瞄準點是**世界固定**的，所以維持轉彎需要持續移動滑鼠 —— 停下滑鼠，飛機就會追上瞄準點並穩住。

相機跟著**瞄準方向**而不是機首，所以圓圈恆在畫面正中央，會漂的是飛機。兩個準星之間的虛線就是指揮儀正在追的誤差角。

**射擊**：目標身上有方框與距離讀數，敵機紅、友機藍；打得到的時候旁邊會多一個圓圈，那是**預瞄環** —— 把機首十字壓上去再開火。預瞄環的顯示條件不是距離門檻，而是「這一發真的追得上」（有攔截解，且飛行時間在彈丸壽命 1.2 s 內），所以「看得到預瞄環」精確等於「打得到」。命中時十字四角會閃出向內收縮的 `X`。

**預瞄環只給敵機。** 子彈直接穿過友機，所以友機的預瞄環會指向一個打不到的點 —— 那是「往這裡開槍」的錯誤暗示，何況 19 架友機同時畫也只是雜訊。

沒有敵機血量顯示，也沒有目標鎖定 —— 你看不出對方的結構完整度，那在二戰題材上說不通。畫面上方只有雙方的**存活架數**，那是看得出來的量。

## 這個專案在做什麼

飛行模型是**史實性能驅動**的：極速、爬升率、失速速度、升限、持續轉彎率都對著史料調，誤差 ±5% 以內由測試守著。兩台飛機的**相對**強弱不是手感調出來的，是從各自的參數自然長出來的 ——

- Bf 109 在 250 km/h 的持續轉彎率優於 P-51（前緣縫翼）
- 400 km/h 時優勢反轉
- 海平面的交叉點落在 319 km/h
- P-51 在高速、高空、滾轉率、能量保持上領先

這些全部是 `test/balance/relative.test.ts` 的斷言，不是註解。

`Ps`（比超量功率）與 `Es`（比能量）顯示在 HUD 上不是為了除錯，是**能量戰的教學元件**：大 G 轉彎時 Ps 會掉到 −40 m/s 以下，玩家看得到能量在流失，才學得會不要亂拉。

## 架構

```
src/
  core/       固定步長迴圈、暫存物件池、數學
  physics/    ISA 大氣、氣動力、推進、6DOF 積分      ← 純函數
  specs/      機種參數（P-51D、Bf 109 G-6）
  analysis/   準靜態包絡求解器                       ← 純函數
  control/    飛行指揮儀、PID、限制器；Controller 介面與玩家／靶機實作
  aircraft/   Aircraft 組裝、撞海判定
  weapons/    武器資料表、射速時鐘、匯聚幾何
  world/      World（多機步進）、預瞄解、命中判定、彈丸池、粗篩索引 ← 純函數為主
              events.ts   撞擊事件緩衝（命中點與法線，逐子步排空）
  ai/         態勢評估、意圖仲裁、轉向、開火紀律、安全層、目標選擇  ← 純函數（狀態全在 AiController）
              assess.ts   態勢量；cornerRatio 回答「我還打得動嗎」、turnTime 回答「轉過去要幾秒」
              steer.ts    失速的兩種診斷分開處理（沒空速壓機頭、拉太猛才卸載）；extend 俯仰是連續量
              safety.ts   兩道硬介入：撞地（拉起）優先於失速（壓頭）
              station.ts  站位幾何（長機航跡的水平框）與站位控制器
              wingman.ts  僚機的四級目標優先序：自衛 > 掩護 > 集火 > 歸隊
  battle/     一場 20v20 怎麼開始與結束：生成、存活統計、全滅重置
              flights.ts  編制與保序壓縮（一條規則同時做完繼位與 Schwarm 內互補）
  input/      指標鎖輸入、世界固定瞄準點
  camera/     CameraRig
  render/     場景、海面、天空、程序化機體幾何
              muzzle.ts   槍焰（每管的計時器 + 內插姿態）
              sparks.ts   命中火花（決定性發射、幀率積分）
              splash.ts   入海水柱（底部貼真實浪高）
  hud/        Canvas 2D overlay
  tools/      sliceRef、hangar                       ← 開發用，不進打包
```

**純函數三兄弟**（`physics/`、`analysis/`、部分 `control/`）不持有狀態、不碰 three.js 的場景圖，所以史實性能可以在 node 裡直接驗證，不必開瀏覽器。`ai/` 走同一條紀律 —— 遲滯閂鎖、最小停留、10 Hz 節流、跟蹤計時器全部住在 `AiController`，其餘五個模組是純函數，所以 288 組安全矩陣與對戰矩陣能在 node 裡跑完。

低速時舵面會失去效力（動壓低於 1 G 失速動壓的 1.44 倍時線性衰減），所以垂直懸掛不是免費的招式 —— 掛太久就拉不回來，機頭會被重力帶下去。實測滿舵能換到的俯仰率由入場的 195 °/s 掉到 26 °/s，AI 則在最壞情況（操縱權歸零、飛機完全停住）下仍能在 15.4 秒內救回、只掉 271 m。設計與實測見 `docs/superpowers/specs/2026-08-03-low-speed-control-authority-design.md`。

物理跑 240 Hz 固定步長，渲染用累加器內插 —— 滾轉率可達 100°/s 以上，100 Hz 在大 G 機動時積分誤差肉眼可見。單步實測 **1.0 μs**；彈丸池滿載 4,000 發時整個 `World.step` 是 **175 μs**（含命中判定），曳光彈維持 **1 個 draw call**。兩架 AI 纏鬥的完整 `World.step` 平均 **19 μs**，其中 10 Hz 的包絡查詢那一格 p99 為 **129 μs**。

**20v20 × 滿載 4,000 發是 223–228 μs**（M7 三次量測；M6 是 209–245 μs，M7 為 `resolveHits` 加了入射面法線與入海判定，成本落在雜訊之內；M5 的佈局下是 313–402 μs，**兩者不可直接比較** —— M6 把每隊的 X 向跨度由 2,280 m 拉到 3,850 m，而粗篩是沿 X 排序的滑動視窗，攤得越開視窗內的架數越少）。每幀 4 步只佔 60 FPS 幀預算的 5–6%。這個數字是 M5 修過的：命中判定原本是 `O(彈丸數 × 架數)` 的雙層迴圈，40 架時整步 7,778 μs、每幀 31 ms —— 幀預算的兩倍。換成沿 X 軸排序後的滑動視窗（窗寬由包圍球與線段的 X 區間重疊代數推導，沒有魔術數字）之後，粗篩本身從 7,408 μs 降到 202 μs。中間試過「把位置攤平成 `Float32Array`」，只省 7% —— 成本不在指標穿越，在那 160,000 次距離計算本身。瀏覽器實測 40 架維持 **238–483 FPS**。M7 的三個特效各是一個 `InstancedMesh`，draw call 只加 3（實測 590 → 593）。

## 機體幾何

兩台的外型是**量出來的**，不是手調的：機身剖面、座艙罩站位、翼面尺寸與各凸起位置全部量自參考模型。工具在 `src/tools/`（三軸切片器 + 機庫比對頁），完整流程與 21 條實測踩過的坑寫在 `.claude/skills/aircraft-from-reference/SKILL.md`。

參考模型放在 `ref/`，列在 `.gitignore` —— **只作為量尺**，不進版控也不進打包。

四份規格的人工驗收全部於 **2026-08-03** 由專案負責人在瀏覽器實際操作走完並通過：M1 §3.5（試飛四項）、M2 §3.4（條件 9、10）、M4 §3.4（條件 9–11）、低速操控權 §8.5（條件 7–9）。紀錄的粒度是每份清單一個通過與否，沒有逐項的量化觀察。M4 的門檻回填紀錄在其規格 §16。

**M4 那一輪人工驗收挖出六個自動化測試抓不到的真缺陷**（當時 1,260 條全綠），全部已修，逐條記在 M4 規格 §3.4。它們都不是「算錯」，而是「算對了一個錯的量」。

**M5 的實作挖出兩件 spec 沒有預見的事**，記在其規格 §14.2 與 §14.3：

- **威脅項本身就是比分攤更強的分散機制。** 關掉它（`threatWeight = 0`），20 架會全部撲同一個目標 —— 比關掉分攤折扣（17 架）還糟。原因是只剩機會項時，所有人的評分函數長得一樣。
- **出生幾何漏了橫向錯開量。** 兩隊正對面時，藍 slot k 與紅 slot k 在 Z 軸上完全共線、高度層也一樣，整場仗退化成 20 場精準的對頭槍戰 —— 而那正是 P-51 六挺翼槍最差的區間（匯聚在 300 m，這種仗打在 660–1,000 m）。有效命中率藍 34% 對紅 97%，藍隊每 9 秒被零損失全滅一次。門檻由 `fire.ts` 的射擊錐推導：`entryRange × tan(3°) = 157 m`，實測懸崖落在 120–180 m 之間，取兩倍為 300 m。

## 尚未實作

調參面板與 Telemetry 歸因面板延後 —— 手感已可接受，沒有要調的東西。

**EM 圖產生器已正式取消**（M4 規格 §1.1）：AI 直接呼叫 `analysis/envelope.ts` 的求解器，不需要中介的 JSON 查表；離線圖表對玩家與 AI 都沒有消費者。

留給後續：**指揮 AI**（分隊級戰術指令與集合點，另一份 spec）、**玩家對僚機下令**（歸隊／攻擊我的目標／自由交戰）、飛機互撞、爆炸火焰與殘骸模型、難度下調（`DifficultyProfile` 的兩個欄位仍一律為 0）、視野盲區。
